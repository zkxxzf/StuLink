## 一、修复内容回顾

v1.7.0 的床位手动操作接口（分配/搬移/互换/取消）为"读-检查-写-commit"模式，无并发控制。实测**两个用户同时操作同一空床位时，双方均返回成功**，后写覆盖导致学生丢失床位（静默错误）。

**修复方案（双层防护）**：
1. **应用级互斥锁**（`threading.Lock`，Waitress 单进程多线程部署下有效）：串行化 7 个写接口的"读-检查-写"全过程；锁内重置 SQLite 旧事务快照（权限检查在锁外建立的快照若不重置，锁内仍读到过期数据）
2. **原子条件 UPDATE**（`WHERE student_id IS NULL` / `WHERE student_id = 该学生`）：影响行数为 0 即返回 409"床位状态已变化，请刷新后重试"；move/swap 双条件更新任一失败整体回滚

附带防御：同床搬移/互换直接拒绝。
