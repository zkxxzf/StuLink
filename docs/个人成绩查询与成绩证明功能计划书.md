- **版本**：v1.10 规划稿（2026-09-13，修订：去除学生/家长角色与电子签章/二维码防伪）
- **状态**：需求规划稿（待评审后进入开发）
- **关联文档**：《成绩管理与可视化分析系统设计文档.md》（v1.9.0，以下简称"主设计"）、《历史记录与日志系统设计.md》、《宿舍分配算法设计规范.md》
- **读者**：开发实施人员、需求确认人
- **范围定位**：在主设计"二期（Out）"中明确列为未实现的两项 —— **学生端/家长端查询** 与 **成绩单打印/成绩证明**。本计划书为其落地方案。

> **修订说明（2026-09-13）**：经确认，**不新增学生/家长角色**（不做学生/家长自助登录），个人查询与成绩证明均由**现有教职工角色**（管理员 / 年级长 / 班主任 / 任课教师）在各自数据范围内操作；同时**不做电子签章（电子签名）与二维码防伪**，成绩证明仅保留文字防伪验证码 + 公开核验页。

## 1. 背景与目标

### 1.1 现状

v1.9.0 的成绩模块只面向**管理/教师视角**的四大分析（年级 / 班级 / 学科 / 任课教师），且已有"学生个体下钻"能力（主设计 A2-T3 班级学生明细、A4 教师班科学生排名下钻），但**没有统一的"单个学生成绩查询页"**，也**无法生成正式的成绩证明**。

数据基础已具备：

- `grades.db` → `exams`、`exam_scores`（窄表：一学生一科目一行，含 `总分` 伪科目行，已落库 `rank_class` / `rank_dir` / `move_rank`）；
- `system.db` → `students`（学号 / 姓名 / 年级 / 班级 / 选科方向 / 学籍状态）；
- 排名口径（方向内 / 班内、同分并列、进退步）已在导入时算好并落库，个人页可直接读取，无需重算；
- 打印 PDF 范式已在主设计 7.5 落地（浏览器打印 + `@media print` 样式）。

### 1.2 目标

新增**个人成绩查询**与**成绩证明**两大能力，由教职工在权限范围内操作：

1. **个人成绩查询**：教职工在自身数据范围内（班 / 年级 / 全校）选定某个学生，查看其历次考试成绩 —— 各科原始分、总分、班排名 / 方向排名、进退步，并与班级 / 年级均值对标；支持单场查看与跨场趋势。
2. **成绩证明**：教职工为选定学生按"单场考试 / 学期 / 学年"生成正式成绩证明（PDF），含学校抬头、学生信息、各科成绩与排名、文字防伪验证码；第三方可通过验证码公开核验真伪（无电子签章、无二维码）。

### 1.3 范围界定（In / Out）

| In（本期） | Out（不在本期） |
|---|---|
| 教职工在权限范围内查询单个学生成绩（新增"个人查询"入口 + 学生选择器） | 学生/家长自助登录与自查（不做学生/家长角色） |
| 个人成绩查询页（单场明细 + 历次趋势 + 班级/年级均值对标） | 家长多子女绑定 |
| 成绩证明生成（单场 / 学期 / 学年，PDF，浏览器打印） | 电子签章 / 电子签名（CA 数字签名） |
| 成绩证明文字防伪验证码 + 公开核验页（无需登录，无二维码） | 二维码防伪 |
| 管理员/年级长/班主任/任课教师按各自范围代生成与下载证明 | 毕业年级/往届成绩证明（复用 `grades/history`、`grades/alumni` 二期页） |

## 2. 用户与权限设计

### 2.1 不新增角色

本期**不创建** `student` / `parent` 角色，沿用现有角色体系（`admin` / `grade_leader` / `homeroom_teacher` / `dorm_manager` / `teacher`）。个人查询与证明由教职工在其既有数据范围内完成。

### 2.2 新增权限 key

| key | 含义 | 默认组 |
|---|---|---|
| `grades.student_query` | 查询单个学生成绩、生成该生成绩证明 | 管理员组（全校）、年级长组（本年级）、班主任组（本班）、任课教师组（本人班科） |

> 教师/班主任/年级长查询单个学生时，目标学生必须落在自身 `scope_service` 范围内（班 / 年级 / 全校），越界返回 403（沿用主设计 9.3 白名单范式）。任课教师仅能查本人任教班级的学生。

### 2.3 学生选择器与鉴权

- 个人查询页提供**学生选择器**：按姓名 / 学号在用户可见范围内检索（复用 `system` 模块学生检索接口，限 scope）；
- 选定学生后，所有数据查询以该 `student_no` 为过滤键，但**强制校验该生属于当前用户 scope**（班级 / 年级 / 全校），不接受越权查询；
- 不做学生账号开通、不做 `User.student_no` 绑定（无学生角色）。

## 3. 数据模型

### 3.1 复用（不新建）

- `exams`、`exam_scores`、`exam_bands`（全部 `grades` bind）；
- `students`（`system.db`，只读关联，不建外键，跨库批量 `WHERE student_no IN (...)` 组装，同主设计 4.2）。

### 3.2 新增

| 对象 | bind | 说明 |
|---|---|---|
| `certificates` | grades | 成绩证明台账（文字防伪核验用），见 3.3 |

> 不再新增 `User.student_no`、`parent_student` 等表/字段。

#### 3.3 certificates（成绩证明台账）

| 字段 | 类型 | 说明 |
|---|---|---|
| id | INTEGER PK | |
| code | TEXT UNIQUE NOT NULL | 文字防伪验证码（见 5.3 生成规则） |
| student_no | TEXT NOT NULL | 证明所属学生 |
| student_name | TEXT | 姓名快照 |
| scope_type | TEXT | `exam`（单场）/ `term`（学期）/ `year`（学年） |
| ref_ids | TEXT(JSON) | 关联考试 id 列表（学期/学年 = 该范围内全部已导入考试） |
| title | TEXT | 证明标题（如"2025-2026 学年第一学期成绩证明"） |
| generated_by | INTEGER | 操作者 user.id（教职工） |
| revoked | INTEGER | 是否作废（0/1），可作废并重开新码 |
| created_at / updated_at | DATETIME | |

- 核验页只读查 `code`，不暴露任何写操作；作废后核验页提示"该证明已作废"。

## 4. 个人成绩查询功能设计

### 4.1 页面与接口

| 路由 | 页面/接口 | 权限 | 说明 |
|---|---|---|---|
| `GET /grades/student` | 个人查询主页（含学生选择器） | grades.student_query | 选学生 → 顶部考试/学期筛选 |
| `GET /grades/api/student/scores?student_no=&exam_id=` | 单场成绩 JSON | grades.student_query | 该生各科 + 总分（含 rank_class/rank_dir/move_rank）；校验 student_no ∈ scope |
| `GET /grades/api/student/trend?student_no=&scope=` | 历次趋势 JSON | grades.student_query | 该生历次总分/排名序列（ECharts 折线） |
| `GET /grades/api/student/benchmark?student_no=&exam_id=` | 对标基准 JSON | grades.student_query | 该生所在班级/年级(方向)各科均值与总分均值 |
| `GET /grades/student/cert?student_no=` | 成绩证明生成页 | grades.student_query | 选范围 → 预览 → 生成 |
| `POST /grades/api/student/cert` | 创建证明（写 certificates，返 code） | grades.student_query | 校验 student_no ∈ scope |
| `GET /grades/cert/<code>` | 公开核验页（无需登录） | 匿名 | 只读展示证明内容 + 有效性 |

### 4.2 个人查询主页展示

- **学生选择器**：姓名/学号检索，结果限定当前用户 scope；选中后进入该生视图。
- **单场明细**（复用 `exam_scores` 该生行）：科目｜分数｜班级排名｜方向排名｜进退步（读 `move_rank`）；总分行置顶高亮。
- **对标列**：每科显示"本人分 / 班级均值 / 年级(方向)均值 / 差值"，差值着色（绿优红劣，仅颜色无文字评价，同主设计 7.4 客观性约束）；班级/年级均值由 `stats_service` 既有聚合（主设计 8.1）取数，不重算。
- **历次趋势**：X=考试（按日期），折线=该生总分 + 方向排名（次轴）；与 A1-G4 / A2-G7 同范式复用 `echarts`。
- **空态**：无成绩 / 未导入考试 → 引导"暂无成绩数据"；缺考科目显示缺考徽标（同主设计 7.3）。
- **隐私标注**：借读等非在籍状态仅显示学籍徽标，不参与任何统计（同主设计确认 #8）。

### 4.3 权限与安全要点

- 所有个人接口除接收 `student_no` 外，**服务端强制校验**该生属于 `current_user` 的 scope（班 / 年级 / 全校）；越界返回 403；
- 任课教师仅能查本人任教班级学生；班主任仅本班；年级长仅本年级；管理员全校；
- 不做学生自助，所有查询均有明确操作者（OperationLog 可追溯）。

## 5. 成绩证明功能设计

### 5.1 生成范围

| 范围 | 取数 | 证明标题示例 |
|---|---|---|
| 单场（exam） | 指定 1 场考试的该生全部科目 + 总分 + 排名 | "2025级 2026-01-15 期中考试 成绩证明" |
| 学期（term） | 该学期（如 `2025-2026` 第一学期）全部考试，按考试逐场列出 | "2025-2026 学年第一学期 成绩证明" |
| 学年（year，扩展） | 一学年全部考试汇总 | "2025-2026 学年 成绩证明" |

- 学期/学年范围由 `exams.term` + `exam_date` 推导（同主设计 5.3.1）。

### 5.2 证明版式（打印模板）

复用主设计 7.5 的 `@media print` 范式 + `print.css`：

- 头部：学校名称（读取系统配置 `school_name`）、"成绩证明"标题、证明编号（=文字防伪码）；
- 学生信息区：姓名 / 学号 / 年级 / 班级 / 选科方向 / 学籍状态；
- 成绩表：考试｜科目｜分数｜班级排名｜方向排名（逐场逐科；学期/学年为每场一个子表或合并表）；
- 尾部：生成日期、**公章占位区**（预留圆形盖章位置，由学校线下加盖，**不做电子签章**）、"本证明由 StuLink 系统生成，验证码可于系统核验"提示；
- **不含二维码**、**不含电子签名**；防伪仅依赖文字验证码 + 公开核验页。

### 5.3 文字防伪验证码规则

- `code` = 易读分组格式，例如 `SL-<学年缩写>-<student_no 后6>-<考试范围hash8>-<随机4>`；
- 生成时写入 `certificates`（含 `ref_ids` 快照，保证核验时即使后续成绩被改，证明仍对应生成时的范围）；
- 可"作废并重开"：原 `code` 置 `revoked=1`，新码有效；
- 操作者（`generated_by`）记教职工 id，便于追溯。

### 5.4 公开核验页 `/grades/cert/<code>`

- 无需登录，输入/粘贴码即查；
- 命中且未作废 → 只读渲染证明内容 + "✅ 该成绩证明真实有效"；
- 未命中 / 已作废 → "❌ 验证码无效或证明已作废"；
- 仅展示、无任何写操作与导航入口（防信息泄露面）。

## 6. 技术实现要点

### 6.1 后端

- 新增 `app/modules/grades/routes/student.py`（个人查询 + 证明路由）、`app/modules/grades/services/student_service.py`（按 `student_no` 取数、趋势、对标、证明生成）。
- 取数范式复用 `store_service` 的 `ExamScore` 读取与 `stats_service` 的均值聚合（主设计 6.2 / 8.1），**不重复实现**统计口径；个人页只做"取该生行 + 套用既有聚合基准"。
- 证明生成：`certificates` 落库 + 返回 `code`；PDF 由前端打印模板产出（同主设计 7.5，不后端渲染 PDF，规避 wkhtmltopdf 等重依赖）。
- scope 校验：复用 `scope_service`（主设计 9.3）的 `class` / `grade` / `school` 白名单，新增"学生是否属于当前用户范围"的判断函数。

### 6.2 前端

- 个人查询页 `templates/grades/student.html`：学生选择器 + 单页筛选 + 明细表 + ECharts 趋势图（复用 `grades.js` 既有渲染与打印范式，新增 `student.js`）；
- 证明页 `templates/grades/cert.html`：范围选择 → 预览 → "生成证明" → 调打印；
- 核验页 `templates/grades/verify.html`：极简只读页，无侧边栏/无菜单。
- 菜单：`base.html` 在 `request.blueprint=='grades'` 且用户具 `grades.student_query` 时，显示"个人查询 / 成绩证明"入口（与四大分析 tab 并列或作为子入口）。

### 6.3 权限与审计

- `decorators.perm_required('grades.student_query')` 守卫所有个人/证明接口；每个接口对 `student_no` 做 scope 校验，越界 403；
- 证明生成、作废写 `OperationLog`（module='grades'，detail 含 code/范围/操作者）；
- 不做学生账号体系，无 `User.student_no` 字段变更。

## 7. 关键流程

### 7.1 教职工查单个学生成绩

```
[教职工登录] → /grades/student → 学生选择器(限 scope) 选学生
→ 选考试/学期 → 调 /api/student/scores（该生行+排名，校验 scope）
→ 对标列（班级/年级均值，stats_service 聚合） → 趋势图（/api/student/trend）
```

### 7.2 生成成绩证明

```
[教职工] → /grades/student/cert?student_no= → 选范围(单场/学期) → 预览
→ POST /api/student/cert（写 certificates，返 code，校验 scope）→ 打印页 → 浏览器另存 PDF
→ 如需核验：/grades/cert/<code>（公开只读）
```

## 8. 里程碑与验收

| 里程碑 | 内容 | 验收标准 |
|---|---|---|
| M1 权限与入口 | `grades.student_query` key + 默认组授权 + `scope_service` 学生范围校验 + 个人查询菜单入口 | 四类教职工角色各建真实账号，按矩阵核验：可见范围正确、越界查他人学生返回 403 |
| M2 个人查询 | `/grades/student` 学生选择器 + 单场明细 + 对标列 + 历次趋势（ECharts） | 单场各科/总分/排名与 `exam_scores` 落库一致；对标列与四大分析页同口径；趋势正确；选择器仅列 scope 内学生 |
| M3 成绩证明 | 生成页（单场/学期）+ 打印模板（无电子签章/无二维码）+ `certificates` + 公开核验页 | 打印 PDF 无裁切、含公章占位与文字防伪码；核验页输入码显示有效、作废码显示失效、未命中显示无效 |
| M4 打磨 | 空态/边界、操作日志 | 无成绩空态引导；证明生成/作废记日志 |

## 9. 风险与二期

| 风险 | 对策 |
|---|---|
| 教职工查到非管辖范围学生（越权） | 每个接口对 `student_no` 做 scope 校验，越界 403 兜底 |
| 成绩后续被改导致证明失真 | 证明落 `ref_ids` 快照，核验按生成时范围；支持作废重开 |
| 打印 PDF 分页/公章裁切 | 复用 7.5 打印样式 + 实测固化 |
| 学生选择器结果过多 | 限定 scope + 姓名/学号精确检索，不做全量下拉 |

**二期预留（已明确不在本期）**：学生/家长自助登录与自查、家长多子女绑定、电子签章（CA 数字签名）、二维码防伪、毕业年级成绩证明（接 `grades/history`、`grades/alumni`）、成绩条批量打印、学生端成绩异议申诉。
