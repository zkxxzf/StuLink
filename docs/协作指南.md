# StuLink 协作指南

> 本文档面向参与 StuLink 开发的协作者，介绍代码获取、日常开发、提交与合并的完整流程。

## 一、开始之前

- 仓库地址：https://github.com/zkxxzf/StuLink
- 你已被邀请为协作者，请先登录 GitHub，在通知或邮件中点击 **Accept invitation**（接受邀请）
- 尚未接受邀请前，你对本仓库没有写入权限

## 二、一次性环境配置

### 1. 配置提交身份（重要）

提交身份决定你的每次提交显示为谁，务必用自己的信息：

```bash
git config --global user.name "你的名字"
git config --global user.email "你GitHub账号的验证邮箱"
```

邮箱可在 GitHub 网页右上角头像 → Settings → Emails 中查看。

### 2. 克隆项目（HTTPS / SSH 二选一）

**方式一：HTTPS（简单，推荐新手）**

```bash
git clone https://github.com/zkxxzf/StuLink.git
```

首次 push 时会弹出浏览器让你登录自己的 GitHub 账号，登录一次后自动记住。

**方式二：SSH（可选，连接更稳定）**

1. 本地生成密钥：`ssh-keygen -t ed25519 -C "你的邮箱"`（一路回车）
2. 把 `~/.ssh/id_ed25519.pub` 文件内容添加到 GitHub → Settings → SSH and GPG keys → New SSH key
3. 克隆：`git clone git@github.com:zkxxzf/StuLink.git`

> 注意：私钥文件永远只留在自己电脑上，不要发送给任何人。

### 3. 运行环境

本地运行所需的依赖与启动方式，见仓库 `docs/` 目录下的相关文档。

## 三、日常开发流程

### 1. 开工第一步：拉取最新代码

```bash
git switch master
git pull
```

### 2. 创建功能分支（不要直接在 master 上开发）

```bash
git switch -c feature/功能名称
```

- 新功能用 `feature/xxx`，修 bug 用 `fix/xxx`
- 一个功能一个分支，不要多个功能混在一个分支里

### 3. 开发并提交

```bash
git add -A
git commit -m "本次改动的简述，例如：修复登录接口的空指针问题"
```

### 4. 推送分支

```bash
git push -u origin feature/功能名称
```

### 5. 发起 Pull Request

推送后打开仓库页面，点击绿色按钮 **Compare & pull request**，填写改动说明，点击 **Create pull request**，等待 @zkxxzf 审核合并。

## 四、保持自己的分支与主线同步

当 master 有新代码合入后，及时把自己的分支同步，避免冲突积累：

```bash
git switch feature/功能名称
git pull origin master
# 若提示冲突，打开冲突文件手动取舍（保留需要的代码，删除冲突标记）
git add -A
git commit -m "解决与 master 的冲突"
git push
```

## 五、协作规则

1. `master` 分支禁止直接推送，所有改动通过分支 + Pull Request 合入
2. 每天收工前把当天代码 push 到自己的分支，不要只留在本地
3. 提交信息写清楚"做了什么"，不要写"更新""修改"这类无意义内容
4. 大功能拆成小步提交、尽早发 PR，便于审核
5. 审核意见通过 PR 评论沟通，修改后 push 到同一分支，PR 会自动更新

## 六、遇到问题

- 推送被拒绝（Permission denied / 403）：确认已接受协作者邀请
- 冲突解决不了或其他 Git 疑难：联系 @zkxxzf，附上报错截图
