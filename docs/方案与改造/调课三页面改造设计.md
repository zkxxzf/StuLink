## 一、页面拆分与顶部 Tab

| Tab | 路径 | 端点 | 语义 |
|---|---|---|---|
| 普通调课 | `/academic/swap/apply` | `academic.swap_apply` | 我的课 → 挪到空档（`new_weekday/new_period`） |
| 两人换课 | `/academic/swap/exchange` | `academic.swap_exchange` | 我的课 ↔ 对方的课（可批量，多位老师） |
| 请人代课 | `/academic/swap/cover` | `academic.swap_cover` | 我的课 → 请某老师来上（可批量，多人代多节） |

共用组件：`app/templates/academic/_swap_tabs.html`（`{% include %}` 时传 `active`）。

## 二、统一交互骨架（三页必须一致）

```
┌ ① 选择「我的课」    ── 卡片网格，点选即加入（多选，右上角角标显示已加入）
├ ② 已选清单          ── 表格；每行 = 一节我的课 + 「配置列」+ 删除按钮；点行可选中高亮
├ ③ 范围与理由        ── 临时（指定日期）/ 永久（整学期）+ 理由 + 逐行预览
└ 提交                ── POST `items_json`（一行一个 item）
```

**各页唯一的差异只在第②步的「配置列」**：

| 页面 | 配置列内容 |
|---|---|
| 普通调课 | 目标时段（绿色可选 / 红色冲突的网格卡片，点选写入） |
| 两人换课 | 对方教师（下拉）→ 对方的课（下拉）→ 我方日期 / 对方日期（两个 date） |
| 请人代课 | 代课教师（下拉）→ 日期（date） |

交互手法统一：**上层用点选卡片增加行，下层用同一个表格承载行**，不再出现"上面下拉、下面点选"或反过来。

## 三、提交契约（`items_json`）

统一为 `{"items":[...]}`，放在隐藏域 `#hItemsJson`，随 `<form>` 一起 POST。

```jsonc
// 普通调课  POST /academic/swap/apply
{"items":[{"entry_id":123,"new_weekday":3,"new_period":5,"swap_date":"2026-10-14"}]}

// 两人换课  POST /academic/swap/exchange
{"items":[{"entry_id":123,"partner_uid":"T001","partner_entry_id":456,
           "swap_time":true,"swap_class":true,          // 对调内容（至少一个 true）
           "swap_date":"2026-10-14","partner_swap_date":"2026-10-16"}]}

// 请人代课  POST /academic/swap/cover
{"items":[{"entry_id":123,"partner_uid":"T007","swap_date":"2026-10-14"}]}
```

表单其余字段（三页同名）：`is_permanent`（on/空）、`reason`、`source_date`（普通调课）。

## 四、数据模型变更（`schedule_swaps`）

| 列 | 类型 | 说明 |
|---|---|---|
| `swap_time` | Boolean | 是否对调上课时间（星期 + 节次） |
| `swap_class` | Boolean | 是否对调上课班级（年级/班/学科/教室） |
| `partner_swap_date` | Date | **对方那节课**所在的日期（临时换课用） |
| `exchange_kind` | String | 取值收敛为 `exchange` / `cover`（旧的 `time`/`class` 由 swap_time/swap_class 表达） |

组合对照：

| swap_time | swap_class | 含义 | 旧称 |
|---|---|---|---|
| ✔ | ✔ | 整条互换：我去上他那节（时间+班），他来上我这节 | 换班上课（原 class） |
| ✔ | ✘ | 只换时间：各上自己班 | 换时段（原 time） |
| ✘ | ✔ | 只换班：时间不动，各自去上对方的班 | （新增） |
| ✘ | ✘ | 非法（至少一个） | —— |

迁移：`scripts/migrate_swap_exchange_v2_20261012.py`（幂等加列 + 旧值回填）。

## 五、后端 API

| 名称 | 签名 | 说明 |
|---|---|---|
| `apply_exchange_batch` | `(applicant_uid, applicant_name, items, is_permanent, reason)` | 换课批量：逐条校验 → 共享 `batch_id` → 每条 `partner_status='pending'` → 分别通知对方 |
| `apply_cover_batch` | `(applicant_uid, applicant_name, items, is_permanent, reason)` | 代课批量（内部走同一 builder，`exchange_kind='cover'`） |
| `exchange_plan` | `(e1, e2, swap_time, swap_class, cover_uid, cover_name)` | 按两个勾选生成落位计划 |
| `check_exchange_conflicts` | 同上参数 | 对调后与**第三方**的冲突校验 |
| `_execute_exchange_temp` | —— | 按 `swap_date` / `partner_swap_date` 两侧各自落位（两个日期可以不同） |

## 六、对方确认与审批

- 批量里每条记录有各自的 `partner_uid` → **各自确认**（互不影响）；
- `can_review(sw)` 要求该条 `partner_status=='agreed'`；
- 整批审批（`review_swap_batch`）要求批内**全部已确认**，否则提示「还有 N 条未确认（x/y）」。
