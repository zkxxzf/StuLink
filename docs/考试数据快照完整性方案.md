# 考试数据快照完整性方案（教师快照 + 班级口径）

> 版本：v1.18.9.0（2026-10-09）｜状态：**方案待评审**（尚未实施）
> 所属模块：`grades`（独立库 `grades.db`）
> 触发背景：用户指出"每学期可能重新分班，学生与任课教师都会大变；每次考试必须记录**考试当时**的师生归属"
> 本文范围：**只解决"数据不错位"**；教师维度的对比形式（同场横向 / 跨考试趋势）另行设计

---

## 1. 业务口径（用户明确）

| 项 | 规则 |
|---|---|
| 班级名 | 稳定不变：`2024级01班` 永远是 `2024级01班` |
| 重新分班 | 每学期可能发生；分班后**学生、任课教师都可能大变** |
| 班级横向对比 | 跨分班前后的对比**无意义**；仅在未重新分班的区间内可比 |
| 学生横向对比 | 拉长三年；指标为**全年级（方向内）排名**，不依赖班级 |
| 教师横向对比 | 在**不重新分班**的前提下，与同年级同学科教师比上线率 / 去差平均分 |

## 2. 现状审计（2026-09-30 实测，含证据）

### 2.1 三维度快照完整度总表

| 维度 | 字段/机制 | 判定 |
|---|---|---|
| **学生身份** | `exam_scores.student_no` / `student_name` 快照 | ✅ 可靠（学号稳定）|
| **学生班级** | `exam_scores.class_name` 快照，但**导入时被主库当前值覆盖** | ❌ **机制缺陷 + 既有数据错位** |
| **学生方向** | 由 `subject_selection` 推导（个人属性，高中三年不变），兜底用班级班型 | ✅ 基本可靠 |
| **班排名** | `rank_class` 按"快照班级"分组计算 | ❌ 随班级错位而错 |
| **方向排名** | `rank_dir` 按方向分组计算（方向来自学生选科） | ✅ 可靠 |
| **任课教师** | **无任何快照**，5 处分析实时查 `TeacherSubjectLink.active` | ❌ 换老师即错位 |

### 2.2 班级快照缺陷：导入时用主库当前值无条件覆盖

`import_service.py:246`（`_attach_student_info`）：
```python
r['class_name'] = stu.class_name      # ← 无条件用主库【当前】班级覆盖 Excel 的「班级」列
r['subject_selection'] = stu.subject_selection or ''
if not direction:
    direction = cp_map.get(stu.class_name) or ''   # 兜底也按当前班级班型
```
- Excel 的「班级」列（`_CLASS_KEYS = ('班级',)`）虽被识别，但**从未被使用**
- 因此"考试当时的班级"**在机制上无法记录**，只能靠"考试后、分班前及时导入"碰巧正确

### 2.3 铁证：2024级 17 场考试的班级快照已全部错位

**证据 A — 学生集合测试**（若被覆盖，任意场次"01班"必为当前 01班 子集）：
```
当前主库 2024级01班: 48 人
17 场考试中"01班"学生：每场"不在当前01班"均为 0 人
全部考试 01班 学生并集 = 48 人（= 当前班人数）
```
→ 并集未超出当前班，**每场"01班"都是当前 01班 的成员**。

**证据 B — 方向铁证**（决定性）：
```
考试#1（2024-09-19 高一上，此时尚未选科分班）：
  01班: {'历史': 46}   ← 100% 单一方向
  02班: {'历史': 44}
  03班: {'物理': 55}
  ... 每班均 100% 单一方向
```
高一上不可能存在"纯历史班/纯物理班"（选科分班发生在高一下~高二上）→ 该场班级必为**高三（当前）班级**。

**结论**：2024级 17 场（2024-09 ~ 2026-09，跨多次分班）的 `class_name` 全部等于导入时（2026-09-22）的主库班级。**这批数据的班级维度与班排名不可用于历史分析。**

### 2.4 2025级 同样中招（3 场）

同样方法实测 2025级 3 场高一上考试（2025-10-01 ~ 2025-12-12）：

| 考试 | 01班 | 02班 | 03班 | 说明 |
|---|---|---|---|---|
| #18 | {历史:45, 物理:2} | {历史:45} | {物理:49} | 每班已 100% 单一方向 |
| #19 | {历史:45, 物理:2} | {历史:45} | {物理:49} | 同上 |
| #20 | {历史:44, 物理:2} | {历史:42} | {物理:48} | 同上 |

- 高一上（2025-10）**尚未选科分班**，不可能存在纯历史/纯物理班 → 班级必为**分班后（当前）**
- 并集测试：每场「01班」学生均**全在当前 01班 内**（`不在当前01班: 0 人`）
- 细节吻合：当前 01班为 `历史48 + 物理2`，而考试#18 的 01班恰为 `{历史:45, 物理:2}` —— 进一步印证为当前班级
- 时间线佐证：`student_change_log` 显示 2025级 于 **2026-08-28** 批量调班 111 人

### 2.5 全年级受损总览

| 年级 | 考试场次 | 班级快照状态 |
|---|---|---|
| **2024级** | 17 场（2024-09 ~ 2026-09）| ❌ 全部被覆盖为当前（高三）班级 |

### 2.8 仍然可靠的部分 ✅

- **方向排名**：`direction` 由学生 `subject_selection`（选科，个人属性，高中三年不变）推导，非班级派生 → **可靠**
- 成绩分数 / 姓名 / 选科：均为独立快照，**可用**
- **2026级**：尚无考试成绩，无历史包袱

## 3. 修复方案

### 3.1 核心：新增考试级教师快照表

```python
class ExamTeacherLink(db.Model):
    """考试 × 班级 × 科目的任课教师快照（换老师不影响历史分析）"""
    __bind_key__ = 'grades'
    __tablename__ = 'exam_teacher_links'

    id = db.Column(db.Integer, primary_key=True)
    exam_id = db.Column(db.Integer, nullable=False, index=True)
    grade = db.Column(db.String(10), nullable=False)
    class_name = db.Column(db.String(10), nullable=False)
    subject = db.Column(db.String(10), nullable=False)
    user_id = db.Column(db.Integer)                 # 关联 users.id（快照）
    teacher_name = db.Column(db.String(50))         # 姓名快照（防改名/删号）
    source = db.Column(db.String(10), default='import')
    #   import=导入时快照（可信）｜backfill=历史回填（推测）｜manual=人工修订
    snapshot_at = db.Column(db.DateTime, default=datetime.now)

    __table_args__ = (
        db.UniqueConstraint('exam_id', 'class_name', 'subject',
                            name='uq_exam_cls_subj'),
    )
```
**规模**：每场 ≈ 班级数 × 科目数（10 × 9 = 90 行），可忽略。

### 3.2 写入时机（三路）

| 路径 | 时机 | source |
|---|---|---|
| **主路径** | 成绩导入确认成功后（`exam_import_confirm`），复制当时 active 映射 | `import` |
| **惰性兜底** | 教师维度分析首次访问时，若本场无快照 → 立即生成并落库 | `backfill` |
| **人工修订** | 分析页「修订本场教师」入口（二期），修正后置 `manual` | `manual` |

### 3.3 分析层改造点

| # | 文件 | 改动 |
|---|---|---|
| 1 | `tab_service.teacher_tab` | `links` 改为"本场快照（缺失则惰性生成）" |
| 2 | `report_teacher_service.py:35` | 同上 |
| 3 | `report_service.py:85` | 同上 |
| 4 | `report_pivot_service.py:17` | 同上 |
| 5 | `class_overview_service.py:170` | **保留当前映射**（"我现在带的班"，非历史归属）|

**权限侧不动**：`scope.py`、`ai_service.py:97` 继续用当前映射 —— 可见范围应随现状变化。

### 3.4 学生班级口径：Excel 优先 + 显式指定

```python
# import_service._attach_student_info
r['class_name'] = normalize_class_name(excel_cls) or stu.class_name
```
- 新增 `normalize_class_name()`：`'2024级06班'` / `'高一03班'` → `'06班'`（复用 `numeric_classes` 正则口径）
- 导入预览新增提示：**"班级与主库不符 N 人"**，一眼看出是否分过班
- **导入向导增加"班级归属"选项**（关键，见 3.6）：

### 3.5 班级下拉补全

`analysis.api_options` 的选修班级改为 **快照班级 ∪ 当前班级**（保持 `numeric_classes` 过滤），避免历史班级消失后不可选。

### 3.6 从源头保障"考试当时班级"（推荐同时做）

机制上主库只有"当前班级"，没有历史。可选两条路线：

**路线甲（推荐，低改动）**：导入向导加单选
```
○ 使用 Excel 中的班级列（考试当时，推荐）
○ 使用学籍库当前班级（仅在考试后未分班时选此项）
```
默认选第一项；若 Excel 无班级列则强制第二项并提示风险。

**路线乙（完备，改动大）**：建"学生班级履历表"`student_class_history(student_no, class_name, grade, from_date, to_date, source)`，导入时按考试日期反查当时班级。
→ 但**历史履历已不可考**（见 §4），只能从今往后积累，所以推荐先做甲。

## 4. 既有数据补救（20 场）

⚠️ **现状**：20 场考试的班级快照已全部被覆盖，**原始 Excel 的「班级」列是唯一可恢复来源**。

**补救步骤（需确认可用的 Excel 范围）**：
1. 找回各场原始成绩 Excel（2024级 17 场为 29 个文件，2025级 3 场另计）
2. 一次性脚本：按 `学号` 匹配，用 Excel「班级」列**重写** `exam_scores.class_name`
3. 重算受影响考试的 `rank_class`（班排名）；`rank_dir` 不变
4. 某场若 Excel 无班级列 → 该场标注"班级不可考"

**若 Excel 已丢失**：建议将这 20 场的**班级维度**标记为"不可用于历史对比"，仅保留个人维度与方向排名分析。
