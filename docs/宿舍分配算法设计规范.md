# 宿舍分配算法设计规范（v8）

> **版本**: v8（2026-08-17，里程碑 StuLink v1.8.0）
> **核心策略**: 初稿生成（严格分级贪心）→ 迭代爬山（多轮搜索）→ 全局评分选优
> **代码**: `app/modules/dormitory/services/room_assignment_v8.py`（所有分配计算统一调用 v8，v7 及以前版本已停用）

---

## 〇、核心要点（速览）

1. **单年级操作**：一次分配只允许一个年级（前端勾选限制 + 后端 `selected_keys` 双重校验），杜绝跨年级混住
2. **跨年级合班禁止**：合班仅限同性别 + 同年级 + 同班型（S2）
3. **严格分级初稿**：L 从 6 递增（6/7/8），取第一个分配成功的等级——6 人间住满 6、8 人间按 L 住人；房间不足清除重算升档（S4/S8）
4. **迭代爬山**：每轮枚举所有可行"份额移动/交换"，执行评分下降最多的操作；无改善操作时自动"抖动"（接受最不差操作）尝试跳出局部最优（S11）
5. **收敛检测**：连续 20 轮未刷新历史最优（实质改善 < 评分 0.5%）即停止；结束时回滚到历史最优状态
6. **全局评分选优**：7 项权重（宽松优先/超6人/满8/合班/班级分散/小房/空房），分数越低越好，权重前端可见可调（S11）
7. **满8 惩罚**：8 人间住满 8 人额外离散重罚（物理极限，避免"8人满 vs 6人"并存）
8. **6人间优先住满**：同层小容量房间先分配（S6）
9. **班级唯一性**：所有班级查询/写入 (grade, class_name) 成对（S14）

## 一、约束条件 SPEC（全部强制）

| 编号 | 约束 | 规则 |
|------|------|------|
| S1 | 性别独立 | 男女独立分配，逻辑相同；房间 `gender` 严格隔离（男/女/不限） |
| S2 | 合班约束 | 仅同性别 + **同年级**（grade 完全一致）+ 同班型（ClassProfile.class_type，无记录→default）；每间合班房 **≤2 个班**；每班发起合班 **≤1 次**（被借不算发起） |
| S3 | 合班时机 | 仅班级收尾（剩余 1 ~ limit-1 人）且下一班有剩余时被动触发 |
| S4 | 压力等级 | L 从 6 递增，取第一个满足 `Σ min(L, 容量) ≥ 人数` 的等级；该等级分配失败（房间碎片）则升档重试 |
| S5 | 房间上限 | `limit = min(L, 容量)`，合班房与普通房完全一致（压力均匀） |
| S6 | 6人间优先 | 同层小容量房间先分配（S 型内容量升序），6 人间优先住满 |
| S7 | 独享优先 | 班级收尾先填满本班独享房空床（至 limit，不超 L），仍剩才合班/独占 |
| S8 | 房间兜底 | 房间不足时填满本班独享房至物理容量；仍不足 → 该 L 失败，清除重算升档（L+1…8） |
| S9 | 全量校验 | Σ实际入住 == Σ总人数，否则报错 |
| S10 | 单年级约束 | 一次分配仅允许一个年级，双年级直接报错 |
| S11 | 评分选优 | 爬山迭代以 7 项权重评分（越低越好）驱动，收敛即输出最优 |
| S12 | 班级唯一性 | 所有班级查询/写入 (grade, class_name) 成对，禁止只按班级名 |
| S13 | 物理容量 | Σ物理床位 < 人数 → 直接报错，提示增选宿舍 |

## 二、评分函数（S11，权重前端可调）

```
score = W_L×(L-6)
      + W_over6 × Σ(8人间人数-6 超出部分)
      + W_full8 × 8人间住满8的间数
      + W_comb  × 合班宿舍间数
      + W_spread× Σ(每个班占房数-1)
      + W_small × ≤3人房数量
      + W_empty × 空房数量（勾选未用）
```

### 默认权重（×10 归一化，前端"高级参数"面板可调）

| 参数 | 默认值 | 含义 |
|------|--------|------|
| 宽松优先 (L) | 200 | 每高 1 级（L=7/8）的惩罚——避免 8 人间住满 |
| 8人间超6人 | 80 | 8 人间每超 6 人 1 人罚 80（线性） |
| **满8(8人间住满)** | **100** | 8 人间住满 8 人的**离散额外惩罚**（物理极限） |
| 合班宿舍 | 50 | 每间合班宿舍 |
| 班级分散 | 80 | 每个班每多占 1 间房 |
| 小房(≤3人) | 100 | 每间 ≤3 人的房间 |
| 空房 | 20 | 每间勾选未用的房间 |
| 迭代轮数 | 1000 | 爬山轮数上限（收敛自动提前停） |

> 权重只取**相对比例**有效（整体 ×N 结果不变）；调大某项 = 更重视该项。
> "满8"与"超6"的区别：超6 是线性（7 人和 8 人都罚），满8 是离散（只有住满 8 才罚）——解决"8+6 与 7+7 评分相同"的缺陷。

### 增量评分

移动操作只影响源/目标两间房与班级分散度，评分增量 O(1) 计算：

```
delta = 源房评分项差 + 目标房评分项差 + 合班项差 + 该班分散项差
```

## 三、迭代爬山（核心流程）

### 3.1 操作集（每轮枚举）

1. **份额拆分移动**：把某班 X 人（1~2 人）从房间 A 移到房间 B
   - B 可为：同班房（有空间）、空房（同性别）、1 班房（变 2 班合班，同年级）
   - 约束：≤2 班/间、不超 limit、同年级、6 人间满员不移出、独享且 ≤6 人房不拆
2. **交换**：2 间合班房互换份额（等量交换，容量平衡）

### 3.2 爬山规则

```
每轮：
  枚举全部可行操作 → 选评分下降最多（delta 最小）的操作执行
  若 delta < 0（有改善）：
      实质改善（改善 ≥ 评分 0.5%）→ 无改善计数清零
      微小改善 → 无改善计数 +1
  若 delta ≥ 0（局部最优）：
      "抖动"——执行最不差的操作（可能临时变差）尝试跳出
      无改善计数 +1
  连续 20 轮未刷新历史最优 → 收敛停止
结束时：回滚到历史最优状态（评分最低）
```

### 3.3 收敛检测（防震荡）

- 只有**刷新历史最低评分**才算"实质改善"，抖动变差与抖动后的"恢复"都不算（避免震荡死循环）
- 连续 20 轮未刷新最优 → 停止并回滚（`[V8-xx收敛]` 日志）
- 轮数上限 1000（前端可调），收敛优先于轮数

## 四、伪代码

```
function allocateOneGender(classes, rooms, L0, weights, iterations):
    for L in L0..8:                          # 严格分级初稿
        result = allocateWithLevel(classes, rooms, L)
        if result 成功:
            hillclimb(result, L, weights, iterations)   # 迭代爬山
            return result
    return 失败

function hillclimb(result, L, W, maxRounds):
    occ, rd = result 的状态
    best = (评分, 状态快照)                    # 历史最优
    noImprove = 0
    for round in 1..maxRounds:
        ops = 枚举所有可行移动/交换          # 约束 S2/S5/S6
        bestOp = ops 中 delta 最小者
        if 无可行操作: break
        执行 bestOp
        cur = 重算评分
        if cur < best.评分 - 阈值(0.5%):     # 实质改善
            best = (cur, 快照); noImprove = 0
        else:
            noImprove += 1
            if noImprove >= 20: break        # 收敛停止
    occ, rd = best.快照                      # 回滚
    重建 allocations，输出
```
