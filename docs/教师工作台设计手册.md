# 教师工作台设计手册

> 版本：v1.19.47.25（2026-10-09）｜状态：**开发中**（占位文档，待补全文）
> 所属模块：`workbench`（无独立库，只读汇聚）｜页面前缀：`/workbench`
> 文档体系：`设计文档.md`（总手册）→ 本手册（模块手册）

## 1. 模块定位与边界

**做什么：** 全体教师（登录用户）的个人工作页面——个人信息（手机号 / 登录密码 / 身份证状态，独立成页）、今日课程、我的课表、我的业绩（提交与查看）、班主任工作记录（占位）。
**不做什么：** 不持有独立数据库；不直接修改教务/成绩数据（只读汇聚 + 少数自有操作如手机号修改）；仅展示本人数据。

## 2. 数据库设计

**无独立库。** 数据来源：
- `academic.db / teachers`（本人教师记录，`teacher_of_user`：user_id 精确关联，兜底唯一同名自动补关联）
- `achievement.db / teacher_achievements`（本人业绩；2026-10-10 起业绩独立成库，原在 academic.db）
- `timetable.db / term_schedules + schedule_entries`（本人课表，按 `teacher_uid` 过滤；与教务端「我的课表」同源）
- `system.db / users`（登录账号）

## 3. 权限与数据范围

- **无需权限点**：所有登录用户可访问（仅本人数据，无跨人暴露）——
  `/workbench/`、`/workbench/profile`（个人信息）、`/workbench/phone`（改手机号）都是"仅本人"，不设权限点；
  `/workbench/my-schedule`、班级概览等跨班数据的页面才用权限点（如 `workbench.class_view`）
- 手机号修改：密码确认 + 全局唯一校验（同步 `users.username` 与 `teachers.phone`）——即"登录名自改权"
- 登录密码修改：复用 `auth.change_password`（弱口令黑名单 / 强度策略 / 与原密码比较），
  个人信息页内嵌同一套表单，POST 到该路由并带 `next` 回跳（2026-10-13）
- 业绩提交：`status=pending` 待教务审核；账号未关联教师名单时显示引导提示

## 4. 核心流程与页面

### 4.1 `/workbench/` 工作台首页（卡片式，2026-10-13 重排信息流）

1. **个人信息**（第一行左）—— 个人隐私信息（**手机号 / 登录密码状态 / 身份证状态**）置顶展示，
   下面是只读基本资料（姓名、教师编号、任教学科、身份、权限组、账号）；
   卡片头「个人中心」按钮 → `/workbench/profile`（改手机号 / 改密码都在那里，首页不再弹窗）
2. 今日课程（按当天星期 + **当前教学周**过滤课表：单双周的课只在对应周出现；
   **节次显示学校的作息名**——`period_number` 只是行号（1=早读），
   展示用 `period_defs.period_name`（`period_number=8` → 「第7节」，见
   `app/utils/period_label.py::period_label`，模板全局）；无数据时占位提示）
3. 待办与通知（待办 + 最近通知 + 未读数）
4. 我的课表（按星期分组徽章展示）+ 班主任工作记录（占位）
5. 我的班级课表（仅班主任，多个班页签切换）
6. 我的业绩（列表 + 提交弹窗，含审核状态徽章）
7. 调课（申请 / 请人代课 / 待我确认 / 我的申请）
8. 考勤入口、班级概览（均按权限点决定是否渲染，避免"看得见、点了 403"）

### 4.2 `/workbench/profile` 个人信息（个人中心，2026-10-13 新增）

| 区块 | 内容 | 可否修改 |
|---|---|---|
| ① 隐私信息与账号安全（**置顶**） | 手机号（＝登录账号）、登录密码、身份证状态 | 手机号 / 密码**本人可改**；身份证仅管理员可改 |
| ② 基本资料 | 姓名、教师编号、任教学科、身份、账号、权限组、数据范围 | 只读（变更联系管理员） |
| ③ 更多设置 | 用户设置（AI 配置 / 我的权限 / 界面偏好）、我的课表、退出登录 | — |

- 与右上角头像菜单里的「用户设置」（`auth.my_settings`）**分工**：本页面向教师本人、隐私信息置顶；
  AI 配置 / 权限清单 / 界面偏好留在用户设置页，两页互相有入口。
- 手机号修改成功后回跳本页（表单带 `return_to=profile`，取值只认白名单，不接受任意跳转地址）；
  改密表单带 `next=/workbench/profile`，成功或失败都回跳本页（失败用 flash 提示）。

## 5. 与其他模块的数据交互

- **读入：** 教务（教师记录、业绩、课表）、平台（登录账号、权限组）
- **写出：** 手机号修改（users + teachers.phone）、登录密码修改（users.password_hash，经 `auth.change_password`）、
  业绩提交（achievement.db；2026-10-10 起业绩独立成库，原在 academic.db）
- **对外提供：** 无（纯个人页面）

## 6. 故障隔离自检

| 场景 | 影响面 |
|------|--------|
| `academic.db` 损坏 | 工作台显示"未关联"引导；手机号修改不可用；其他模块不受影响 |
| `achievement.db` 损坏 | "我的业绩"列表与提交不可用（2026-10-10 业绩独立成库）；教师名单/课表/手机号不受影响 |
| `system.db` 正常性 | 登录、权限判断依赖 system（根基库），异常为全局问题而非本模块问题 |
