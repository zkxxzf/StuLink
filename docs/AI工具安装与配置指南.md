# AI 工具安装与配置指南

> 适用范围：把 AI 能力装进你的电脑或工作流的全部常见形态——本地部署工具、云端 API 工具、
> 浏览器插件、桌面应用、IDE 插件。文档以 **StuLink MCP 服务**作为贯穿实例，
> 但方法、检查项与排查思路对所有 AI 工具通用。
>
> 目标不是"照着点下一步"，而是让你在任何一种形态下都能回答四个问题：
> **要装什么 → 怎么确认装好了 → 怎么让多个工具保持一致 → 装不上时从哪里查起。**

## 1. 先建立认知：AI 工具的四种交付形态

不同形态的差别不在"功能强弱"，而在**四件事**：代码跑在哪、依赖装在哪、凭据放在哪、
谁负责升级。先把这张表看懂，后面的所有差异都能自己推导：

| 形态 | 运行位置 | 主要依赖 | 凭据边界 | 更新方式 | 典型代表 |
|---|---|---|---|---|---|
| **本地部署型** | 你自己的机器/服务器 | Python/Node 运行时、依赖包、数据库、端口 | 凭据留在本机配置文件 | 手动升级或一键脚本 | StuLink MCP 服务、Ollama、LM Studio、vLLM |
| **云端 API 型** | 厂商服务器 | 只需网络 + API Key | 凭据（Key）掌握在你手里，**数据要出网** | 厂商自动升级 | OpenAI / Anthropic / DeepSeek 兼容服务 |
| **浏览器插件型** | 浏览器沙箱内 | 浏览器版本、扩展权限 | 登录态与浏览器同域共享 | 商店自动更新 | 网页助手类扩展、用户脚本 |
| **桌面应用型** | 本机进程 | 安装包（自带运行时） | 应用配置目录内的 JSON/env | 应用内更新 | Claude Desktop、Cherry Studio、ChatBox |
| **IDE / 编辑器插件型** | 编辑器进程内 | 编辑器版本、插件市场 | 工作区或全局配置 | 市场自动更新 | VS Code / JetBrains / CodeBuddy 等插件 |

**判断口诀**：

- 要"数据不出本机" → 选**本地部署型**或本地模型；
- 要"零运维、随时用" → 选**云端 API 型**；
- 要"在浏览器里贴身干活" → **浏览器插件**；
- 要"日常对话 + 接本地能力" → **桌面应用**；
- 要"在代码/文档现场干活" → **IDE 插件**，并优先用 MCP 这类标准协议接本地服务。

## 2. 安装前必须确定的六类组件

任何 AI 工具的安装，本质都是把这六类组件凑齐。缺哪一类，就会在第 6 章的验证阶梯里
卡在对应层级。

| # | 组件 | 要确认什么 | 如何确认 | 缺失后果 |
|---|---|---|---|---|
| 1 | **运行时** | Python / Node / 浏览器 / 容器版本 | `python --version`、`node -v`、`docker -v` | 脚本直接报"命令不存在" |
| 2 | **依赖包** | 依赖清单是否齐全、版本是否被锁定 | `pip install -r requirements.txt`、市场页的"依赖说明" | 装了主程序但启动即 ImportError |
| 3 | **服务端点** | 本机 / 局域网 / 公网；端口与路径 | 服务启动横幅、`netstat`、浏览器打开探活地址 | 客户端连不上或连到旧实例 |
| 4 | **凭据与账户** | 本地账号、API Key、服务令牌、组织授权 | 服务端配置说明、厂商控制台 | 401 / 403，功能被静默禁用 |
| 5 | **配置与数据文件** | 文件位置、编码（UTF-8）、读写权限 | 应用设置页、配置目录 | 改了没生效（改的不是生效那份） |
| 6 | **系统资源** | 端口占用、内存/显存、磁盘、证书 | 任务管理器、`netstat -ano`、`df -h` | 启动成功但随机崩溃、加载极慢 |

### 2.1 环境与依赖的通用要求

- **运行时版本**：以依赖清单与镜像的显式声明为准。例：StuLink MCP 需要
  **Python 3.11+**（与主应用一致；Docker 镜像为 `python:3.11-slim`），
  不要靠"系统默认 python"碰运气。
- **隔离环境**：Python 用 venv、Node 用本地 node_modules，**永远不要装进全局环境**。
  隔离的价值是"删掉目录 = 彻底卸载"，也是不同工具互不污染的保证。
- **编码**：Windows 中文环境务必 UTF-8（脚本里 `chcp 65001` / `PYTHONUTF8=1`），
  否则中文路径、中文输出会乱码甚至报错。
- **网络**：需要访问包源（PyPI/npm/插件市场）。受限网络要预先配置镜像源或代理，
  而不是等安装失败再补。

### 2.2 权限与账户要求

| 场景 | 需要什么权限 | 说明 |
|---|---|---|
| 安装到系统目录 | 管理员 / sudo | 能装到用户目录就避免提权（更安全） |
| 创建虚拟环境 / 写数据目录 | 目录读写权限 | 避免放在 `C:\Program Files`、NAS 只读共享里 |
| 监听端口 | 高位端口无需特权 | 避免占用 80/443 这类需特权的端口 |
| 云服务 | API Key（或组织授权） | Key 要绑定额度与最小权限，可随时吊销 |
| 访问业务系统 | 业务账号（且**最小权限**） | 例：给 MCP 建只读账号，而不是用 admin |
| 浏览器插件 | 扩展权限（站点访问、剪贴板等） | 安装时看清权限弹窗再点允许 |
| 企业环境 | 可能被策略禁用 | 商店禁用时只能用离线包（第 4.3 节） |

### 2.3 常见平台差异

| 维度 | Windows | macOS | Linux |
|---|---|---|---|
| 路径与空格 | `\` 分隔、路径常含空格与中文 → 配置里要**双反斜杠或正斜杠** | `/Users/...`；App 数据在 `~/Library/Application Support/` | `/home/...`；配置多在 `~/.config/` |
| 环境变量 | `setx` / 会话级 `$env:` | `launchctl` / shell 配置；GUI 应用不继承 shell 变量 | shell 配置 / systemd 单元 |
| 执行权限 | 一般无此概念 | 首次运行需"仍要打开"（未签名应用） | `chmod +x` |
| 防火墙 | 首次监听会弹窗，**误点"取消"会导致本机都连不上** | 弹窗允许即可 | 需显式放行端口（ufw/firewalld） |
| 解释器查找 | `py -3.12` 启动器最稳 | `python3`（无 `python`） | `python3`，注意发行版差异 |
| 编码 | 默认可能是 GBK → 必须强制 UTF-8 | UTF-8 | UTF-8 |
| 杀软 | 可能拦截脚本/监听端口 | 一般无 | 一般无 |

## 3. 通用安装流程（六步法）

每一步都给出**完成判定**（做不到就不许进下一步）——这是避免"装到一半不知道哪错了"的关键。

### 步骤 1：环境预检

- 确认运行时可执行、版本符合要求、能访问包源。
- 确认端口空闲、目标目录可写、磁盘充足。
- **完成判定**：`python --version`（或等价命令）输出版本达标；目标端口无监听。

### 步骤 2：获取与校验安装包

- 只用**官方渠道**（官网 / 官方仓库 / 官方市场），核对发行方与版本号。
- 下载后校验（哈希或签名），企业环境尤其必要。
- **完成判定**：能说出"这个包从哪来、版本是多少、谁发布的"。

### 步骤 3：安装运行时与依赖

- 先建隔离环境，再按依赖清单一键安装；失败时**从第一条报错读起**（第一条才是根因）。
- **完成判定**：安装命令退出码为 0；`pip list` / `npm ls` 能看到关键依赖。

### 步骤 4：首次配置（最小可用）

- 只填**必需项**：端点、凭据、开关。先把服务跑起来，再逐项加参数。
- 凭据用占位符替换，避免手抄错（空格、引号、全角字符是最常见错误）。
- **完成判定**：配置文件语法合法（JSON 能被解析）、服务能启动且不报错。

### 步骤 5：分层验证

- 按第 6 章 L0→L6 逐层验证，**不要跳层**。
- **完成判定**：用真账号跑通"真实取数"（L5），并用越权操作验证边界（L6）。

### 步骤 6：固化

- 开机自启（快捷方式 / 服务 / 计划任务）、配置备份、把"端口/账号/路径"写进自己的备忘。
- **完成判定**：重启一次机器（或重启客户端），全部功能照常可用。

## 4. 分形态详解

### 4.1 本地部署型（自托管服务与本地模型运行时）

**特点**：一次安装、长期运行；所有数据留在本机；升级需要人工介入。

#### 通用流程

1. 装运行时（Python/Node/容器）；
2. 建隔离目录与虚拟环境；
3. 安装依赖（依赖清单必须来自仓库，不靠记忆逐个装）；
4. 生成/编辑配置文件；
5. 启动并验证（看启动日志横幅 → 探活 → 业务握手）；
6. 设为常驻（服务/计划任务）。

#### 实例：StuLink MCP 服务（HTTP 模式完整流程）

**① 组件清单**

| 组件 | 本项目取值 |
|---|---|
| 运行时 | Python **3.11+**（Docker 镜像 `python:3.11-slim`） |
| 虚拟环境 | `mcp_server\.venv`（与主应用完全隔离） |
| 依赖 | `mcp_server/requirements.txt`（内含主应用依赖 + `mcp>=2.3.0,<3.0.0` + `uvicorn`） |
| 服务端点 | 默认 `http://127.0.0.1:8765/mcp` |
| 凭据 | StuLink 账号密码（`auth_mode=account`，默认）或静态令牌（`token` 模式） |
| 配置文件 | `mcp_server\config.json`（首次启动自动生成，含逐键中文说明） |
| 前置依赖 | 主应用数据库（MCP 直接读取主应用的数据库文件） |

**② 安装与启动**

```bat
:: 建隔离环境并安装依赖（依赖清单见 mcp_server/requirements.txt，约 1-3 分钟）
python -m venv mcp_server\.venv
mcp_server\.venv\Scripts\python.exe -m pip install -r mcp_server\requirements.txt

:: 启动服务（默认监听 127.0.0.1:8765，端点 /mcp）
mcp_server\.venv\Scripts\python.exe mcp_server\run.py
```

> Docker 部署（NAS / 服务器）：`docker build -f Dockerfile.mcp -t stulink-mcp:v1.0.0 .`，
> 再由 `deploy/docker-compose.yml` 的 `mcp` 服务承载。详见 [MCP 服务技术文档](MCP服务技术文档.md)。

**③ 关键配置项**（`config.json`，改完需重启服务）

| 键 | 默认 | 说明 |
|---|---|---|
| `host` / `port` / `path` | `127.0.0.1` / `8765` / `/mcp` | 监听地址与端点；改为 `0.0.0.0` 才能被局域网访问 |
| `auth_mode` | `account` | 每请求校验账号密码（推荐）；`token` 为兼容模式 |
| `require_token` | `false` | 是否再加一道静态令牌（防端口扫描） |
| `allow_write` | `true` | 写工具总开关；只读场景建议改 `false` |
| `max_rows` | `200` | 单次返回行数上限，防"一次拉全库" |
| `allowed_hosts` | `[]` | Host 白名单（DNS 重绑定防护），留空自动放行本机 |

**④ 验证**（详见第 6 章）：启动横幅出现 → 端口可连 → MCP 握手成功 → 工具列表 30 项 →
真实取数成功 → 越权操作被拒。

**⑤ 局域网开放检查单**

- [ ] `host` 改 `0.0.0.0`，防火墙放行端口；
- [ ] `require_token` 打开（或确保每个客户端都有独立账号）；
- [ ] 给 MCP 用**独立的最小权限账号**，不用 admin；
- [ ] 确认 `allowed_hosts` 覆盖访问方的 Host；
- [ ] 明确"谁能访问这个端口"（同网段是否有不可信设备）。

#### 常见坑（本地部署型通用）

| 症状 | 常见根因 |
|---|---|
| 启动即报错、窗口一闪而过 | 运行时版本不符 / 依赖没装全；**用命令行跑一次看完整报错** |
| 端口被占用 | 旧实例没退（`netstat -ano \| findstr 8765`） |
| 本机能用、局域网不能用 | `host` 仍是 `127.0.0.1`；或防火墙拦了入站 |
| 改了配置没生效 | 改的不是生效文件；或没重启进程 |
| 中文乱码 | 未强制 UTF-8（脚本加 `chcp 65001`、env 加 `PYTHONUTF8=1`） |
| 杀软报毒/拦截监听 | 加信任目录；不要为了省事关杀软 |

### 4.2 云端 API 型

**特点**：无安装负担，但**数据要出网**、按量计费、受网络与配额影响。

#### 核心配置三要素

| 要素 | 说明 | 常见错误 |
|---|---|---|
| `base_url`（端点） | 官方地址，或兼容网关地址 | 用了不带 `/v1` 的地址；公司代理重写路径 |
| API Key | 凭据本体，可吊销、可限额 | Key 写进代码仓库；多个工具共用一个 Key 无法分账 |
| 模型名 | 必须与端点支持的清单一致 | 复制了别家模型的名称 |

#### 安装/配置流程

1. 在厂商控制台创建 Key，**按用途命名**（如 `stulink-mcp-dev`），设置额度与 IP 白名单（若支持）；
2. 在工具的设置页填入端点与 Key，先点"测试连接"；
3. 用一次最小请求确认可用（1 个 token 的请求即可）；
4. 记录：Key 归属、额度、到期/轮换时间。

#### 验证

- 最小请求返回 200 且内容正常；
- 故意用错 Key → 应得到明确的 401（证明错误可被区分，而不是静默失败）；
- 控制台能看到这次的用量（证明 Key 用对了）。

#### 混合架构（最常见）

```
本地 AI 客户端 ──(API Key, 出网)──> 云端模型
      └──(本机 HTTP/stdio, 不出网)──> 本地 MCP 服务（如 StuLink）──> 本地数据库
```

要点：**模型在云端、数据在本地**这条线必须清楚——模型只能看到工具返回的那部分数据，
所以"工具返回什么"就是数据出网的边界（这也是 MCP 侧要做权限与字段裁剪的原因）。

#### 常见坑

- **Key 泄露**：进了 Git、日志、截图。处理：立刻吊销重发，改从环境变量读取。
- **计费失控**：把 Key 给了自动化脚本却没设额度。
- **代理与证书**：企业代理下 HTTPS 失败（自签证书需导入信任链），表现为"连接超时"或证书错误。
- **区域限制**：某些服务对地区/网络有要求，表现为握手阶段就被断开。

### 4.3 浏览器插件型

**特点**：装进浏览器沙箱，权限敏感，受商店与企业策略控制。

#### 两种安装途径

| 途径 | 适用 | 步骤要点 | 风险 |
|---|---|---|---|
| 官方商店安装 | 个人日常使用 | 商店页 → 添加 → 看清权限弹窗 → 允许 | 低（有商店审核与自动更新） |
| 开发者模式加载（解包扩展） | 企业内部分发、离线环境、商店不可用 | 扩展管理页开启开发者模式 → "加载已解压的扩展程序" → 选择含 `manifest.json` 的目录 | 中（无自动更新；来源要可信） |
| 用户脚本（脚本管理器） | 轻量网页改造 | 安装脚本管理器 → 新建脚本 → 粘贴并保存 | 中（脚本能读页面内容） |

#### 权限模型要点

- **站点访问权限**（`host_permissions`）：决定插件能读哪些网站的页面内容，能少给就少给；
- **可选权限**：好的插件会按需申请，而不是安装时一次要全；
- **Manifest V3**：后台改为 Service Worker（空闲会被回收），老旧插件可能因此失效；
- **跨域请求**：插件发起跨域请求受 `host_permissions` 与 CORS 双重约束，直连本地服务
  时还可能撞上混合内容（HTTPS 页面请求 HTTP 本地服务）限制。

#### 验证

1. 扩展管理页中状态为"已启用"，无红色错误标记；
2. 打开目标网页，插件图标可交互、面板能正常弹出；
3. 需要联网/本地服务时，插件自身的日志（右键 → 检查 → Console）无报错。

#### 常见坑

| 症状 | 根因 |
|---|---|
| 商店打不开/安装被禁用 | 企业策略管控 → 改用离线包或走管理员白名单 |
| 装上了但不生效 | 未授予站点权限；或页面 CSP 限制；或需刷新页面 |
| 更新后失效 | Manifest V3 迁移、接口变更 → 回退版本并等待作者修复 |
| 连不上本地服务（如 127.0.0.1:8765） | 混合内容限制 / 服务未启动 / 端口不对 |
| 静默失效 | 浏览器升级后旧扩展被禁用 → 查看扩展页的提示 |

---

### 4.4 桌面应用型

**特点**：安装包自带运行时，双击可用；配置集中在应用自己的配置目录；
**支持 MCP 的桌面应用是接本地能力的主力**。

#### 安装流程

1. 从官方站点下载对应平台安装包（macOS 认准签名/公证，Windows 认准发行方）；
2. 安装到默认位置（自定义路径带来的问题通常多于收益）；
3. 首次启动完成引导（登录/填 Key/选模型）；
4. 如需接入本地 MCP 服务，编辑应用的 MCP 配置文件后**完全退出并重启应用**。

#### 配置文件位置（常见约定）

| 平台 | 位置形态 |
|---|---|
| Windows | `%APPDATA%\<厂商>\<应用>\` |
| macOS | `~/Library/Application Support/<厂商>/<应用>/` |
| Linux | `~/.config/<厂商>/<应用>/` |

（不同应用文件名不同，如 `claude_desktop_config.json`、`mcp.json`；
以应用官方说明为准，不要照抄。）

#### 接入 StuLink MCP 的两种写法

HTTP 模式（服务已在运行）：

```json
{
  "mcpServers": {
    "stulink": {
      "type": "streamableHttp",
      "url": "http://127.0.0.1:8765/mcp",
      "headers": {
        "X-StuLink-User": "<你的 StuLink 账号>",
        "X-StuLink-Password": "<你的账号密码>"
      }
    }
  }
}
```

stdio 模式（应用自己拉起进程，无需手动启动服务）：

```json
{
  "mcpServers": {
    "stulink": {
      "type": "stdio",
      "command": "<项目路径>\\mcp_server\\.venv\\Scripts\\python.exe",
      "args": ["<项目路径>\\mcp_server\\run_stdio.py"],
      "env": {
        "PYTHONUTF8": "1",
        "STULINK_MCP_USER": "<你的 StuLink 账号>",
        "STULINK_MCP_PASSWORD": "<你的账号密码>"
      }
    }
  }
}
```

#### 实例：豆包（豆包工作）HTTP 接入

豆包客户端把外部 MCP 服务加为「自定义插件」。官方入口与字段（据豆包工作帮助中心）：

1. 打开豆包客户端 → 左侧「插件·技能·伙伴」→「插件」页 → 右上角「+ 添加」→「新建自定义插件」；
2. 按下表填写后保存：

| 字段 | 填什么 |
|---|---|
| 服务器名称 | `StuLink`（自定义，即插件名） |
| 传输类型 | **HTTP** |
| 服务器 URL | 见下方"地址必须公网可达" |
| 自定义 Headers | `Authorization` = `Basic <base64(账号:密码)>`（单头写法，不依赖多条 Header） |

3. 生效确认：「我安装的」里能看到该插件且开关已开启；在任务对话框用 `/` 或 `@` 唤起它。

**关键前提：HTTP 模式的地址必须公网可达。** 官方把 HTTP 定位为"连接云端程序"、
STDIO 定位为"连接本地运行的程序"——即 HTTP 请求极可能由豆包云端发起，
此时 `127.0.0.1` 指向的是豆包的服务器而不是你的电脑，**必定连不上**。三个可选做法：

| 做法 | 命令/要点 | 适用 |
|---|---|---|
| 内网穿透隧道 | `cloudflared tunnel --url http://127.0.0.1:8765`（或 frp / ngrok）→ 得到 `https://xxx.trycloudflare.com`，URL 填 `…/mcp` | 最快验证 |
| 部署到公网服务器 | 与主应用同机部署 MCP，Nginx 反代 + HTTPS，开放 `https://域名/mcp` | 长期方案 |
| 改用 STDIO | 传输类型选 STDIO，填 `mcp_server\.venv\Scripts\python.exe` + `run_stdio.py` + 账号环境变量 | 不想让数据出网 |

**公网暴露必须同时做的加固**（account 模式每个请求都带账号密码，明文 HTTP 等于泄露凭据）：

- [ ] 用 HTTPS（隧道自带证书；自建用 Nginx + 证书）；
- [ ] `require_token` 改 `true`，并加第二个 Header `X-StuLink-Token: <config.json 里的 token>`；
- [ ] `allow_write` 改 `false`（豆包是云端模型，避免误改本地数据）；
- [ ] 给豆包单独建一个**最小权限账号**，绝不用 admin；
- [ ] `allowed_hosts` 填入公网域名（DNS 重绑定防护；留空只自动放行本机与监听地址）；
- [ ] 确认学校/合规允许"学生数据经公网传给第三方云模型"，否则选 STDIO 或隧道 + 只读账号。

生成 Basic 头（在服务所在的机器上执行）：

```powershell
[Convert]::ToBase64String([Text.Encoding]::UTF8.GetBytes("你的账号:你的密码"))
```

> 若不确定豆包 HTTP 是否接受内网/本地地址，先按上表试隧道地址；填 `http://` 被拒就换 `https://`。

#### 常见坑

| 症状 | 根因 |
|---|---|
| 改了配置没反应 | 应用没完全退出（托盘常驻）；或编辑的是另一个安装的配置目录 |
| stdio 模式报"找不到命令/文件" | 路径含空格或中文未加引号/未转义；相对路径不解析 |
| HTTP 模式连不上 | 服务没启动；或端口/路径写错 |
| macOS 提示"应用已损坏" | 未签名应用被 Gatekeeper 拦 → 系统设置里放行 |
| Windows 首次运行被拦 | SmartScreen/杀软 → 核对发行方后放行 |

### 4.5 IDE / 编辑器插件型

**特点**：与代码/文档同处一个工作区，最适合"让 AI 直接操作项目"；
MCP 配置分**工作区级**与**全局级**两处，容易改错地方。

#### 安装

| 方式 | 适用 | 要点 |
|---|---|---|
| 市场在线安装 | 绝大多数情况 | 搜索插件名 → 核对发布者 → 安装 → 重载窗口 |
| VSIX 离线安装 | 内网/离线环境 | 从官方渠道下载 `.vsix` → "从 VSIX 安装" |

#### MCP 配置位置

| 层级 | 作用范围 | 典型位置 |
|---|---|---|
| 工作区级 | 只对当前项目生效 | 项目内 `.mcp.json` / 编辑器工作区设置 |
| 用户级（全局） | 对本机所有项目生效 | 编辑器用户设置里的 MCP 配置段 |

**建议**：项目专用的服务（如 StuLink）放工作区级；通用能力（如文件系统工具）放全局级。

#### 验证（IDE 场景）

1. 插件面板显示 MCP 服务状态为"已连接"；
2. 工具列表里能看到预期的工具数量（StuLink 当前为 30 项）；
3. 用一句只读提问验证真实取数（例："查 2025级01班最近一次考试"）；
4. 用越权提问验证边界（用受限账号时应返回"权限不足"）。

#### 常见坑

- **PATH 问题**：stdio 模式的 `command` 用绝对路径，不要依赖 shell 的 PATH；
- **工作目录**：相对路径以编辑器的工作区为基准，容易与双击运行不一致；
- **超时**：首次调用要建 Flask app + 预热，可能超过默认超时 → 增大客户端超时或先手动启动服务；
- **长连接被回收**：HTTP 模式长时间闲置后重连失败 → 重启服务或客户端；
- **改错层级**：在工作区级配置里找不到服务，实际写进了全局配置（或反之）。

## 5. 接入传输方式怎么选（stdio / Streamable HTTP）

| 维度 | stdio | Streamable HTTP |
|---|---|---|
| 谁启动服务 | 客户端拉起子进程 | 你手动/服务方式常驻 |
| 生命周期 | 跟随客户端（关客户端即停） | 独立（可多客户端共享） |
| 适合场景 | 单人本机、免手动启动 | 多人共享、局域网、需要常驻与审计 |
| 凭据位置 | 客户端 `env`（环境变量） | 请求头（每请求认证） |
| 网络暴露 | 无端口，天然不暴露 | 需自行控制监听地址与防火墙 |
| 多客户端一致性 | 每个客户端各自拉起一份 | 共用一份服务，天然一致 |
| 排查难度 | 子进程日志分散在客户端里 | 服务端日志集中 |

**决策建议**：

- 只有你自己用、图省事 → **stdio**；
- 多人/多工具共用、要审计与统一权限 → **HTTP**（默认 `127.0.0.1`；需跨机时再改 `0.0.0.0` 并加令牌）。

## 6. 验证"安装成功"的分层阶梯（L0–L6）

**永远按层级往下走**：上层没过，查下层的问题，不要跳到"业务功能不可用"。
以 StuLink MCP（HTTP 模式）为例，其它工具可类比：

| 层级 | 验证什么 | 操作 | 通过标准 | 失败时看哪里 |
|---|---|---|---|---|
| **L0 进程** | 服务/应用在运行 | 看启动窗口/任务管理器 | 有进程，横幅打印完整 | 启动日志、退出码 |
| **L1 连通** | 端口可连、路径可达 | `Test-NetConnection 127.0.0.1 -Port 8765` | TcpTestSucceeded=True | 监听地址、防火墙、端口占用 |
| **L2 协议** | MCP 握手 | 客户端发起连接 / `curl` 发 initialize | 返回会话信息（非 4xx/5xx） | Host 白名单、协议版本、路径 |
| **L3 认证** | 凭据有效 | 用真实账号密码连接 | 不再返回 401 | 错误码：`unauthorized`/`invalid_credentials`/`account_disabled`/`invalid_token` |
| **L4 工具** | 工具清单完整 | 客户端查看工具列表 | 数量与预期一致（StuLink 30 项） | 工具模块加载错误（看服务端日志） |
| **L5 取数** | 真实数据可读 | 问一句只读问题 | 返回真实数据而非报错 | 数据库文件、缓存 TTL、参数 |
| **L6 边界** | 权限与范围正确 | 用受限账号/越权提问 | 明确返回"权限不足" | 权限点、数据范围、账号角色 |

**通用验证命令速查**：

```powershell
# L1：端口连通
Test-NetConnection 127.0.0.1 -Port 8765

# L1/L2：HTTP 探活（MCP 端点对未认证请求应返回 401 + 中文说明，而不是超时）
curl.exe -i -X POST http://127.0.0.1:8765/mcp `
  -H "Content-Type: application/json" `
  -d '{\"jsonrpc\":\"2.0\",\"id\":1,\"method\":\"initialize\",\"params\":{}}'
```

```bat
:: L4/L5：项目自带端到端自测（含认证、权限、写开关用例）
mcp_server\.venv\Scripts\python.exe mcp_server\smoke_mcp.py
:: 通过则输出：通过 40 / 失败 0
```

> 提醒：**只看"进程启动了"就认为装好，是最常见的误判**。
> L5 之前都不算装完。

## 7. 如何在不同工具之间保持一致

多工具接入同一个服务后，最容易出现"这个能用、那个不能用"。根因几乎都是四点不一致：
**端点不同、凭据不同、版本不同、配置层级不同**。用下面的办法系统性消除：

### 7.1 建立单一事实源（SSOT）

```
服务端（唯一真相）           客户端（副本）
mcp_server/config.json  ←──  各 AI 工具的接入配置
   · 监听地址/端口/路径          · 只填写"服务端给的"信息
   · 认证模式与凭据类型          · 不自行猜测/拼凑 URL
```

**规则**：客户端配置里出现的 URL 与凭据类型，必须能从服务端启动横幅或
`config.json` 直接抄到；不允许"凭记忆写"。

### 7.2 三份不变量

| 不变量 | 统一做法 | 检查方式 |
|---|---|---|
| 端点 | 统一写 `http://127.0.0.1:8765/mcp`；需要局域网时**统一改一次**配置并同步所有客户端 | 所有客户端配置里搜同一个 URL |
| 凭据来源 | 统一用"账号密码头"（或统一令牌）；**禁止**一半工具用旧令牌一半用账号 | 各客户端配置的键名是否一致 |
| 权限预期 | 明确每个工具用哪个账号，且都是**最小权限** | 用同一账号在任一客户端做同一提问，结果应一致 |

### 7.3 落地手段

1. **一份片段模板**：把第 4.4/4.5 节的 JSON 片段存到项目文档里，各工具直接复制，
   只替换凭据（避免手写出错）；
2. **凭据集中**：能读环境变量的优先用环境变量（`env` 字段 / 系统环境变量），
   一处更新、多处生效；
3. **版本锁定**：客户端与服务端都记录版本号（StuLink 用 `python -m scripts.bump_version show`），
   升级前查兼容（如 MCP SDK 的 `mcp>=2.3.0,<3.0.0` 约束）；
4. **配置清单一览表**（建议自己维护一张，随改随更新）：

   | 工具 | 版本 | 接入方式 | 配置文件位置 | 凭据来源 | 最后验证日期 |
   |---|---|---|---|---|---|
   | 例：某桌面应用 | x.y.z | HTTP | `%APPDATA%\...\mcp.json` | 专用只读账号 | 2026-10-11 |
   | 例：某 IDE 插件 | x.y.z | stdio | 工作区 `.mcp.json` | 环境变量 | 2026-10-11 |

5. **变更同步**：服务端改了端口/认证方式后，把"需要同步的客户端清单"过一遍，
   每个改完都做一次 L2→L5 快速验证。

## 8. 排查安装失败：分层定位法

### 8.1 定位顺序（照着问自己）

1. **进程在吗？**（L0）——不在：看启动日志第一条报错。
2. **端口通吗？**（L1）——不通：监听地址/防火墙/端口占用。
3. **协议握手成吗？**（L2）——不成：路径写错、Host 白名单、版本不兼容。
4. **认证过吗？**（L3）——不过：区分 401 的五种错误码（见下）。
5. **工具齐吗？**（L4）——不齐：工具模块加载报错、依赖缺失。
6. **取数对吗？**（L5）——不对：数据库/参数/缓存。
7. **边界对吗？**（L6）——不对：权限点与数据范围（这是"权限问题"，不是"安装问题"）。

### 8.2 认证类错误码速查（StuLink MCP）

| 响应 `error` | 含义 | 处理 |
|---|---|---|
| `unauthorized` | 没带账号密码 | 客户端补 `X-StuLink-User/Password` 或 Basic |
| `invalid_credentials` | 账号或密码错误 | 核对账号密码；注意全角字符与首尾空格 |
| `account_disabled` | 账号被停用 | 联系管理员启用或换账号 |
| `invalid_token` | 服务令牌缺失/错误 | 用 `config.json` 里的 `token`（`require_token=true` 时必需） |
| `too_many_attempts` | 连续失败被锁定 | 按 `Retry-After` 等待（默认 300 秒） |

### 8.3 通用错误对照表

| 症状 | 可能原因 | 确认方法 | 处理 |
|---|---|---|---|
| 命令找不到 / 脚本一闪而过 | 运行时未安装或不在 PATH | 命令行手动执行同一条命令 | 装运行时；或用绝对路径 |
| `ModuleNotFoundError` | 依赖没装全 / 装错环境 | `pip list` 查关键包 | 在**同一环境**重装依赖 |
| `Address already in use` | 端口被占用 | `netstat -ano \| findstr <端口>` | 结束旧进程或换端口 |
| 连接超时 | 服务未起 / 防火墙 / 代理 | 本机先 `Test-NetConnection` | 放行端口；配置代理例外 |
| `401 Unauthorized` | 凭据缺失或错误 | 看响应体 `error` 字段 | 按 8.2 处理 |
| `403 Forbidden` | 权限不足或被策略拦截 | 看是业务层还是网关层 | 换账号/调整权限；企业策略找管理员 |
| Host 校验失败（4xx） | 访问用的 Host 不在白名单 | 看服务端日志 | 配 `allowed_hosts` 或用被允许的地址访问 |
| 中文乱码 | 编码非 UTF-8 | 终端 `chcp` / 文件编码 | 统一 UTF-8 |
| 配置改了不生效 | 改错文件 / 未重启 | 打开实际生效的配置文件核对 | 改对文件并完全重启 |
| 首次调用超时、之后正常 | 冷启动慢（建应用/预热） | 看服务端启动日志 | 增大客户端超时；先手动启动服务 |
| 客户端显示"已连接"但提问报错 | 工具层错误（非安装问题） | 看工具返回的 `error` | 属参数/权限问题，见 8.2 与 L6 |
| 局域网其他机器连不上 | 监听在 127.0.0.1 | 本机看横幅地址 | 改 `host=0.0.0.0` + 防火墙放行 |
| 升级后全部工具报错 | 版本不兼容 | 对比升级前后版本 | 回退版本或按发布说明调整 |

### 8.4 排查时该准备什么信息（向他人求助时）

1. 形态与版本（工具名 + 版本号 + 操作系统）；
2. 完整报错原文（截图/日志，**打码凭据**）；
3. 卡在 L0–L6 哪一层（第 6 章对照）；
4. 已尝试过的步骤与结果；
5. 相关配置文件片段（同样**打码凭据**）。

## 9. 安全与合规基线

无论哪种形态，以下 7 条是底线：

1. **最小权限账号**：给 AI 工具用的账号只开必需权限（只读场景绝不发写权限）；
2. **凭据不落库、不进 Git**：配置文件加 `.gitignore`；泄露立刻吊销重发；
3. **默认不暴露**：本地服务默认只听 `127.0.0.1`；确需跨机时再加令牌与白名单；
4. **写操作单独开关**：确认 AI 工具的写入能力是你主动打开的（StuLink 的 `allow_write`）；
5. **留痕**：能审计"谁在什么时候调了什么"（StuLink MCP 会写系统操作日志，认证失败也留痕）；
6. **数据出境边界**：用云端模型时，只有工具返回的数据会出网——工具返回什么，
   决定了隐私边界（这也是要控制字段与范围的原因）；
7. **定期复核**：账号权限、Key 额度、客户端配置清单（每季度过一遍）。

## 10. 附录

### A. 四种形态速查

| 形态 | 装什么 | 配什么 | 怎么验证 | 最常踩的坑 |
|---|---|---|---|---|
| 本地部署 | 运行时 + 隔离环境 + 依赖 | 配置文件（端口/凭据/开关） | 横幅 → 端口 → 握手 → 取数 | 端口占用、host 未开放、编码 |
| 云端 API | 什么都不用装 | 端点 + Key + 模型名 | 最小请求 + 控制台用量 | Key 泄露、代理证书、额度 |
| 浏览器插件 | 商店安装或加载解包 | 站点权限 | 面板可用 + Console 无报错 | 企业策略、混合内容、版本失效 |
| 桌面应用 | 官方安装包 | 应用配置目录内的 JSON | 应用内状态 + 重启后可用 | 未完全退出、路径写错 |
| IDE 插件 | 市场/VSIX | 工作区级 vs 全局级 MCP 配置 | 连接状态 + 工具数 + 真实取数 | PATH、工作目录、改错层级 |

### B. StuLink MCP 配置模板（可直接复制）

见本文 4.4 节（桌面应用）与 4.5 节（IDE）：HTTP 与 stdio 两种写法各一份。
凭据一律用占位符替换；`require_token=true` 时在 headers 中追加：

```json
"X-StuLink-Token": "<config.json 里的 token>"
```

### C. 术语表

| 术语 | 含义 |
|---|---|
| 运行时 | 执行程序的环境（Python、Node、JRE 等） |
| 隔离环境 | 项目独立的依赖目录（venv / node_modules） |
| 端点 | 服务的访问地址（协议 + 主机 + 端口 + 路径） |
| 凭据 | 证明身份的东西（账号密码、API Key、令牌） |
| MCP | Model Context Protocol，AI 客户端接本地能力的标准协议 |
| stdio / Streamable HTTP | MCP 的两种传输方式（子进程管道 / HTTP 请求） |
| SSOT | 单一事实源：只允许一个地方定义"真相"，其余都是副本 |
