## 二、`exam_guard` vs `check_exam_visible` 差异清单

这两个函数都在判断"某个年级的资源我能不能看"，但**口径不同**。这是审计里唯一实质性的安全隐患。

| 场景 | `check_exam_visible`（考试） | `assert_grade_visible`（考务批次） | 是否一致 |
|---|---|---|---|
| admin | 放行 | 放行 | ✅ |
| 用户级授权年级命中 | 放行 | 放行 | ✅ |
| 用户级授权年级**未命中** | **拒绝** | **拒绝** | ✅ |
| 任课教师，年级在任课映射内 | 放行 | 放行 | ✅ |
| `scope=SCOPE_SCHOOL` | 放行 | 放行 | ✅ |
| `scope=SCOPE_GRADE` 且年级不符 | 拒绝 | 拒绝 | ✅ |
| `scope=SCOPE_GRADE` 且年级相符 | 放行 | 放行 | ✅ |
| **`scope=SCOPE_CLASS`（班主任）** | 看 `UserClassLink` 的**年级集合**，不在则拒绝 | **先看该年级有无他管的班，有则放行** | ❌ **分歧** |
| **毕业年级数据** | `exam.grade in 毕业年级 且 scope≠SCHOOL → 拒绝` | **无此判断** | ❌ **分歧** |
| `homeroom_teacher`/`grade_leader` 角色 | 走 `get_scope` 通用分支 | **额外兜底**：只要本年级有他管的班就放行 | ❌ **分歧** |
| 无任何有效范围 | 拒绝 | 拒绝 | ✅ |

### 两处真实分歧

**分歧 1：班主任访问本年级考务**

- `check_exam_visible`：班主任看**非自己年级**的考试 → 拒绝
- `assert_grade_visible`：班主任只要在该年级**有任何一个班**，就能看/建该年级考务 → 放行

**分歧 2：毕业年级**

- `check_exam_visible`：**明确拒绝**（非全校范围看毕业年级数据）
- `assert_grade_visible`：**完全没判断**，班主任若管着某毕业年级的班，就能看到该毕业年级考务

### 建议

按**更严格**的 `check_exam_visible` 统一，即给 `assert_grade_visible` 补上"毕业年级拒绝"。但这是**功能变更**（会让部分班主任失去对毕业年级考务的访问），需要你确认。

## 四、如果发现问题的处理

| 现象 | 可能原因 | 排查 |
|---|---|---|
| 宿舍合班名不对 | 归一逻辑 | 看 `/assignments/manage` 保存请求 |
| 批量设置没拦截已占用房间 | 我的批量判定 | 检查 `rooms.py` `batch_setting` 的 `occupied_room_ids` |
| 调班无记录 | 日志顺序 | 看日志里有没有"调班记录写入失败" |
| 页面 500 | 语法/导入 | 看后端控制台 traceback |
| 静态资源 404 | `?v=` 版本号 | 我拆了 `_register_asset_version`，确认 `su()` 仍输出 `?v=` |
