## 1. 项目背景与目标

### 1.1 现状

StuLink 当前已包含：学生基础信息（system.db）、宿舍分配（dormitory.db）、系统管理、积分管理（占位）等模块。成绩管理目前仅有占位页：

- 路由：[app/modules/grades/routes.py](../app/modules/grades/routes.py) 提供 `/grades/`、`/grades/history`、`/grades/alumni` 三个空视图（"功能开发中"）；
- 模板：`app/templates/grades/index.html` 为占位页；
- 权限：`grades.view`（查看成绩）、`grades.edit`（成绩管理）两个 key 已在权限组模块预置，但无业务支撑；
- 数据库：**没有任何考试/成绩相关表**，需全新设计；
- 首页 `welcome/index.html` 已有"成绩管理"入口卡片（占位状态）。

### 1.2 目标

为 StuLink 新增**成绩管理与可视化分析系统**，形成"考试成绩导入 → 数据存储 → 划线分层配置 → 四大分析模块可视化 → 导出"的完整闭环。系统只做**客观统计与可视化**（表格 + ECharts 图表），不输出任何文字分析报告；预留 AI 分析接口位，二期接入。

### 1.3 范围界定（In / Out）

| In（本期） | Out（不在本期，列为二期） |
|---|---|
| 考试登记与历次成绩 Excel 批量导入（支持两种模板识别 + 单班导入） | 往届/毕业年级成绩在线分析（grades/history、alumni 占位页保留，对接毕业归档流程） |
| 任课教师-班级-科目映射维护（账号制） | AI 文字分析（仅预留接口） |
| 考试级划线/分层配置（自定义名称与分数线，支持按比例自动划线） | 去极值均分（去最高/最低）等扩展指标 |
| 年级 / 班级 / 学科 / 任课教师 四大分析模块（表格+图表） | 学生端/家长端查询 |
| 表格导出 Excel（openpyxl）、页面打印导出 PDF（浏览器打印样式） | 成绩单打印、成绩条 |
| 权限控制（管理员/年级长/班主任/任课教师） | 移动端适配 |

### 1.4 术语表（全文统一口径）

| 术语 | 定义 |
|---|---|
| 年级 | 与主库字典一致，如 `2024级`/`2025级`（全校格式统一；**导入文件中的年级只认此格式**，不认"高三/高二/高一"等称谓列） |
| 班级 | `01班`~`10班`（年级+班级成对使用，班级不跨年级复用） |
| 方向 | 选科方向：`物理` / `历史`（源：字典 `subject_direction`、班型设置 `class_profiles.subject_direction`） |
| 选科组合 | 如 `物化生`、`史政地`（源：学生 `subject_selection`，12 种组合见字典） |
| 考试科目（9 科全集） | `语文、数学、外语、物理、历史、化学、生物、政治、地理`（新增字典 `exam_subject`，固定显示顺序） |
| 应考科目 | 某学生某场考试的应考集合 = 语数外 + 方向科（物理/历史二选一）+ 选科组合中 2 门再选科，共 6 门 |
| 参考学生 / 参考数 | 该考试中至少有一门应考科目成绩的学生；**不分学籍状态**（借读等一律计入，用户确认 #8），凡导入有分即统计 |
| 缺考（科目） | 应考科目无成绩（导入单元格留空） |
| 方向排名 | 物理类内部、历史类内部各自按总分（或单科）降序排名；同分同名次（竞争排名，后续顺延跳号） |
| 班排名 | 本班同方向学生内排名（默认班级内学生同方向；若混向则按方向内子集排名） |
| 进退步 | 本次考试总分方向排名 − 上一次同方向考试总分方向排名（负数为进步；上次为"同方向上一场已导入考试"） |
| 分层 / 层 | 将方向内参考学生按总分切分为有序若干层，默认四层：优秀 / 良好 / 及格 / 待提升；名称与层数均可配置 |
| 分数线 / 线 | 层的分界分数（含"上线人数"统计用法）；每条线可"固定分数"或"按方向内人数比例自动换算"取值 |
| 科目优秀率 / 及格率 | 该科分数 ≥ 该科"优秀线 / 及格线"（默认 = 满分的 90% / 60%，可按科配置）的学生占比 |
| 低分人数 | 该科分数低于"低分线"（默认 = 满分的 40%，可按科配置）的人数 |
| 得分率 | 均分 ÷ 该科满分（用于雷达图等跨科可比指标） |
| 分数段 | 总分等距分段，默认 30 分为一档（可配 10/20/30/50/100），显示时隐藏全空段 |
| 名次段 | 方向内名次区间分段（默认 1-10/11-20/21-30/31-50/51-100/101-200/201 及以上，可配），用于考察头部集中度 |
| 参考数口径 | 见"参考学生"；所有均值/率/分层/箱线/排名类指标均只基于参考学生；学籍状态（借读等）仅作信息标注，不影响统计 |

## 2. 需求分析（与需求方沟通结论固化）

### 2.1 需求来源

- 需求方原话整理（见 2.3 需求总表）；
- 分析维度参照：根目录 `参考表格/分析表成绩分析全匹配V1.0.xlsx`（共 35 个 sheet，详见第 3 章映射）；
- 2026-09-02 两轮需求澄清问答，结论见 2.2。

### 2.2 已确认口径决策（Q&A 记录，设计依据）

| # | 澄清点 | 需求方结论 | 对设计的落点 |
|---|---|---|---|
| 1 | 分层/分数线口径 | 分层名称与分数线由用户输入；每次上传新的全年级成绩后可在系统设置相关分数线；支持按比例划线 | 引入"划线/分层配置"（考试级），预置模板，第 5.3、8.2 节 |
| 2 | 排名口径 | 按方向分列排名 | 所有"校排/年级排"= 方向内排名；第 5.4、8.1 节 |
| 3 | 成绩数据管理范围 | 完整闭环：考试登记 + Excel 导入 + 任课教师映射维护 + 成绩修正 | 第 5、6 节 |
| 4 | 年级范围 | 各年级独立（考试/成绩按年级组织），毕业年级不做在线分析 | exam 绑定 grade；第 5.1 节 |
| 5 | 导入文件与总分 | 两种模板自动识别（参考 Excel 结构 / 简化结构），支持总分列外部提供或系统按应考科目累加；另支持单班小批量导入 | 第 6.3 节 |
| 6 | 分数段与名次段 | 两种视图都要（总分等距分数段 + 方向内名次段） | 第 8.3 节 |
| 7 | PDF 导出方案 | 浏览器打印样式（@media print），Excel 走后端 openpyxl | 第 7.5 节 |
| 8 | 参考/统计口径（借读等） | **借读生等不剔除**：只要有分、是这个班的学生，成绩一律计入 | 废除原"学籍剔除"草案：凡导入有分学生全部参与统计与排名，学籍状态仅作信息标注；术语表/5.3.2/第 8 章同步 |
| 9 | 考试登记方式 | 每次考试新建：选年级、确定考试日期；考试名称默认 = 年级 + 考试日期 | exams.name 默认自动生成（可改）；5.3.1/10.1 |
| 10 | 导入表头与分批覆盖 | 表头需先明确；支持分批导入（先历史方向后物理方向、或分批导不同科目）；**后导入的为准，可覆盖上次导入** | 模板列定义（6.3）；行×列增量覆盖模式 A + 整场重置模式 B |
| 11 | 教师映射维护 | 支持 Excel 批量导入 + 网页端单独改；按年级分设；与用户管理对接；任课教师登录后仅能看到自己的科目 | 6.4（批量导入转本期）/9.2（账号制确认） |
| 12 | 成绩导入模板列 | 学生成绩模板表头**增加"年级"列**；年级一律用 `2024级/2025级…` 形式，与字典表一致 | 模板列定义 + 行级年级校验（6.3）；术语表同步 |
| 13 | 教师导入与账号（基于《教师安排表.xlsx》样例） | 按姓名核对是否已有账号：已有 → 绑定；没有 → 自动新建（默认账号=姓名拼音，后期可自行改为手机号）；**姓名不可改** | 横表同构导入 + 自动开户流程（6.4）；用户管理 real_name 锁定（9.5） |

> 注：需求原文"年级各班汇总表"示例列为"优秀数｜及格数｜待提升数"，与班级分层统计表的四层（优秀/良好/及格/待提升）不一致。按确认结论 #1，**层数与层名由考试级配置决定、表格列随配置动态生成**：系统默认预置"四层模板"（3 条线切成 4 层：优秀/良好/及格/待提升）；需求方若希望汇总表只出 3 个计数，可在配置中删除"良好"层或改用它模板。各表头呈现见第 7.3 节规格。

#### C. 非功能要求

- 客观性：任何界面不出现对教师/班级/学生的评价性文字，图表只呈现数值；
- 兼容：现代浏览器（Chrome/Edge，内网环境），沿用 Bootstrap 5 + jQuery 基础栈，不承诺 IE；
- 性能：一次考试成绩数据（约 550 学生 × 9 科目 ≈ 5 千行）聚合查询应在 1s 内返回（SQLite 索引 + 内存聚合，见 6.2）；
- 数据安全：成绩库独立文件 `grades.db`，导入解析不落盘原始文件（仅存校验报告）；
- 审计：考试导入/删除/划线修改等关键操作写入操作日志（复用 OperationLog）。

### 4.2 数据层定位（新库 grades.db）

- 新增 SQLite 独立库 `data/grades.db`，在 `config.py` 的 `SQLALCHEMY_BINDS` 增加 `'grades'` 条目（与 dormitory/history 多库模式一致）；模型统一声明 `__bind_key__ = 'grades'`。
- 理由：① 与现有模块独立库架构一致（可独立备份/清理）；② 成绩属敏感数据，隔离存储降低与基础库互相影响；③ 单次考试数据量小（约 550 学生 × 9 科 ≈ 5 千行），SQLite 完全胜任。
- 表创建：Flask-SQLAlchemy 多 bind 模式下 `db.create_all()` 覆盖所有 bind，首次启动自动建表；数据目录已被 Docker 卷挂载（stulink-data），**无需重建容器**，与轻量部署规则兼容。
- 跨库策略：成绩库不建外键到主库；学生信息按需批量查询（一次 `WHERE student_no IN (...)` 拉全考试名单），在 Python 层组装。参考宿舍模块跨库 relationship 的 viewonly 先例（本模块用"批量取数 + dict 组装"，不建 ORM relationship）。

### 4.3 技术选型与复用清单

| 项 | 选型 | 说明/依据 |
|---|---|---|
| 后端 | Flask + Flask-SQLAlchemy（现状） | 不做变更 |
| Excel 导入/导出 | openpyxl（现状已用） | 导出样式沿用 export_helpers 的表头/边框约定 |
| 图表 | ECharts 5（新引入） | 需求指定；CDN 方式与现有 Chart.js（jsdelivr）一致；如内网 CDN 不稳可在 app/static/js 落地 vendor 文件（部署时随代码上传） |
| 表格 | Bootstrap 5 原生表格 + 轻量 JS 排序 | 无需引入表格插件；统一 css class（见 7.4） |
| 权限 | 现有 role/scope_type/UserClassLink 体系 | 见第 9 章 |
| 审计/日志 | OperationLog（现有） | 导入/重算/删除/划线修改记日志 |
| 缓存 | Flask-Caching simple（config 已配置，未启用的模块可直接复用） | 分析接口结果缓存 60~300s，按 (tab, exam_id, direction, class, subject) 拼 key，考试数据变更时按 exam 前缀失效 |

### 4.4 端到端数据流

```

→ 解析校验(模板识别/学号匹配/分数校验) → 校验报告(成功/错误/未匹配) → 确认导入

→ 分层配置(默认模板生成，可改线值/层名/比例) → 四大分析页(表格+图表, 按权限过滤) → Excel 导出 / 打印 PDF
```

#### 5.3.2 exam_scores（成绩明细，窄表）

核心设计：一学生一科目一行（含伪科目 `总分` 行），快照冗余学生属性，统计/排名无需跨库。

| 字段 | 类型 | 说明 |
|---|---|---|
| id | INTEGER PK | |
| exam_id | INTEGER NOT NULL，索引 | |
| student_no | TEXT NOT NULL | 学号快照（主库匹配键） |
| student_name | TEXT | 姓名快照 |
| grade | TEXT | 年级快照 |
| class_name | TEXT | 班级快照（换班不影响历史统计口径） |
| direction | TEXT | 方向快照（物理/历史） |
| subject_selection | TEXT | 选科组合快照 |
| subject | TEXT NOT NULL | `语文..地理` 9 科之一，或 `总分` |
| score | REAL | 分数（NULL = 无成绩）。总分行：外部总分优先，否则=应考 6 科求和（缺考科按 0） |
| rank_class | INTEGER | 班排名（NULL=未参与，如该科缺考/整场未参考） |
| rank_dir | INTEGER | 方向排名 |
| move_rank | INTEGER | 仅总分行：进退步（本次方向排 − 上次方向排，负数=进步）；上次不存在为 NULL |
| updated_at | DATETIME | |

唯一约束：`(exam_id, student_no, subject)`。
索引：`(exam_id, subject)`、`(exam_id, subject, class_name)`、`(exam_id, subject, direction)`、`(exam_id, class_name, subject)`。

**写入规则（导入口径，重要；分批覆盖细节见 6.3）**：
1. 参考与计入：文件中有分的学生即"参考"，**不分学籍状态**（借读/在籍不在校等仅作信息标注，不剔除、不影响任何统计与排名，用户确认 #8）；
2. 该生应考科留空 = 缺考（无行）；非应考科若粘贴了数值（参考 Excel 整表粘贴时历史类学生"物理"列常为空格）→ 解析时自动忽略并提示；
3. 增量覆盖：同一 (考试, 学号, 科目) 后导入的有分数据覆盖旧值；文件出现的科目列中为空 → 删除旧行（记为本次缺考）；**文件未出现的科目列不受影响**（支持分批导不同科目）；
4. 总分行：文件含总分列则覆盖采用；不含则当该生应考 6 科齐全后系统自动重算（详见 6.3）；
5. 整场无任何成绩的名单行 → 不导入，确认报告提示；分数越界（>满分+0.5 / <0 / 非数值）→ 错误行拦截；
6. 单条修正（成绩管理页编辑某科分数/补录）→ 考试置 `dirty`，提供"重新计算排名"一键（重算后置回 `imported`）；每次导入确认后同样整场重算排名与进退步。

#### 5.3.3 exam_bands（分层/上线界配置）

| 字段 | 类型 | 说明 |
|---|---|---|
| id | INTEGER PK | |
| exam_id | INTEGER NOT NULL | |
| direction | TEXT | 物理/历史（分层按方向独立设置；同值适用双方向时也可只建方向=空串一行，统计时双向套用） |
| seq | INTEGER | 层序（1=最高层） |
| name | TEXT | 层名（默认：优秀/良好/及格/待提升） |
| lower_mode | TEXT | 该层下界取值方式：`score`(固定分数) / `ratio`(方向内参考人数百分比，自动换算为名次→分数) |
| lower_value | REAL | 下界值（ratio 时为百分数 0~100） |

- 约定：seq=1 层为最高层（无上界）；每层人数 = 方向内参考学生中 `score(总分) >= 本层下界且 < 上一层下界` 的学生数（待提升层下界视为 0）。
- "X 线人数/上线"（Excel 语义，如"特控线上线"）即"该线对应层及以上各层的累计人数"，由层定义自然推导，无需重复存储。
- 界面"分层模板"：① 四层模板：优秀(ratio 20) / 良好(ratio 60) / 及格(ratio 95) / 待提升；② 高考线模板：清北(ratio 3) / 985(ratio 8) / 211(ratio 20) / 特控(ratio 60) / 本科(ratio 95) / 未上线。模板应用时自动把 ratio 换算为分数落库（保留换算参数快照到 config_json，便于"该考试改人数后重算"）。层名可改、层可增删，**列头随配置动态生成**（对应确认 #1）。
- 比例换算法：按方向内参考学生总分降序名次取（名次 ≤ 参考数×比例% 的学生分数）为下界分数；同分并列时取该名次档最低分，保证"低于此分不入层"。
- 实现注记（v1.9.0）：一期换算后直接以固定分数落库（layer 行统一 lower_mode='score'），不保留比例参数快照；参考人数变化后重新"应用模板"即可按新人数重算。

#### 5.3.4 teacher_subject_links（任课教师映射）

| 字段 | 类型 | 说明 |
|---|---|---|
| id | INTEGER PK | |
| grade | TEXT NOT NULL | |
| class_name | TEXT NOT NULL | |
| subject | TEXT NOT NULL | 9 科之一（不含"总分"） |
| user_id | INTEGER NOT NULL | 教师账号（users.id）；前提：任课教师均有系统账号 |
| active | INTEGER | 是否生效（离职/换岗可停用，保留历史映射） |
| created_by / created_at / updated_at | | |

唯一约束：`(grade, class_name, subject)`（一科一班一师，同一教师可带多班多科）。A4 分析只取 active=1 且当前年级的映射；历史有效性控制由"新学期停用+新建"完成，不做时间片（一期从简）。

### 5.4 排名与进退步算法（落库定义）

1. 排名对象：方向内（物理类全体 / 历史类全体）与班内（班级同方向子集），分别对总分行与各科行计算；
2. 排序键：分数降序；分数相同 → 名次相同（并列），下一名次按人数顺延（1,1,3…）；
3. 不参与排名：缺考（无行）、整场未参考（未产生总分行）；学籍状态不影响排名（确认 #8）；
4. 进位：保留一位小数的原始分；分数异常（>满分+1 或 <0 或非数值）在导入校验阶段拦截；
5. 进退步 move_rank（总分行）= 本场方向排名 − 上一场（同方向、日期最近且早于本场、已导入）方向排名；上次缺考/未参考/首场考试 → NULL（前端显示"-"）；
6. 重算触发点：确认导入、单条成绩修正、整场删除后；重算实现 = 内存排序后按 exam_id 批量 UPDATE（事务包裹，失败回滚并保留原值）。

### 5.5 数据快照与一致性策略

- 成绩行快照班级/选科/方向：学生中途换班/转科不影响历史考试统计（"当时在哪个班就以哪个班统计"）；主库学生改名不追溯（历史成绩显示导入时姓名）。
- 借读身份**不**快照，运行时以主库当前状态为准（与宿舍模块一致）；成绩明细页对借读生行加徽标。
- 年级毕业归档（grade_mgmt 流程）不删除 grades.db 数据：毕业年级考试数据保留只读（成绩模块筛选列表默认不出现已毕业年级，二期通过 history/alumni 查询页开放）。

### 6.2 分析 API 通用约定

统一端点：`GET /grades/api/analysis/{grade_tab|class_tab|subject_tab|teacher_tab}?exam_id=&direction=&class_name=&subject=&rank_scope=`（rank_scope=dir/class 仅明细表用）。

响应结构：

```json
{
  "success": true,
  "data": {
    "exam": {"id": 1, "name": "期中", "date": "2025-11-12", "grade": "2025级", "status": "imported"},
    "tables": {
      "class_summary": {
        "title": "年级各班汇总表",
        "columns": [{"key": "class_name", "label": "班级", "type": "text"}, ...],
        "rows": [{"class_name": "01班", "avg": 512.3, ...}, ...]
      }
    },
    "charts": {
      "avg_bar": {"type": "bar", "title": "各班总分均值对比", "xAxis": ["01班", ...],
                   "series": [{"name": "总分均值", "data": [512.3, ...], "itemStyle": {...}}]},
      "score_box": {"type": "boxplot", "xAxis": [...], "series": [{"data": [[min,q1,med,q3,max], ...]}]}
    },
    "meta": {"direction": "全部", "bands": [{"name": "优秀", "count": 45, "ratio": 0.10}]}
  }
}
```

- 数据点精度：均值/标准差/分差 1 位小数，占比类 1 位小数，排名/人数整数；全部由后端格式化并携带 `type` 供前端排序/导出；
- 每 tab 返回该 tab 全部表格+图表所需数据（单请求渲染，前端不二次拉取）；表格排序在前端本地完成；
- 服务端数据权限过滤（scope_service）在先，任何筛选参数都受白名单钳制（见第 9 章）；
- 无数据考试（draft）或空结果：返回 `tables: {}` 与 `charts: {}` + `meta.empty=true`，前端渲染空态引导；
- 缓存：响应按 (tab+全部入参+用户范围) 拼 key 缓存 60s，考试成绩/分层变更按 exam 前缀清除。

### 6.3 成绩导入设计

**导入模板（表头明确；模板下载含 3 个 sheet：模板 A / 模板 B / 填表说明）**

| 模板 | 列定义（第一行必须为表头，列顺序不限） | 说明 |
|---|---|---|
| 模板 A（推荐，兼容参考 Excel） | `学号`(必填) `姓名`(必填) `年级`(选填) `班级`(选填) `总分`(选填) + 9 科列 `语文 数学 外语 物理 历史 化学 生物 政治 地理` | 参考 Excel"学生成绩表"整表复制粘贴即可（多余列自动忽略） |
| 模板 B（简化/分科） | `学号`(必填) `姓名`(必填) `年级`(选填) `班级`(选填) + 若干科目列（可只含本次导入的科） | 无总分列；**两个模板都允许只含部分科目列** |

- **列名兼容映射**：`学号/学生学号→student_no`，`姓名→student_name`，`年级→grade`（仅认 `2024级` 格式，`高三/高二` 等称谓列识别后忽略），`班级→class_name`，`总分/总成绩→total`；科目列名须与字典 `exam_subject` 一致；`考号/方向/选科` 等多余列识别后忽略不报错；仅"考号"无"学号"列 → 报错"需补充学号列"（考生编排维护二期）；
- 识别规则：含 `总分` 列视为模板 A，否则模板 B；解析后向操作员展示识别结果供确认；
- **年级列（确认 #12）**：有"年级"列 → 逐行校验与考试年级一致（格式 `2024级`），不一致的行列为错误（防跨年级混入）；无"年级"列 → 默认按考试年级处理；
- **班级/方向范围**：文件含"班级"列 → 以班级列定范围（仅含 01-05 班即单班/多班分批，一次导历史方向班级、下次导物理方向班级）；无"班级"列 → 操作员在向导中选"全部 / 物理方向 / 历史方向 / 指定班级"作为范围；
- **身份与快照**：学号为主键匹配主库学生（无学号可按 姓名+班级 匹配并逐条列出候选）；方向/选科/班级快照由系统按学号带出，不信任文件中的方向/选科列内容（防错填）。

**分批导入与覆盖规则（用户确认 #10：后导入的为准，可覆盖）**

模式 A：增量覆盖（默认）
- 本次影响范围 = 文件内出现的行（学生）× 文件内出现的科目列；
- 单元格：有分 → upsert 覆盖旧值；文件含该科目列但该生为空 → 视为该科本次缺考：删除旧行且不建行；**文件未出现的科目列一律保留原值**（第一次导语数外、下次补导其他科时互不影响）；
- 总分行：文件含总分列 → 覆盖采用外部值（与系统累加差异 >1 分时报告提示，操作员可选择采用累加值）；文件不含 → 合并后该生应考 6 科齐全则自动重算并覆盖总分行，不齐则保留旧总分行并提示"该生科目不全，请补导或手动补总分"；
- 未出现在文件中的原有成绩学生 → 默认保留（防误删），确认页列出"N 人未出现"，可勾选"一并移除（删除其全部成绩行）"以纠正错导人员；
- 确认导入后**整场重算排名与进退步**（部分覆盖后榜单自动自洽）。

模式 B：整场重置（纠错场景：上次整体导错要重来）
- 清空该考试全部成绩行后仅按本次文件导入；强确认（输入考试名）。

**解析校验与报告**：
1. 表头识别失败 / 缺学号列 → 明确报错并引导下载模板；
2. 分数越界（非数值 / 负分 / >满分+0.5）→ 错误行列表（不阻断整批，可导出错误明细 xlsx）；
3. 学号未匹配主库 → 错误列表；全行无分 → 忽略并提示"未参加 N 人"；
4. 学籍状态（借读/在籍不在校等）**不剔除、不提示阻断**，仅统计页标注（用户确认 #8）；
5. 确认页差异预览：新增 X 人 / 更新 Y 条 / 缺考删除 K 条 / 未出现保留 P 人（或一并移除）→ 确认后事务提交。

**导入状态机（防误覆盖/并发）**：

```
draft(新建) ──上传+确认──> imported ──单条修正/再次上传──> dirty ──重算/确认──> imported
      └──────────────────< 删除考试（级联）
```

- 上传解析（预检）不落库，返回报告后由操作员确认；确认动作校验 `import_token`（预检批次号）防串批；SQLite 写事务内提交，失败自动回滚；并发同考试导入由 token + 事务串行双重保证；
- 每次导入批次（模式/范围/差异摘要/操作人）写入 import_info 并记 OperationLog；
- 16MB 上传限制沿用 Config.MAX_CONTENT_LENGTH；上传文件仅内存解析（BytesIO），不写磁盘。

### 6.4 任课教师映射维护

- **按年级分设**：映射以 `(年级, 班级, 科目)` 为唯一维度（5.3.4）；每个年级独立矩阵互不影响，同一教师可跨年级、跨班带课；维护页顶部选年级，科目行 × 班级列展示；
- **网页端维护**：矩阵单元格下拉选教师账号（来源 users，teacher/班主任角色优先排序）即单改保存；支持"整行/整列批量填充"（如某教师带 01-05 班同一科）；
- **Excel 批量导入（与《教师安排表.xlsx》同构，确认 #11/#13）**：导入模板采用学校实际使用的"总任课表"横表结构——**一行一个班级、科目为列**（语文/数学/英语/物理/化学/生物/政治/历史/地理），列头另含 年级/班级/选科/正班/副班/教室位置/班型 等（自动忽略）；一个文件可含**多个年级区段**（如 2024级/2025级/2026级 三段，解析器按"X级任课安排"标题行 + 表头行分段）；教务排课导出的原表可直接上传，也可使用下载模板（同构示例，含填表说明 sheet）；样例文件：`StuLink学生数据20260813/教师安排表.xlsx`（含 2024/2025/2026 三级三段 + 备课组长区段，2026-09-03 解析确认）；
  - 列别名：`英语→外语`（对齐字典 exam_subject），其余科目列名照录；`年级` 列只认 `2024级` 格式，`高三/高二/高一` 称谓列忽略；
  - 忽略内容：选科/正班/副班/体育/音乐/美术/信息/心理/教室位置/班型列、"备课组长"区段、含 COUNTA 公式的"数量"统计行、合并标题行；
- **账号核对与自动开户（确认 #13）**：
  1. 解析后逐 (年级, 班, 科) 组合按**姓名（user.real_name）精确核对**系统账号；
  2. 已有账号且启用 → 直接绑定（同组合旧映射停用）；账号已停用 → 错误提示"账号已停用，请先启用"；姓名重名 → 错误行列出候选账号供选择；
  3. 无账号 → **自动新建**：real_name=姓名（固定）、username=姓名拼音（pypinyin 无调全拼；重名/与既有账号冲突自动追加序号，预览页可手工修改）、role=teacher、权限组=任课教师组、初始密码=随机 8 位（字母+数字混合）、must_change_pwd=True（首次登录强制改密）；
  4. 预览页汇总：绑定 X 条 / 新开账号 Y 个（列表含 姓名/拟用账号[可编辑]/初始密码，密码仅此一次可见，可复制、可下载《账号开通清单.xlsx》）；确认后统一建号 + 映射写入（同组合重复 = 覆盖更新）；
  5. **账号可改**：拼音仅为默认用户名，教师登录后或管理员可把账号（username）修改为手机号，不影响任课映射（映射绑定 user_id）；**姓名不可改**（见下）；
- **姓名不可改（确认 #13）**：real_name 是身份锚（安排表核对、成绩归属、报表展示均以姓名呈现）；实施时同步锁定"教师管理/用户管理"中的姓名编辑（前端只读 + 后端拒绝修改，联动变更见 9.5）；
- 校验与约束：教师账号须存在且 is_active=1（停用账号不出现于下拉、不参与匹配）；保存即 active=1；
- **与用户管理对接（登录后可见性）**：数据源 = users；教师登录成绩模块后，可见范围 = 其全部 active 映射的并集（跨年级/跨班/跨科自动合并），只能查看**自己科目**的数据（本人 A4 行与走势、本人班科学生排名下钻），看不到其他教师或其他班科目（服务端白名单见 9.2/9.3）；
- 权限：维护（单改+导入）需 grades.teachers，默认管理员组；年级长如需限本年级维护另行配置；
- 审计：单改/批量导入/自动开户均记 OperationLog（模块=grades）。

- **A1-T1**：分层计数列默认 4 列（列名=层名+“数”），单元格值"人数(占比%)"；层配置缺失（draft）时隐藏分层列并提示"考试设置中配置分层"；
- **A1-T3 / A1-T4 / A2-T1 分段列**：段标签如 `[660,690)`、`[630,660)`…，顶部开区间标注；
- **A2-T3 明细**：默认方向排名；行级徽标：学籍徽标(灰，仅信息标注，确认 #8)、有科目缺考(黄)；整表后端一次出全部（≤60 人/班），前端本地排序；"上次"来自上一场同方向考试（导入时已算好 move_rank，直接读列，无需跨场计算）；
- **A2-T4**：层行 + 每层人数/占比 + 总分均值 + 该班应考科目均分列（应考科目=班型配置组合或班内实际出现科目并集）；
- **A3-G9 热力图**：值域着色（低分冷色→高分暖色）连续渐变，无应考格显示浅灰"-"，行列不排序（科目固定序/班级按班号）；
- **A4-G12**：X 轴="教师·班级"（同教师多班同色），tooltip 展示 参考数/及格率；
- **图表默认主题色**与宿舍统计模块调色板一致（蓝 #3b82f6 系），方向物理/历史分色（物理蓝/历史紫），系列 ≥ 2 时自动扩展调色板。

### 7.4 统一样式规范

- 表格：`table table-hover align-middle` + 自定义 `.g-table`（表头白字深蓝底、斑马纹、右对齐数值列），表头右上角提供"展开/收起"；

- 图表卡片统一：圆角卡片 + 标题（图标+表名）+ 容器 360px + `chart` resize 监听；
- 空值一律 "—"，零值显示 0；缺考/借读/未参考用徽标区分色，不写文字评价。

### 7.5 导出与打印（B3，确认 #7）

- **Excel**：见 6.6，前端按钮即调后端下载；
- **打印 PDF**：打印样式表 `@media print`：隐藏侧边栏/顶栏/筛选工具栏/按钮；仅打印当前激活 tab 内容；A4 横向（年级/学科 tab 表格列宽）、表格自动分页（thead 重复）；图表容器设置固定打印宽度（echarts canvas 打印不重绘即可见）；每 tab 内容超过一页时表格头部重复；打印前自动对当前 tab 数据做 DOM 克隆（防止懒加载内容缺失）；
- 用户在打印对话框选"另存为 PDF"（现代浏览器原生支持），页面提示文字不含评价。

### 7.6 边界与空态

- 教师映射未维护（任课教师分析 tab 无数据）：管理员/年级长看到"未维护任课教师映射"引导按钮；教师本人提示"未分配任课班级，请联系管理员"；
- 删除考试/重导前置强确认（输考试名或下拉二次确认，参照宿舍删除房间交互）。

## 8. 分析指标计算口径规范（公式级定义）

> 除特别说明外，所有统计均遵循 **方向内可比原则**：物理类与历史类学生的分数结构不同（应考科目组合不同），排名、分层、上线与基准值都在方向内部计算；界面可通过"方向"筛选查看，默认"全部"时按方向分组展示（分层/名次段等方向敏感表自动按方向分行成表头或由方向筛选决定）。

### 8.1 基础口径

| 指标 | 定义与公式 |
|---|---|
| 学生是否参考（本场考试） | 存在总分行且 `score is not null`（至少一门应考科有分）；**不分学籍状态**（确认 #8） |
| 参考数（班级/方向/年级） | 上述参考学生数；分母一律用参考数 |
| 科目参考数 | 该科 `score is not null` 且学生参考的行数 |
| 总分（无外部总分时） | 应考 6 科（语数外 + 方向科 + 选科组合 2 门再选科）分数之和；缺考科按 0 计；某科为 NULL（非应考）不参与 |
| 均值（班/方向/年级/科目） | 参考者分数之和 ÷ 参考数 |
| 标准差 | 样本标准差 s = √(Σ(xi−x̄)²/(n−1))（n=参考数；n=1 时记为 0），Python `statistics.stdev` 口径 |
| 最高分 / 最低分 | 参考者中 max / min；科目同 |
| 优秀率 / 及格率（科目） | ≥ 该科优秀线 / 及格线（默认 90% / 60% 满分，可按考试、按科在 config 覆盖）的人数 ÷ 科目参考数 |
| 低分人数 | 该科分 < 低分线（默认 40% 满分，可覆盖）的人数（含 0 分参考者） |
| 与年级均值差 | 班级均值 − 方向内年级均值（方向筛选=全部时按该班所属方向取对应年级均值） |
| 得分率 | 科目均值 ÷ 该科满分（雷达图/跨科对比用） |
| 层人数 / 层占比 | 见 8.2 |
| 分数段 / 名次段 | 见 8.3 |
| 班排 / 方向排名 | 见 5.4（同分同名次、缺考与借读默认不参与） |
| 进退步 | 见 5.4 第 5 条（本场方向排 − 上一场方向排） |

### 8.2 分层（exam_bands）与线判定

- 分层仅针对总分（方向内）；层 i 人数 = 总分 `score >= lower_i` 且 `score < lower_{i-1}`（seq=1 层无上界；最低层下界=0）；边界含上不含下（`[下界, 上界)`）；
- 同分并列处理：某生总分恰好等于层界分数时落入高一层（`>=` 归上层），保证方向内"上线"统计的 Excel 语义（"≥ 特控线为上线"）；
- ratio 模式：下界分数 = 参考学生总分降序第 ceil(n×ratio%) 名的分数（同分取该档最低分，使恰为下界的都计入上层）；换算结果落库为 score 模式并保留 ratio 参数快照，人数变化后可"一键按原比例重算"；
- 科目级三线（优秀/及格/低分）默认 = 满分 × 0.9 / 0.6 / 0.4，考试级 `subject_lines` 覆盖；分层模板与科目线相互独立（分层管总分分层，三线管单科合格率类指标）。

### 8.3 分数段与名次段

- 分数段（总分等距）：`band_width` 默认 30（可配 10/20/30/50/100）；段 = [0,30),[30,60)…直到覆盖最高分（`段上限 = ceil(max/width)*width`）；仅输出非空段；A1-T3 输出各班人数与"年级合计人数(占比%)"，A2-T1 输出本班各段人数；
- 直方图（A2-G6）与分数段同宽同界（保证图形与表一致）；
- 名次段（方向内，参考 Excel 段内分布表）：默认界 `rank_bands=[10,20,30,50,100,200,300]` → 段 [1,10],[11,20],[21,30],[31,50],[51,100],[101,200],[201,300],[301+]；界面可改界值（存 config_json）；只统计参与方向排名的参考学生；A1-T4 输出各班各段人数；
- 分段列标签统一：分数段 `[660,690)`；名次段 `11-20`（末段 `301+`）。

### 8.4 特殊值规则

| 场景 | 处理 |
|---|---|
| 某科应考但无分（缺考） | 不产生行、不参与该科统计与排名；明细中该生该科显示"缺考"徽标 |
| 0 分 | 有效成绩（参考者），参与均值/最低分/低分统计与排名 |
| 分数小数 | 最多保留 1 位（导入时四舍五入校验提示）；排名按原值 |
| 学籍状态（借读/在籍不在校等） | 不影响任何统计与排名（确认 #8）；明细与成绩单仅显示学籍徽标作信息标注 |
| 全部科目空行 | 视为未参加本场考试，不入库（报告提示） |
| 单科超满分/负分 | 导入拦截为错误行，不落库 |
| 选科组合异常（无法推断应考科） | 导入时按该生方向 + 主库 subject_selection 推断；推断失败 → 错误行提示人工修正 |

## 10. 关键流程设计

### 10.1 考试登记 → 导入 → 分层 → 分析（主流程）

```
[管理员/年级长]
1. 考试管理 → 新建考试（选年级、定考试日期；名称自动 = 年级+日期，可改；类型可选）→ 状态 draft（确认 #9）
2. 考试详情 → 下载模板（A/B/说明）或直接上传已有成绩表
3. 上传向导 → 选导入模式（A 增量覆盖 / B 整场重置）与范围（班级/方向，文件无班级列时）→ 预检报告
   （识别列/新增 X 人/更新 Y 条/缺考删除 K 条/未出现保留 P 人/错误 E 条）→ 可选导出错误明细后重传
4. 确认导入 → 事务按模式合并写入 + 整场排名/进退步重算 → 状态 imported（导入日志落 OperationLog）
5. 分层配置（默认四层模板一键生成，或高考线模板/手动）→ 保存即生效
6. 进入成绩分析页 → 各 tab 呈现（可选方向/班级/科目切换）
7. 导出 Excel / 打印 PDF
```

### 10.2 分批补导 / 整场重置 / 单条修正 / 删除

- 分批补导（日常推荐流程，确认 #10）：任意时刻再次上传（模式 A），文件只需含要更新的班级/方向与科目列；确认页显示"新增 X 人 / 更新 Y 条 / 缺考删除 K 条 / 未出现保留 P 人"，确认后整场重算；
- 整场重置（模式 B）：上次整体导错时使用，强确认（输入考试名）后清空重导；
- 单条修正：详情页编辑某科分数或补录（补录产生新行）→ 状态 dirty → 页面提示并一键"重新计算"（排名/进退步全量重算）；
- 删除考试：强确认（输入考试名）→ 事务删除 scores/bands → 日志。

### 10.3 分层配置页交互

- 顶部：模板按钮（四层 / 高考线）+ 方向页签（物理/历史）；
- 表格：行=层（seq 降序），列=层名(可改)/下界模式(分数|比例)/下界值/人数预览/占比预览；增删层、上下移；
- 保存：校验层序与界值（下界单调下降、顶层无下界）；保存写库 + 清除该考试缓存；
- 人数预览基于当前导入数据实时计算（缓存 60s），不落库。

### 10.4 教师映射维护流程

- 网页单改：映射页 → 选年级 → 矩阵（科目行×班级列）单元格下拉选教师（仅已有启用账号）→ 保存差异（新增/变更/停用预览）→ 确认；
- 批量导入（推荐）：上传《教师安排表》同构文件 → 区段解析（多年级，英语→外语别名，忽略非高考科目列）→ 逐 (年级,班,科) 组合按姓名核对账号：命中启用账号 → 绑定；停用/重名 → 错误行；未命中 → 自动开户预览行（账号=拼音可编辑、姓名固定、随机初始密码一次性可见）→ 确认（建号 + 映射写入 + 同组合旧映射停用）→ 报告含《账号开通清单》下载；
- 账号规则：username 默认=姓名拼音（冲突加序号），教师后续可自行或管理员改为手机号；real_name 不可修改（用户管理姓名入口锁定，见 9.5）；
- 停用账号不参与匹配与下拉；确认后 A4 分析即时生效。

### 10.5 上线部署与数据迁移步骤（本模块首次发布）

### 12.2 风险与对策

| 风险 | 影响 | 对策 |
|---|---|---|
| 导入成绩与外部成绩单总分不一致（外部总分含听力等） | 分析结果与外部榜单对不上 | 总分列优先外部值并记录来源；导入时对比"外部总分 vs 系统累加"差异 >1 分时在报告提示，操作员可决定采用值（默认外部） |
| 打印图表裁切/分页不佳 | PDF 观感 | 打印样式固定 A4 横向、图表统一 360px 打印宽；实测一次后固化样式 |
| 内网 CDN 不可达 | ECharts 加载失败 | 页面脚本带超时失败提示；必要时 vendor 本地文件（部署随代码） |
| 同时多账号导入同一考试 | 数据互相覆盖 | import_token 批次校验 + 整场事务 + 状态机（dirty），确认页显示差异 |
| 分批导入范围理解偏差（行×列范围/空值=缺考语义） | 部分成绩被意外覆盖或旧行残留 | 确认页差异预览（新增/更新/删除/保留）先行展示"将影响 X 人 Y 条"才可确认；事务内失败回滚；重导前建议导出当前成绩留档 |
| 年级长误删本年级考试 | 数据丢失 | 强确认 + 操作日志（可追溯恢复上次备份） |
| 一次查询数据量增长（多年级×多考试） | 变慢 | 全部查询带 exam_id/grade 条件（索引覆盖）；分析接口 60s 缓存 |
