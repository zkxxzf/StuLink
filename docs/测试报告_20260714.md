## 四、安全测试详情

### 4.1 SQL 注入

| 测试向量 | 目标 | 结果 |
|---------|------|------|
| `?name=' OR 1=1--` | /students/ | 未注入成功（参数化查询） |
| `?name='; DROP TABLE students;--` | /students/ | 未注入成功 |
| `?student_number=1' UNION SELECT * FROM users--` | /students/ | 未注入成功 |
| `?keyword=' OR 1=1--` | /operation-logs/ | 未注入成功（ORM `.like()`） |
| `?name=' OR 1=1--` | /grade-mgmt/history | 未注入成功（参数化） |

**代码审计结论**：检查了 80 处 SQL 执行点，包括：
- `grade_mgmt.py` 毕业归档的原生 SQL（INSERT/SELECT）
- `alumni_app` 往届生查询的动态 WHERE 拼接
- `helpers.py` 的 write_change_log
- `operation_logs.py` 的关键词搜索
- `students.py` / `assignments.py` / `rooms.py` 的 ORM 查询

**全部使用参数化查询（`?` 占位符 + params 传参）**，f-string 仅用于构造 SQL 结构（WHERE 子句列表拼接），值均通过参数传递。**无 SQL 注入风险**。

### 4.7 登录频率限制

| 检查项 | 结果 |
|--------|------|
| 实现位置 | [auth/routes.py:14-16](file:///d:/Users/lenovo/Desktop/StuLink/app/modules/auth/routes.py#L14-L16) |

| 触发后行为 | 返回 200 + flash "登录尝试过于频繁" |

## 七、测试结论

### 7.1 总体评价

**项目状态：可用，适合进入升级开发阶段。**

- 核心功能（宿舍管理、系统管理）完整可用，33 条路由 30 条通过、3 条为测试方法偏差
- 安全防护完善，9/10 项安全测试通过，未发现 High/Critical 漏洞
- 硬约束全部实现（学号必选、隐私提示、时间戳文件名、操作日志）
- 代码质量良好：SQL 全参数化、权限装饰器全覆盖、敏感数据加密

### 7.2 建议改进项（升级时可考虑）

| 优先级 | 建议 |
|--------|------|
| LOW | 登录频率限制改为返回 429 状态码，并在 CSRF 验证前计数 |
| LOW | 补充 /static/ 目录下的占位静态文件，避免 404 日志噪音 |

### 7.3 后续升级测试建议

1. 升级新功能后，重新运行本报告中的路由测试矩阵
2. 新增模块需验证：@login_required + @perm_required 覆盖、SQL 参数化、CSRF 保护
3. 如新增数据库分库，验证 SQLALCHEMY_BINDS 配置和跨库 relationship 的 viewonly 约束
4. 积分/成绩模块开发完成后，补充对应的路由和权限测试
