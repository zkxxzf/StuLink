# 德育管理设计手册

> 版本：v1.19.50.64（2026-10-13）｜状态：**可用**（含两个子模块：积分 `points` + 奖惩 `morality`）
> 所属模块：`points`（独立库 `points.db`）+ `morality`（独立库 `morality.db`）｜页面前缀：`/points`、`/morality`
> 文档体系：`设计文档.md`（总手册）→ 本手册（模块手册）

## 1. 模块定位与边界

本手册覆盖「德育管理」菜单下的**两套并列子系统**，同菜单、同权限组命名空间，但**各自独立成库、生命周期不同**：

| 子系统 | 库 | 定位 | 页面 |
|--------|-----|------|------|
| **积分**（加减分流水） | `points.db` | 日常德育表现的加减分记录，可频繁增删改 | `/points` |
| **奖惩**（奖惩档案） | `morality.db` | 长期档案：表彰与处分，含附件、处分期限、撤销记录 | `/morality/rewards` |

**为什么拆两个库：** 奖惩是**长期档案**（附件、处分期限、撤销记录，毕业后仍要可查），
积分是**日常流水**（随学期波动、可清理）。两者不是一个生命周期，拆库后互不影响
（`app/models/morality.py` 文件头设计口径）。

**做什么：**
- 积分：学生加减分记录（纪律/学习/卫生/活动/其他类别）、按班级筛选、积分汇总统计、录入与编辑、批量导入、导出、积分规则模板
- 奖惩：奖励/惩罚登记（含考试作弊等处分）、类别与级别、处分期限与到期推算、状态流转（待确认→已生效→已撤销）、附件上传与鉴权下载、按范围可见的列表与统计

**不做什么：** 不修改学生基础信息（学号/班级快照）；不承担学生评价的自动计算；
学生画像模块按学号**只读**汇聚积分数据（`portrait_aggregation`），本模块不反向写画像。

## 2. 数据库设计

### 2.1 points.db（2 张表）

| 表 | 说明 |
|----|------|
| `point_records` | 积分记录（学号、姓名、年级/班级快照、分值、类别、事由、备注、日期、操作人） |
| `point_rule_templates` | 积分规则模板（名称、类别、默认分值、说明、是否启用） |

**快照关联：** 学号 + 年级/班级快照 → `system.db / students`（班级快照使积分记录可独立按范围过滤）。

### 2.2 morality.db（2 张表）

| 表 | 说明 |
|----|------|
| `reward_punishments` | 奖惩记录主表（见下） |
| `reward_punishment_attachments` | 附件表：`record_id`（指向主表 id，同库）、`file_name`（原始名）、`stored_name`（落盘名 `uuid.hex + .ext`）、`ext`、`mime`、`size`、`doc_type`（材料分类）、`uploaded_by/uploaded_name`、`created_at` |

**`reward_punishments` 关键字段：**
- 学生快照：`student_no`（索引）、`student_name`、`grade`、`class_name`
- 主体：`kind`（reward/punish）、`category`（类别）、`level`（表彰层级/处分档次）、`title`（事由）、`description`
- 时间：`happen_date`（发生日期，索引）、`expire_date`（到期日；未手填时按「发生日 + `period_months` 个月」推算）
- 惩罚专属：`related_exam`（涉及考试）、`subject`（涉及科目）、`effect`（处理影响）、`period_months`（处分期限月数）
- 奖励专属：`source`（颁发单位）、`award_name`（奖项名称）
- 状态机：`status`（draft 待确认 / confirmed 已生效 / revoked 已撤销）+ `confirmed_by/confirmed_at`、`revoked_at/revoke_reason`
- 其他：`notify_parent`（是否已通知家长）、`operator_id/operator_name`、时间戳

**枚举（`app/models/morality.py`）：** 奖励类别 9 项（学业优秀/竞赛获奖/品德表彰/进步显著/文体活动/志愿服务/学生干部/全勤守纪/其他）；惩罚类别 10 项（考试作弊为首个落地项，另含迟到旷课/课堂违纪/校园欺凌/破坏公物/抽烟饮酒/违规使用手机/宿舍违纪/打架斗殴/其他）；奖励级别 6 档（国家级→班级级）；处分档次 6 档（通报批评→留校察看）；材料分类 7 种（佐证材料/考场记录/情况说明/承诺书/证书扫描件/通知通报/其他）。

**索引：** `idx_rp_grade_class(grade, class_name)`、`idx_rp_kind(kind)`、`idx_rp_date(happen_date)`。

**附件存储：** `app/static/uploads/morality/<record_id>/`，目录名只由记录 id 拼成（不含用户输入）；
`/static/uploads` 直链已被全局 before_request 封禁，必须走带 `morality.view` 鉴权的
`rp_file_view` / `rp_file_download`；`attachment_path()` 用 `os.path.commonpath` 防目录穿越。

**快照关联：** 与积分同口径——学号/姓名/年级/班级快照存储，跨库不设外键；
学生毕业/转班后历史奖惩记录仍可查、不被改。

## 3. 权限与数据范围

**子功能六档（`app/utils/permission_map.py` · points 组， morality 与积分同挂「德育管理」模块）：**

| 子功能 | 不可见 | 只读 | 写入 |
|--------|-------|------|------|
| 查看 | 空集 | `points.view` | — |
| 录入编辑 | — | — | `points.edit` |
| 批量导入 | — | — | `points.import` |
| 导出 | — | — | `points.export` |
| 规则模板 | — | — | `points.rules` |
| **奖惩信息** | 空集 | `morality.view` | `morality.view` + `morality.edit` |

**预置权限组授予（`app/__init__.py` 种子 + `scripts/add_morality_perm.py` 存量补丁）：**
管理员组 view+edit；年级长组 view+edit（可登记/管理本年级奖惩）；班主任组**仅 view**（登记/处理由德育处统一口径）。

**数据范围（三层判定，与成绩模块 `grades.services.scope` 同口径）：**
1. 用户级：`UserDataScope` 授权年级清单 → `user_grades` 模式，按记录的年级快照过滤
2. 组级：`scope_type`（school=全校 / grade=本年级 / class=所辖班白名单）
3. 无任何范围 → **空集**（不回落全校）

**适用范围：** 该范围口径**两个子系统通用**——积分走 `points/routes.py::_scope()`，
奖惩走 `morality/services/reward_service.py::scope_of()/apply_scope()/can_see()`。
奖惩的详情与附件入口逐个记录过 `can_see`（`_or_404`），越权按 404 处理。
**典型身份：** 学生发展中心（仅积分写入 + 学生只读）；德育处（奖惩登记与状态流转）。

## 4. 核心流程与页面

### 4.1 积分 `/points`（单页应用）

筛选（年级/班级/类别/搜索）→ 列表展示（分页）→ 统计汇总（按学生/班级/类别）→ 录入/编辑弹窗（实时搜索选择学生）。
辅助页面：`/points/import`（两阶段批量导入：上传→确认）、`/points/export`（Excel）、`/points/rules`（规则模板 CRUD + 启停）。

### 4.2 奖惩 `/morality/rewards`（列表 + 模态框）

1. **列表页**：概览统计卡（总数/奖励/惩罚/待确认/已生效）+ 筛选（类型/类别/级别/状态/年级/班级/日期区间/关键字学号姓名事由）+ 分页（每页 30）+ 年级下拉（无可见年级时为空，不回退全校）
2. **登记**（`morality.edit`）：模态框表单，按 kind 动态切换类别/级别选项，可同时带附件（多文件）
3. **状态流转**（`morality.edit`）：待确认 → 已生效 / 撤销（撤销需填原因）
4. **详情**（`morality.view`）：JSON 详情 + 附件列表 + 附件上传/删除（`morality.edit`）
5. **附件预览/下载**（`morality.view`）：图片与 PDF 内联打开，其余强制下载；单文件 ≤10MB，白名单 12 种扩展名（pdf/doc/docx/xls/xlsx/txt/jpg/jpeg/png/gif/bmp/webp），经 `upload_guard` 扩展名 + 危险类型 + magic 字节三重校验

**审计：** 登记/修改/删除/状态流转/上传附件/删除附件均写 `operation_logs`（`module='morality'`）；
另有 `app/utils/audit.py::record_request_audit` 对所有写请求兜底落库（已埋点请求去重）。

## 5. 与其他模块的数据交互

- **读入：** `system.db / students`（学号、姓名、班级、年级快照）、`UserClassLink`（班主任班级范围）
- **对外提供（只读）：** 学生画像 `portrait_aggregation` 按学号汇聚积分总和（`behavior_score` 与出勤率估算均取自积分）
- **依赖：** 成绩模块 `grades.services.scope`（可见范围口径复用，单向依赖，未构成循环）
- **与积分的关系：** 同菜单、同权限组命名空间，但**两库之间无 join / 外键 / 代码互调**

## 6. 故障隔离自检

| 场景 | 影响面 |
|------|--------|
| `points.db` 损坏 | 积分页报错；奖惩与其他模块不受影响（逐库建表容错） |
| `morality.db` 损坏 | 奖惩页报错；积分与其他模块不受影响 |
| 附件目录损坏/丢失 | 列表与登记正常，仅附件预览下载不可用（`attachment_path` 返回 None 走降级） |
| 写入范围 | 积分仅 `points.db`；奖惩写 `morality.db` + `app/static/uploads/morality/`，无跨模块写入 |
