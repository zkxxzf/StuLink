# 教务管理设计手册

> 版本：v1.19.49.37（2026-10-13）｜状态：**核心流程已实现**
> 所属模块：`academic`（独立库：`academic.db` 师资基础 / `timetable.db` 课表与值班 / `inspection.db` 查课 / `achievement.db` 业绩 / `forms.db` 问卷收集 —— 2026-10-10 按「一个功能一个库」拆分）｜页面前缀：`/academic`
> 文档体系：`设计文档.md`（总手册）→ 本手册（模块手册）

## 1. 模块定位与边界

**做什么：**
- 教师名单（基础数据）：Excel 导入、随机唯一编号、身份证加密可后补、账号自动匹配/建号
- 查课统计：巡课记录录入与按年级/教师统计
- 教师业绩库：证书/课题/论文/荣誉/培训记录的录入与审核（教师工作台提交 → 教务审核）
- 学期课表（v1.16.0 起）：学期档案 / 节次与作息配置（一页，含 A4 打印；**节次数量不限**，
  常规时长 **早读 40 / 正课 45 / 晚自习 50 分钟**，可存为「全局作息模板」供各学期复用） /
  班级·年级·教师·全校总课表 /
  整班原样导入（按班级 + 周次批量） / 调课申请与执行 / 历史课表（归档回看） /
  变更历史（版本快照） / 打印（2026-10-10 起原「大课表」页下线，并入「全校总课表」）
- 表单与填报汇总（v1.16.0 起，`/academic/forms`）
- 为教师评分与教师工作台提供基础数据支撑（规划）
- 权限子功能（v1.19.49.37）：`academic.view` / `academic.edit` / `academic.timetable` / `academic.swap` /
  `academic.swap_bulk`（统一调课）/ `academic.swap_approve`（调课审批一级）/
  `academic.inspection_export`（查课导出）/ `academic.forms_view` + `academic.forms`（问卷收集）

**不做什么：** 不直接管理登录账号的密码/权限（账号体系归系统管理）；不做自动排课算法
（只做手工排课 + Excel 导入 + 调课流程）。

## 2. 数据库设计（2026-10-10 分库：academic / timetable / inspection / achievement / forms）

| 库 / 表 | 说明 |
|----|------|
| `academic.db` / `teachers` | 教师名单（`teacher_uid` 随机唯一编号、姓名、身份证密文 id_card_enc（唯一可空）、手机号、学科、状态、user_id 快照） |
| `academic.db` / `subject_leaders`、`work_records`、`attendance_records` | 学科组长登记（备课组长 / 教研组长）/ 班主任工作记录（班会/家访/谈话）/ 考勤导入记录 |
| `academic.db` / `subject_leader_plans` | 学科组长**方案**（2026-10-14）：每个「学年 × 学期」一条，记录方案名 / 说明 / 是否当前学期（`is_current`，至多一个）。组长数据本身仍在 `subject_leaders`；课表徽章按课表自己的学年学期回查，**不受"当前方案"影响** |
| `grades.db` / `teacher_link_plans`、`teacher_link_plan_rows` | 任课映射**方案**（2026-10-14）：方案元信息（名称 / 学年学期 / 说明 / `is_current`）+ 明细快照（方案 × 年级 × 班级 × 科目 → 教师账号）。主表 `teacher_subject_links` 仍是"当前生效映射"的唯一运行真值，切换方案＝把快照**物化**回主表 |
| `data/timetable.db`（独立库） | **学期课表（唯一课表体系）**：`term_schedules`（学期/起止日期/教学周）、`period_defs`（节次/作息，**数量不限**，可存为全局模板复用）、`schedule_entries`（条目，含周次范围与软删除）、`schedule_swaps`（调课）、`schedule_versions`（版本快照）、`night_duties`（晚自习值班） |
| `inspection.db` / `inspection_records` | 查课记录（日期、**年级**、节次、教师、班级、科目、结果、检查人、备注） |
| `achievement.db` / `teacher_achievements`、`achievement_attachments` | 教师业绩（类别、名称、级别、取得时间、颁发单位、状态：待审核/已通过/已驳回、提交人/审核人）+ 附件材料 |
| `forms.db` / `form_templates` 等 6 张 | 问卷收集：模板 / 收集轮次 / 题目 / 提交 / 答案 / 分类 |

**分库说明（2026-10-10）：** 原 `academic.db` 一库混装四件事，现按「一个功能一个库」拆为 师资基础 / 查课 / 业绩 / 问卷 四库（课表与值班原已在 `timetable.db`）。跨库只按逻辑键（user_id / teacher_uid / 学号）关联、不建跨库外键；问卷提交与答案（未来最大的两张表）独立成库并补齐索引；迁移脚本 `scripts/migrate_split_academic_20261010.py`（幂等、自动备份、逐表行数校验）。

**快照关联：** `user_id` → `system.db / users`（教师账号关联）；`teacher_uid` 为教务侧主标识。

## 3. 权限与数据范围

**权限边界（permission_map.py）：** 查看（`academic.view`：名单/查课/课表查看）/ 录入管理（`academic.edit`：教师名单、查课、业绩和表单管理）/ 课表管理（`academic.timetable`：学期排课、审批与执行）/ 调课申请（`academic.swap`）。
**字段级（2026-10-13）：** `academic.view_teacher_phone`（standalone）——教师手机号明文查看。
无此权限时，教师名单 / 教师课表查询 / 教师编辑页 / 教师名单导出统一显示脱敏值（`138****5678`，
唯一入口 `app/utils/sensitive.py` 的 `field_value`）；编辑页无权限时手机号只读 + `hidden` 保留原值。
详见《系统管理设计手册》§3.1。
**数据范围：** 查课、实时/新版课表复用成绩模块的 `visible_grades()`，并按可见班级进一步过滤；用户级年级/班级授权和权限组中的班主任、任课教师映射保持一致。教师名单与业绩仍是全校基础数据。调课申请还须匹配申请人的任课课程或负责班级。

**教师-学科关系的唯一依据（2026-10-10）：** 以「任课教师映射」（`TeacherSubjectLink`，页面 `/academic/teacher-links` 与 `/grades/teachers`，权限 key `grades.teachers`）为准（**2026-10-15 扩容**：映射的科目列 = 9 个文化科 + 综合组六科 —— 体育 / 音乐 / 美术 / 信息技术 / 通用技术 / 心理，页面上以一条「综合组」分组带归类；批量导入模板同步加这 6 列（含「信息」→信息技术、「心理健康」→心理 等写法归一），课表导入的任课核对也一并纳入这 6 科；**成绩链路仍只认 9 科**，见 `LINK_SUBJECTS` 与 `SUBJECTS` 的分工）；原「任课安排」表 `/academic/duty`（按课表实时聚合，含 `/academic/duty/export` 与 `/academic/api/duty`）已整功能下线、旧地址 404，不再参考或依赖。**学科组长（2026-10-14 定口径，页面 `/academic/leaders`）：** 一页三类 ——

- **备课组长**：年级 × 学科（高一 / 高二 / 高三 每学科各一名），**年级必填**；
- **教研组长**：只按学科、**不分年级**（年级留空＝全校）；
- **综合组组长**（用户口径，同日二次修订）：**整个综合组只设 1 名** —— 体育 / 音乐 / 美术 /
  信息技术 / 通用技术 / 心理 六科**合用一位**，不分年级、不分学科；落库为
  `subject_leaders` 里 `subject='综合组'` / `grade=''` / `category='综合组组长'` 的一条记录，
  矩阵里综合组**只渲染一行一格**（键 `综合组|综合组`，候选取六科教师并集），
  导出年级列写「不分年级」，课表徽章在六科的课表上标「综合组组长」；
- 三类组长都**必须是本学科教师**（任课映射 `TeacherSubjectLink` 为唯一依据、课表兜底、
  教师档案学科最后兜底；都没有任课数据时放行但提示补建教师名单）；综合组的候选＝六科并集；
- **页面只有一张矩阵表**（与「任课教师映射」同形）：行＝学科（9 个文化科，外加综合组一行，
  共 10 行，文化科目与综合组之间有一条分组带），列＝高一 / 高二 / 高三 / 教研组（不分年级），
  格内下拉**只列本学科教师**（该学科在任课数据里查不到教师时退化为「全部教师」并标注），
  右上「保存全部」按改动过的格子批量提交（`POST /academic/leaders/matrix/save`，
  只提交 diff，未动过的格子不受影响；清空格子＝删除该条登记）；
  任课数据缺失时该列/行也照常可选，不会把学科卡死。
- **已下线（2026-10-14）**：原「职责 / 组范围」明细页签、新增/编辑弹窗、单条保存与删除接口
  （`/academic/leaders/save`、`/academic/leaders/delete`、`/academic/leaders/candidates` 与
  `subject_leaders` 的 `members` / `duty` / `sort_order` 三列）**整功能删除**、旧地址 404 ——
  用户确认从未使用（"我都没听说过"），页面只保留「谁当组长」的矩阵维护；
  迁移脚本 `scripts/migrate_subject_leader_category_20261014.py` 重建表时同步删列。

晚自习值班（`/academic/schedule/<sid>/night-duty`）不受影响。
**典型身份：** 教务员（成绩/教务写入 + 学生/积分只读，按勾选年级如"仅 2025 级"）；教务主任（全校写入）。

## 4. 核心流程与页面

- **教务工作台** `/academic/`（首页；2026-10-12 用户口径改为**六项实时数据**，取代原静态/占位 KPI）：
  - KPI 六项：**①今日查课 / 本月累计查课**（附**今日查课覆盖率**）· **②今日迟到 / 本月迟到人次** · **③今日缺勤 / 本月缺勤人次**
    · **④待审批调课申请**（按批次折叠，与调课列表、待审徽章同一口径）· **⑤教师业绩待审核** · **⑥材料回收**（回收率 / 待回收份数 / 进行中收集数）
  - **口径**：查课/迟到/缺勤记录经 `apply_academic_scope` 按用户数据范围过滤（与查课页一致）；
    **覆盖率 = 今日已查 ÷ 今日应查**，分母 `_today_expected_cells()` ＝ 启用学期**当天周课表格子数**（全校口径），与查课页 `coverage` 完全一致；当天无课时显示「—」而非 0%。
  - **材料回收** = 对**所有 `status='open'` 的收集**汇总应交/已交（驳回待重交**不算**已交），复用 `form_summary_service.get_submission_stats`；
    **需 `academic.edit`**，无权限者显示「—」；统计异常只记日志、降级渲染（不拖垮工作台）。
  - 待办三项均带一键跳转；下方为「教务主流程」三块（课表 / 查课 / 调课）+ 最近动态（审计日志，按权限过滤）。
- **教师三页合一（2026-10-14，用户要求）**：教务侧「教师名单」`/academic/teachers`、「任课教师映射」
  `/academic/teacher-links`、「学科组长」`/academic/leaders` 合成**一个入口** —— 侧栏只有「教师」一项，
  进来后页内顶部 tab 互切（共用部件 `app/templates/academic/_staff_tabs.html`；三个 URL 仍各自独立，
  可收藏 / 分享 / 后退，与调课两页、课表查询三项同款交互）。成绩管理侧 `/grades/teachers` 是同源
  另一入口，不显示该 tab、保留返回按钮；「任课教师映射」tab 需 `grades.teachers` 权限。
  **教师名单还有第二处入口（2026-10-14）**：系统管理「教师管理 → 教师名单」`/users/teachers`
  ——同一批视图函数与同一份数据（页内链接按蓝图自适应，`_ep()`），权限仍是 `academic.view`。
  教务主任 / 教务员 / 校长 / 副校长 / 备课组长 / 教研组长都只有 `academic.view`、没有 `system.users`，
  所以**教务侧入口必须保留**（不能只挂系统管理）；系统管理侧见《系统管理设计手册》§4。
- **方案 · 历史记录（2026-10-14，用户要求"每学期会变、要有记录、可新增方案"）**：任课教师映射与
  学科组长两个页面右上角各加「历史记录」按钮，弹窗即方案中心 —— **新建方案**（起点可选"复制当前 /
  空白 / 复制某历史方案"，可勾"创建后立即使用"）、**使用**（切换到该方案）、**编辑**（改名 / 说明）、
  **删除**；共用部件 `app/templates/_plan_manager.html`（Jinja 宏 + 内联脚本，调用方**必须放在
  `extra_js` 块** —— 放在 content 里会在 jQuery 之前执行，弹窗按钮点了没反应）。
  - **任课映射**：方案是 `TeacherSubjectLink` 的**留档**，主表列与语义不动（成绩 / 教务 / 考务 /
    工作台 / MCP 等读取点零改动）；当前方案（`is_current`，全局至多一个）的快照与主表保持一致 ——
    保存矩阵 / 导入确认后自动刷新，页面进入时若发现不一致（如运维脚本直接改了主表）以主表为准自愈；
    「使用」＝先把主表现状回写当前方案快照（防丢），再把目标方案的快照**物化**回主表
    （新增 / 恢复 / 改派 / 失效），最后翻转 `is_current`。**当前方案不可删除**。
  - **学科组长**：方案就是「学年 × 学期」（与 `subject_leaders` 唯一键同坐标，一个学期只能一套），
    页面顶部下拉即方案切换器；「使用」＝设为当前学期方案并跳转到该学期。**删除方案会连同该学期的
    组长登记一起删**（弹窗二次确认）；课表徽标不受影响（按课表自己的学年学期回查）。
  - 落库：`grades.db` 的 `teacher_link_plans` / `teacher_link_plan_rows`、`academic.db` 的
    `subject_leader_plans`；迁移脚本 `scripts/migrate_link_plans_20261014.py`、
    `scripts/migrate_subject_leader_plans_20261014.py`（均幂等，登记在《数据库迁移清单》A2 / A3）。
- **教师名单** `/academic/teachers`：下载模板 → 上传解析（匹配优先级：身份证 > 手机号 > 姓名）→ 预览确认（新增/更新/冲突/建号计划）→ 落库 + 初始密码清单（CSV）；支持搜索、编辑（身份证仅管理入口可更新）
- **查课** `/academic/inspection`：录入（日期/年级/节次/教师/班级/结果）→ 列表筛选 → 月度统计（次数/异常/按教师）；`/academic/inspection/live-schedule` 按日期和节次核对实时课表，并叠加当天已执行的临时调课。
- **单节课表视图**（2026-10-13 新增，在实时查课页内切换，`?view=period`，**不新增路由/入口**）：把某一节课按年级分块铺开成"班级卡片墙"（班名 / 学科 / 任课教师，临时调课调入带「临调」角标、无课显示空档），班级数量按课表数据动态派生（**不写死每年级班数**，12 / 20 个班等规模自适应）；顶部统计年级 / 班级 / 有课 / 空档。有 `academic.timetable` 或 `academic.swap_approve` 的账号可点卡片**就地发起代课 / 调课**：只选教师＝代课（`exchange_kind='cover'`，时间班级都不动），再选这位教师的某一节课＝调课（`exchange_kind='exchange'`，**只换上课时间**，2026-10-14 起不再换班）；落库以**原任课教师**为申请人，复用 `swap_service.apply_exchange_batch`，与 `/swap/cover`、`/swap/apply` 同一条「对方确认 → 审批 → 执行」链路，冲突原因原样回显在弹窗。视图本身由服务端渲染（切换节次走整页刷新，与日期 / 年级一致）；唯一的写入接口是
`POST /academic/inspection/quick-swap`（数据装配用 `_period_overview_data`）。
- **单节查课 UI 口径（2026-10-16 优化，巡课视角）**：
  - **卡片即状态**：卡片底色与左侧 4px 色条＝查课结果 —— 未查＝琥珀（最醒目，巡课要找的就是它）、
    正常＝白底绿条（最安静）、迟到＝黄、缺勤＝红、调课＝紫、考试＝蓝（全部走 `--sl-soft-*`
    变量，深色主题自动适配）；标记后卡片状态色跟着变（不只换徽标文字）；
  - **学科色点**：学科名前的小色点复用课表网格的 `subject_tone`（与矩阵同一套配色语言）；
  - **「换人」默认淡出**：hover / focus / 触屏才显形（原来 30 张卡 30 个按钮常驻，抢"标记查课"
    这个主操作的视觉）；「换人」上右键不再弹查课菜单；
  - **工具栏一条成组**：视图｜节次｜日期·年级·今天｜批量+图例，组间竖分隔线；节次下拉标注
    「N 课 / 空」（缺省节次不再落到无课的节次——夜里打开不再整页空档）；图例直接复用徽标类
    （不再手抄色值），长句操作说明收进 ⓘ 的 title（用户口径「细则进悬浮提示」）；
  - **交互修复**：① 连点两张不同卡片不再"丢 A / 误标 B 迟到"（双击判定 timer 改挂在元素上，
    只有同一张卡的第二击才算双击）；② 改日期 / 点「今天」保留单节视图与节次（原先会静默跳回
    全天矩阵）；③ 只读账号的覆盖率不再被 JS 清成 0/0/0%；④ 标记即时 pending 反馈、单击/双击
    不再每次弹 toast；⑤ 触屏长按卡片＝右键菜单（原来触屏无法标缺勤/调课/考试）、菜单贴边收敛；

## 5. 与其他模块的数据交互

- **读入：** `system.db / users`（账号匹配：手机号 == username 优先，姓名唯一匹配；`UserDataScope` 数据范围）
- **复用成绩模块服务：** `grades/services/user_account.py`（拼音建号 + 随机密码）——教务导入自动开户共用
- **对外提供：** 教师工作台（我的信息/我的业绩/我的课表，`teachers.user_id` 关联）；成绩模块任课映射经 user_id 自动打通（名单页显示映射数）

## 6. 故障隔离自检

| 场景 | 影响面 |
|------|--------|
| `academic.db` / `inspection.db` / `achievement.db` / `forms.db` / `timetable.db` 任一损坏 | 仅对应功能报错（教师名单 / 查课 / 业绩 / 问卷 / 课表与值班），其余教务功能与其它模块不受影响；教师工作台显示"未关联"提示 |
| 写入范围 | 各功能写各自的库（师资基础 / 查课 / 业绩 / 问卷 / 课表）；建号时写 `system.db`（经用户服务，失败仅该行跳过） |
| 依赖 grades 服务 | 代码级依赖 user_account（若成绩模块代码异常，教务导入受影响；只读使用不涉及数据耦合） |
