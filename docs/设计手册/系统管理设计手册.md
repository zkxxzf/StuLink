# 系统管理设计手册

> 版本：v1.19.49.40（2026-10-13）｜状态：**可用（项目根基）**
> 所属模块：`system`（**根基库 `system.db`**）｜页面前缀：`/students`、`/users`、`/dictionary`、`/class-profile`、`/perm-groups`、`/grade-mgmt`、`/settings`、`/operation-logs`
> 文档体系：`设计文档.md`（总手册）→ 本手册（模块手册）

## 1. 模块定位与边界

**做什么（项目基础 · 底层数据 · 完全可用且可扩展）：**
- 学生管理（基础信息：学号/姓名/班级/选科/身份证等——全系统的学生数据唯一来源）
- 教师管理（登录账号、角色、权限组归属；2026-10-14 起页内两个子页：教师名单 / 教师权限管理）
- 字典管理（年级/科目/考试类型/分数段等所有下拉数据源）
- 班型设置（班级 → 年级/班型/班主任映射）、年级管理、学校设置
- 权限管理（二维权限：身份 × 子功能 × 三档 + 用户数据范围）
- 操作日志（全站审计）
- 通知中心（`notifications` 三表，独立蓝图 `/notifications`，权限挂 workbench 命名空间）

**不做什么：** 不承载任何业务数据（住宿/成绩/积分/教务数据均在各自模块库）。

## 2. 数据库设计（system.db，15 张表）

| 分组 | 表 |
|------|----|
| 人员 | `users`（账号/角色/权限组/状态）、`students`（学生基础信息） |
| 组织 | `class_profiles` / `class_subjects`（班型）、`grade_settings`（年级管理）、`user_class_links`（用户-班级关联） |
| 配置 | `dict_categories` / `dict_items`（字典）、`system_settings`（学校名称等） |
| 权限 | `permission_groups`（身份：menu_keys JSON + scope_type + role）、`user_data_scopes`（用户 × 年级/班级，v1.9.2） |
| 审计 | `operation_logs`（含 HTTP 审计字段：`endpoint`、`method`、`status_code`、`request_id`、`severity`） |
| 通知 | `notifications`、`notification_reads`、`notification_recipients`（v1.19.49.40，通知中心；蓝图独立但数据落本库） |

**根基地位：** 所有模块的身份、权限、学生快照均源于本库；**所有业务模块只读本库，不反向写入**（例外：用户服务代建的账号，经统一服务写入）。

**审计双轨：** ① 业务埋点 `log_operation`（记 user/action/target/detail/module）；
② `app/utils/audit.py::record_request_audit` 请求级兜底网——**所有写请求**（POST/PUT/PATCH/DELETE）统一落 `operation_logs`
（记 endpoint/method/path/status_code/request_id/severity，已埋点请求经 `g._audit_logged` 去重；**不记录请求体**，防密码/身份证泄露）。

## 3. 权限与数据范围

> 全项目权限模型、权限点全清单、预置身份矩阵与数据范围口径见
> [权限体系说明.md](../规范与说明/权限体系说明.md)；本节只讲系统管理模块自身的子功能与防误操作保护。

**子功能三档（permission_map.py · system 组）：** 教师管理（`system.users`）/ 基础配置（`system.dictionary`+`system.class_profile`+`system.grade_mgmt`）/ 权限管理（`system.perm_groups`）/ 系统设置（`system.settings`）——均只有"不可见/写入"两档（无只读场景）。
**防误操作保护：**
- 管理员组（身份）：**系统保留**——不可改名/改权限/删除（前端锁定 + 后端拦截）
- 管理员账号：不可禁用、角色不可修改（防止系统失去管理入口）；系统无删除用户入口
- 用户不能禁用当前登录账号

### 3.1 敏感字段「字段级」权限（v1.19.49.40，2026-10-13）

**背景：** 学生身份证号 / 联系电话此前只有**导出**维度有权限点（`students.export_id_card` /
`students.export_phone`），**页面展示**维度完全没有控制 —— 只要拿到 `students.view`，
学生详情页的身份证号、学生列表 / 宿舍床位卡的联系电话就是明文。

**新增三个「查看」级权限点**（`permission_map.py` 中 `standalone=True`，不随模块「写入」批发，
只能单独勾选，默认不可见）：

| 权限点 | 归属子功能 | 作用 |
|--------|-----------|------|
| `students.view_id_card` | 学生管理 → 查看身份证号 | 有则明文，无则 `110***********1234` |
| `students.view_phone` | 学生管理 → 查看联系电话 | 有则明文，无则 `138****5678` |
| `academic.view_teacher_phone` | 教务管理 → 教师手机号明文 | 同上（教师名单/课表/编辑页/导出） |

**实现口径（唯一入口 `app/utils/sensitive.py`）：**
- 模板用 Jinja 全局 `field_value(value, 'id_card'|'phone'|'teacher_phone')` 取值，
  **后端决定明文/脱敏**（不是前端隐藏）——无权限时即使直接调接口也只拿得到脱敏值；
- 覆盖展示点：学生列表 / 详情 / 编辑 / 查询、宿舍床位卡与住宿查询、历史与校友归档页、
  教师名单 / 课表查询 / 教师编辑页；
- **编辑页保护**：无查看权时手机号渲染为只读脱敏值 + `hidden` 保留原值（否则保存会清空号码）；
- **导出需「查看 + 导出」双权限**（`export_helpers.py` 的 `view_perm`）：看不到明文就不允许导出明文；
  导出弹窗勾选框同样按双权限置灰。

**预置授予（用户口径 2026-10-13：默认只有管理员与班主任可看学生身份证号 / 联系电话）：**

| 权限点 | 管理员组 | 班主任组（本班） | 其他身份 |
|--------|:---:|:---:|:---:|
| `students.view_id_card`（身份证明文） | ✔ | ✔ | ✘ 脱敏 |
| `students.view_phone`（联系电话明文） | ✔ | ✔ | ✘ 脱敏 |
| `academic.view_teacher_phone`（教师手机号明文） | ✔ | ✘ | ✘ |

> 宿管组原先给过 `students.view_phone`，已按该口径**收回**（宿舍侧学生敏感字段一律脱敏）。
> 存量库补丁：`scripts/migrate_sensitive_perm_v2_20261013.py`（幂等，改库前自动备份）。

**同批最小权限重排（越权项收掉）：**
- 年级长组：移除 `students.import`、`students.export_id_card`、`students.export_phone`
- 班主任组：移除 `students.import`、`students.transfer`、`students.export_id_card`、
  `students.export_phone`、`students.export_graduation_school`、`students.export_enrollment`
- 学生列表的「批量导入 / 批量调班 / 导出 / 编辑 / 调班」按钮同步改为**按权限点显示**
  （原按角色 → 收权后会出现"看得见按钮、点了 403"）

## 4. 核心流程与页面

- 学生管理：列表（分组/搜索/导出，敏感导出独立权限）、增删改、批量导入（模板）、调班、毕业归档（写 history.db）
  - **宿舍信息只读列**（v1.19.47.4）：列表展示「住校/走读、出门权限、宿舍、床位」四列，
    数据来自 `dormitory.db`（`student_accommodation` / `bed_assignments` + `rooms`），
    **本模块不提供任何修改入口**（无编辑控件、无批量改宿舍字段），并明确提示这几列归宿舍管理模块维护。
    导出（`/students/export`）支持勾选这四列，无额外权限门槛（能看学生列表即可导）。
- 教师管理 `/users/`（2026-10-14 拆成两个子页，页内 tab 互切：教师名单 / 教师权限管理）：
  - **教师权限管理** `/users/`：列表（按权限组分组折叠 + 搜索）、新建/编辑（角色 + 权限组）、批量导入、禁用/启用、重置密码；
  - **教师名单** `/users/teachers`（2026-10-14 新增）：教务基础档案（教师编号 / 姓名 / 学科 / 手机号 /
    身份证 / 登录账号 / 任课映射），支持 Excel 导入、编辑、导出；**与教务管理 `/academic/teachers`
    是同一批视图函数与同一份数据**（`academic.db.teachers`，权限 key 仍是 `academic.view`），
    路由用 `add_url_rule` 挂全链路（页面 / 导出 / 模板 / 导入 / 编辑）、页内链接与重定向按蓝图自适应
    （`users.*` ↔ `academic.*`，见 `app/modules/academic/routes/teachers.py::_ep()`）。
    **两边都保留入口是有意为之**：教务主任 / 教务员 / 校长 / 副校长 / 备课组长 / 教研组长都有
    `academic.view` 但**没有 `system.users`**，只留系统管理一侧会让他们看不到教师名单。
    tab 栏：系统管理侧 `app/templates/system/_user_tabs.html`（需 `academic.view` 才显示教师名单项）。
- 权限管理 `/perm-groups/`：表格一（身份 × 子功能 × 三档，点击切换徽章、表头/首列双向悬挂）+ 表格二（用户 × 年级数据范围）+ 身份增删改
- 字典/班型/年级/学校设置：下拉数据源与组织结构的维护入口
- 操作日志 `/operation-logs`（`system.users` 门槛，无独立日志权限点）：六维筛选（动作/模块/目标类型/用户/时间起止/关键字），
  module/action/target_type 下拉为**动态 distinct**（原硬编码 4 值导致 academic/workbench/portrait 日志筛不出）；detail 支持 JSON 展开
- 通知中心 `/notifications`：列表、创建、已读/未读、删除、未读数、详情、已读进度、用户搜索、分类（13 条路由；
  权限 `workbench.notifications_view` / `workbench.notifications`，`system.settings` 亦可）

## 5. 与其他模块的数据交互

| 方向 | 内容 |
|------|------|
| 对外提供（只读） | 所有模块：学生快照（学号）、账号与权限（user_id / permission_groups）、字典数据 |
| 接受写入 | 经统一服务：建号（教师导入/教务导入共用 `user_account`）、学生毕业归档（→history.db） |
| 依赖 | **零业务模块依赖**（不 import 任何 grades/points/academic/dormitory 模型或服务） |

## 6. 故障隔离自检（根基保障）

| 场景 | 影响面 |
|------|--------|
| system.db 自身损坏 | 全局不可用（根基）——启动时 system 库最先建表，失败会有明确告警 |
| **任何业务模块库损坏** | **系统管理不受影响**（逐库建表容错 + 零业务依赖）；登录与基础数据始终可用 |
| 权限/身份配置错误 | 页面提供即改即生效 + 管理员组防误操作保护兜底 |
