# 宿舍管理设计手册

> 版本：v1.19.59.64（2026-10-13）｜状态：**可用**
> 所属模块：`dormitory`（独立库 `dormitory.db`）｜页面前缀：`/dashboard`、`/rooms`、`/assignments`、`/statistics`
> 文档体系：`设计文档.md`（总手册）→ 本手册（模块手册）→ `宿舍分配算法手册.md`（算法手册）

## 1. 模块定位与边界

**做什么：** 宿舍房间管理、床位分配（自动分配算法 v8）、合班管理、床位可视化、统计报表。
**不做什么：** 不修改学生基础信息（只读快照）；住宿相关数据全部独立存于 `dormitory.db`。

## 2. 数据库设计（dormitory.db，3 张表）

| 表 | 说明 |
|----|------|
| `rooms` | 房间信息（楼栋、楼层、房号、容量、性别）；分配字段：`grade`（年级）、`class_name`（**完整合班名**，多个班用 `+` 拼接如"07班+08班"，**不分主次**；非合班为单一班名）、`combined_class`（合班标识）、`combined_details`（合班各班份额 JSON 如 `[{"class_name":"07班","count":4}]`） |
| `bed_assignments` | 床位分配记录（房间 × 床位 × 学生） |
| `student_accommodation` | 学生住宿信息（学号快照、住/走读类型、教材、教师备注） |

**快照关联：** 学号 → `system.db / students`（不建跨库外键）。
**历史库：** 分配变更流水在 `history.db / assignment_history`（跨模块共享，与往届查询系统共读）——
`assignments.py` 的 11 个调用点（clear/assign/unassign/move/swap/auto_assign）逐操作写入。

## 3. 权限与数据范围

**子功能四档（permission_map.py）：** 查看统计（`dormitory.view`+`statistics.view`）/ 房间管理（`dormitory.manage`+`dormitory.import`）/ 宿舍分配（`dormitory.assign`）/ 床位分配（`dormitory.beds`）。

**四档实际把关范围（2026-10-13 接线修正）：**

| 权限点 | 把关的路由 |
|--------|-----------|
| `dormitory.manage` | 房间 CRUD：`/<id>/edit`、`/create`、`/<id>/delete`、`/batch-setting`（批量设置性别/容量）、`/batch-add-rooms`（批量加房） |
| `dormitory.assign` | **把班级配到房间**：`/assign-visual`（拖拽分配页）、`/assign-data`、`/assign-room`、`/unassign-room`、`/set-combined`（合班）、`/save-assignments`、`/update-room-assignment`、`/assign-auto`（含 `/stats` `/preview` `/execute` `/room-stats`，自动分配算法 v8）、`/available-rooms-data`、`/swap-data` + `/swap`（宿舍互换） |
| `dormitory.beds` | **把学生配到床位**：`assignments.py` 全部 8 条（`/manage`、clear-class/assign/unassign/move/swap、`/auto-assign`、`/auto-assign-all`） |
| `dormitory.view` | 只读：宿舍列表/详情/班级床位需求/报表与导出、住宿查询 |

> 2026-10-13 已修复：`dormitory.assign` 此前是**死权限点**（自动分配、拖拽分配、合班、宿舍互换等
> 分配类路由全部误用 `dormitory.manage` 把关，授权与否不影响任何页面）。现分配类路由统一改用
> `dormitory.assign`，四档语义落地——「班主任可床位分配、不可宿舍分配」这类组合现在真实可用。
> 同步调整前端：侧栏「分配宿舍」入口与宿舍列表「宿舍互换」按钮改为按 `dormitory.assign` 显示
> （原按 `dormitory.view` / 角色，会出现"看得见入口、点了 403"）。
> 因 `dormitory.assign` 现在可单独授予年级/班级范围账号，`/swap-data` 与 `/swap` 补了
> `room_scope_query` 范围过滤（互换的两个房间都必须落在可见范围内）。

**数据范围：** 组级 `scope_type` + 用户级 `UserDataScope`（v1.19.5.0，2026-10-11 起接入）——
统一口径在 `app/utils/dormitory_scope.py`（admin→school；有 UserDataScope→限定授权年级；否则回落组级 school/grade/class；其他→none 空集），
`rooms.py`、`assignments.py`、`statistics.py` 均已接入（`room_scope_query` / `class_in_scope` / `student_in_dorm_scope` / `resolve_scope`）。
> 2026-10-13 已修复：`statistics.py` 原先自带 `_get_scope()`（只判 role 与组级 scope_type、**不读 UserDataScope**），
> 且 `scope_type='none'` 时 `index()` 走 else「全校」分支（**fail-open**）——非全校账号会看到全校班级统计、房间明细与宿舍容量汇总。
> 现统一走 `resolve_scope()`（含用户级范围 + fail-closed 403），`_dorm_stats()` 亦按范围过滤。

## 4. 核心流程与页面

四个蓝图、约 47 条路由（`app/modules/dormitory/routes/`）：

- **宿舍总览 `/dashboard`**（`dashboard.py`，7 条）：学生住宿查询（搜索/导出/批量改住宿类型/导入模板与导入）、入住情况图表与容量统计
- **房间管理 `/rooms`**（`rooms.py`，25 条）：房间 CRUD、批量导入、批量设置/批量加房、**拖拽可视化分配**（`/assign-visual`，原生 HTML5 Drag and Drop + `/assign-data` 一次性取数）、**自动分配**（`/assign-auto/stats|preview|execute`）、房间对调（`/swap-data` `/swap`）、铺位图（`/<id>` 纯 Jinja+CSS，每两床号凑一组上下铺）
- **床位分配 `/assignments`**（`assignments.py`，8 条，全部 `dormitory.beds`）：`/manage` 管理页、clear-class/assign/unassign/move/swap、`/auto-assign`（挂并发写锁 `_bed_write_lock_decorator`）、`/auto-assign-all`
- **统计报表 `/statistics`**（`statistics.py`，7 条）：四页签 school/class/rooms/import（旧 `grade` 值重写为 `class`）、`/history`（分配流水）、`/alumni`（往届住宿）、模板下载、`/export-bed-detail`（8 列 xlsx）、`/import-dormitory`
- **自动分配算法 v8**：严格分级初稿 → 迭代爬山 → 全局评分选优；7 项权重可调；收敛检测（详见《宿舍分配算法手册》）
- **合班管理**：`/rooms/set-combined`，合班份额存 `combined_details`
- **报表导出均为 xlsx**（无 CSV/PDF）：`/statistics/export-bed-detail`（8 列）、`/rooms/report/export`（6 列 + 汇总行，已接范围过滤）、`/dashboard/export`（学生住宿明细）
- `/rooms/report` 为兼容旧链接的 302 空壳，已合并到 `/statistics/?tab=rooms`
- **已知部署风险（待修）：** `/dashboard` 首页图表用 Chart.js 4.4.4 **公网 CDN** 加载（与项目其余部分用本地 echarts 不一致），NAS/内网离线部署会图表空白（有降级提示文案）

## 5. 与其他模块的数据交互

- **读入：** `system.db / students`（学号、姓名、班级、年级、性别快照）
- **对外提供：** `history.db` 的分配流水供往届查询系统（:5001）只读；系统管理学生列表/导出的「住宿四列」只读展示（数据来自本库，归宿舍模块维护）
- 无代码级依赖其他业务模块。

## 6. 故障隔离自检

| 场景 | 影响面 |
|------|--------|
| `dormitory.db` 损坏 | 宿舍相关页面报错；登录/系统管理/成绩/教务不受影响（逐库建表容错） |
| 写入范围 | 仅 `dormitory.db` 与 `history.db`（分配流水），无跨模块事务 |
