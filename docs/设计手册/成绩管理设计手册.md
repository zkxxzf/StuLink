## 1. 模块定位与边界

**做什么：**
- 首页仪表盘（`/grades/`，模块落地页）：考试总次数、各年级考试次数、阶段分布、参与人数、证明条数与当前动态（实时刷新）
- 考试数据管理：考试创建（状态机 draft/imported/dirty）、成绩 Excel 导入（双模板识别、分批覆盖、差异预览）、排名计算（方向内排名）
- 四大分析：年级分析 / 班级分析 / 学科分析 / 任课教师分析（表格 + ECharts 图表）
- 自由透视表：行/列/指标任意组合的交叉表分析
- 划线分层：总分线、单科三线（模板批量应用，比例自动换算为分数线）
- 成绩汇报区：面向校级汇报的五大板块表格 + PPT/HTML 交付物导出
- 考务管理：考场编排（考号规则、选科分组、固定考场）与打印交付（桌签/名单 PDF）
- 个人成绩查询与成绩证明：按权限查询学生成绩、生成带防伪码的证明（公开核验）
- AI 分析（BYOK）：考题分析报告与多轮对话（个人 Key 或全局 Key，数据按权限收敛）

**不做什么：**
- 不修改学生基础信息（学号/姓名/班级等仅作快照引用，写操作只发生在 `grades.db`）
- 不承担教务排课、日常考勤（教务模块职责）
- 成绩证明核验页为公开只读端点（限流 + 脱敏），不做登录要求
- **不做主观评价**：界面不出现对教师/班级/学生的评价性文字，只呈现数值（变动列仅用颜色标注）

**快照关联（跨库无外键）：**
- `student_no`（学号）→ `system.db` 的 `students`：成绩、考务均以学号快照关联，学号不可变
- `user_id` → `system.db` 的 `users`：任课映射与报告归属；被教务模块经 `user_id` 读取（教师任课映射数）
- 换班/转科不影响历史考试统计（"当时在哪个班就以哪个班统计"）；主库改名不追溯历史成绩姓名

> **班级口径（易错点，v1.19.47.3 明确）**：`exam_scores` 里 **总分行** 的 `class_name`
> 是「考试当时的班级」（导入时按 Excel 列写入，是班级统计的唯一依据）；
> **科目行** 的 `class_name` 是「导入那一刻的学生当前班级」。判班级一律用总分行，
> 不要用科目行。

**索引要点：** `exam_scores` 按 (exam_id, subject, class_name)、(exam_id, student_no) 及覆盖索引 (student_no, subject, exam_id)（v1.13.2 性能优化）、`exam_no`（`idx_scores_exam_no`）；`exam_bands` 唯一约束 (exam_id, direction, subject, seq)。

## 4. 核心流程与页面

### 4.1 考试与成绩
1. 创建考试（年级 + 日期 + 类型；同名阻断）→ 2. 下载导入模板（模板 A 全科含总分列 / 模板 B 分科；填表说明）→ 3. 上传解析（**预检不落库**，返回 import_token + 差异预览：新增 X 人/更新 Y 条/缺考删除 K 条/未出现保留 P 人/错误 E 行，可下载错误明细）→ 4. 确认导入（事务写入 + 整场重算排名与进退步）→ 5. 单条修正（改分自动重算该生总分；状态置 dirty）→ 6. 重新计算排名（dirty → imported）

- **进入考试的落点（2026-10-19 用户口径）**：考试列表点行时按有无成绩分流 ——
  尚未导入成绩 → 考务安排（`exam_affair_go`，无批次会自动创建并进步骤① 学生名单）；
  已导入成绩 → 成绩总览（`grades.index?exam=<id>&tab=grade`）。无 `grades.edit`
  的账号（任课教师 / 班主任）仍只进本场成绩分析。

**导入状态机（防误覆盖/并发）：**
```
draft(新建) ──上传+确认──> imported ──单条修正/再次上传──> dirty ──重算/确认──> imported
      └──────────────────< 删除考试（级联）
```
- 模式 A 增量覆盖（日常）：影响范围 = 文件出现的 (学生 × 科目列)；单元格空 = 该科本次缺考（删旧行）；**文件未出现的科目列保留不动**（支持分批补导）；未出现学生默认保留（可勾"一并移除"纠错）
- 模式 B 整场重置（纠错）：清空全场按本次文件重导（输入考试名强确认）
- 上传 16MB 上限，仅内存解析（BytesIO），不落盘；token + 整场事务双重防串批；每次导入写 import_info + OperationLog

**导入解析校验**：表头识别失败/缺学号列 → 整批报错引导模板；年级列不一致 → 行错误（防跨年级混入）；分数越界（非数值/负分/超满分+0.5）→ 行错误；学号未匹配 → 行错误；非应考科目 → 忽略；全行无分 → 提示未参加；**错误行不阻断整批**；借读等学籍状态不剔除仅标注。

### 4.2 划线分层
模板选择（比例制：按参考人数换算分数线；分数制：直接指定，层名可改）→ 应用至考试（按方向/科目独立，考试与模板绑定）→ 分层结果进入各分析与汇报口径。层判定/比例换算/三线口径见[算法手册第 4 章](成绩分析算法手册.md)。

**「先定模板」口径（2026-10-13）**：进入划线页先确定本场用哪个模板，已保存的线按模板层名对号入座——
- 模板推荐优先级：已绑定 → **本场已保存划线的层名（归一化，去尾「线」）匹配** → 按考试适用类型 →
  **兜底内置「默认模板」**（985线/211线/特控线/本科线；不再落到「不套用 + 默认四层」）；
  推荐依据在页头展示（`suggest_reason`：`lines` / `exam_type` / `default`）
- 按划线匹配时的排序键（越小越合适）：**① 模板缺少几条已保存的线 → ② 模板里还有几层没有对应划线值
  → ③ 内置模板优先 → ④ sort_order/id**。命中数相同也不能选"多出空层"的 AI 遗留模板
  （实测某场已保存 211/特控/本科，「默认模板」与遗留的五层模板都命中 3，须选默认模板）
- 已保存划线中不属于当前模板层名的层会**追加为新行**：行底淡琥珀（`--sl-extra-bg`）+ 层名下
  「不在当前模板内」标注 + 顶部黄字列出层名（不再静默混入、也不再和模板层长一个样）
- 模板层带比例定义（ratio）时，层名下方展示「模板定义：比例 x% · 约 N 人」（N=参考人数×比例，估算）
- AI 智能导入分数线表后绑定模板同样用归一化匹配（`_norm_line`），「985/211/特控/本科」直接复用「默认模板」，不再重复新建

**「按组合」列开关与组合格（2026-10-15）**：可组合的列（总分 / 再选四科）表头带小方框，
勾上即按选科组合分行填（`物化地 / 物化政 / 物化生` 各一条，未划线也列出来），不勾＝该科按方向一个标准。
- 页面里「整张表都是输入框」（方向格的 `input` 去边框、由 `td` 画格线），**组合格是格中格**，
  必须一眼看出"能填"：`.q-selrow` 内为「组合名小标签（`.q-sel-name`）+ 输入框（`.q-selcell`）」，
  输入框用 **2px 强调色实线**（`--sl-accent`：浅色深蓝 / 深色浅蓝）+ 面板底
  ——2026-10-15 用户反馈「你这个框不是很明显啊」后从内联 `1px #adb5bd` 改到 theme.css `#bandTable` 区块
  （不再硬编码白底，深色模式不再靠覆盖）。只读用户看到同样的小标签 + 数值文本（无输入框）。
- 切换该开关（组合键 `方向|科目` 与方向键 `组合|科目` 是两套键）：
  - **本列只有一个组合时**（如历史类只有史地政）两套口径**等价** → 直接把值搬过去
    （勾上＝方向值→组合、取消＝组合值→方向），**不弹确认、不清空**，并给一行提示
    （2026-10-15 用户口径「不需要把数据清空」）；
  - **多组合时**（1 条方向线 ↔ N 条组合线无法自动对应）才 `confirm`——文案带组合数与已填组合，

  仍遵循同一原则：**AI 只做识图/判表，结构化落库由确定性代码负责**
  （`looks_like_schedule_sheet` / `parse_schedule_sheet` / `parse_schedule_json`）。
- **防误覆盖**（2026-10-12 新增）：本场已有成绩且选「整场覆盖（模式 B）」时，
  必须输入当前账号密码二次确认，避免一次误点清空整场成绩
- **体积上限**：单文件 5MB、全部文件合计 40MB、草稿落库前 8MB（超限要求分批）；
  解析行数上限 `MAX_SCAN_ROWS=4000`
- 接口：`POST /grades/exams/<id>/ai-import/analyze`（multipart，`ai` 字段带本机配置）、
  `POST /grades/exams/<id>/ai-import/apply`（`dry_run` 预览 / 正式写入）
- **「不参加考试」学生的成绩（2026-10-19 用户口径）**：考务步骤① 标记为「不参加」
  的学生，成绩表里即使有分数，导入时也**默认跳过**。标准导入的确认页与 AI 导入
  卡片都提供「仍然添加」勾选（`include_skip=1`），勾选后才写入；差异预览按默认
  口径（已跳过）计算。实现：`services/import_attend.py`（考务名单 → 学号过滤），

#### 4.9.2 「提示词生成器」（2026-10-14）

老师不写提示词，点选即可：**范围（班级/学科；年级内置在考试里，不单独选）→ 分析侧重 →

任务中断、失败或「停止」后可把当时的选择与提示词**无损回填**继续改。

- **入口**：AI 分析工作台 `/grades/ai` 与**成绩汇报区** `/grades/report` 的 AI 卡片右上角
  「提示词生成器」（两者共用 `static/js/ai_prompt_gen.js` 的工厂实例，DOM 选择器与考试来源参数化；
  样式 `.ai-gen-panel` / `.ai-gen-chips` 在 `theme.css`，深浅主题自适应）。
- **年级不单独选（2026-10-14 用户口径）**：每场考试自带年级（「考试」下拉已标），生成器只在
  **本场考试内**收窄范围，因此面板只有班级/学科两组多选；`gen.grades` 恒为空数组
  （＝本场考试所属年级），字段保留仅为模板 payload 向后兼容。
- **选项来源（按权限收窄，选项里选不出越权组合）**：班级 = 本场考试**成绩（考试当时班级）∪
  任课快照**（与成绩分析页 `_classes_by_exam` 同源，"已排考务、未导入成绩"的考试也能选）；
  学科 = 本场考试实际有成绩的学科（排除总分）；两者再分别经
  `score_guard.visible_classes / grade_subjects` 过滤。侧重 / 输出格式 / 附加要求预设
  由服务端下发（`services/ai_prompt.py` 是唯一维护点）。空态文案直接在面板里说明
  （"本场考试还没有成绩或考务数据，先导入成绩再分析"）。
- **拼装与校验**：`POST /grades/ai/prompt/build` 做**真实性 + 权限双校验**（班级/学科必须是本场
  考试真实存在的值、在可见范围内，非法即 400 并说明原因），再拼成一段带
  【考试】【分析范围】【分析重点】【输出要求】【附加要求】【数据纪律】的提示词。
  拼装结果只是 `AiTask.question`（**用户仍可手动编辑**）；数据边界仍由工具层的 `score_guard`
  兜底，所以"手动改过的提示词"照常可跑、不构成权限通道。
- **输出格式**：三个选项都是 HTML 变体（标准 / 简要小结 / 详细报告）——渲染链路只认
  HTML 片段（§4.9.1），这里调的是篇幅与结构，不改变产物类型。
- **模板**：`ai_prompt_templates`（`user_id + name + payload(JSON)`，仅本人可见/可删）。
  payload 存**结构化选项 + 当时生成的 prompt**；同名保存＝覆盖；套用＝回填选项与提示词。
- **停止（新状态 `canceled`）**：`POST /grades/ai/tasks/<id>/stop` → 进程内标记

  检查（模型 HTTP 请求在飞时不可中断，语义是"当前这一步跑完就停"）→ 任务状态记 `canceled`。
  前端在 `running` 时显示「停止」，`canceled / interrupted / error` 时显示「重新编辑提示词」
  （数据源＝任务的 `gen` 列，老任务没有 `gen` 时降级为只回填提示词文本）。
- **接口**：`GET /grades/ai/prompt/options?exam_id=`、`POST /grades/ai/prompt/build`、
  `GET|POST /grades/ai/prompt/templates`、`POST /grades/ai/prompt/templates/<id>/delete`、
  `POST /grades/ai/tasks/<id>/stop`；`POST /grades/ai/ask` 新增可选 `gen`（结构化选项留档）。
- **迁移**：`scripts/migrate_ai_prompt_tpl_20261014.py`（建 `ai_prompt_templates` +
  `ai_tasks.gen` 列；`ai_tasks.question` 上限由 500 放宽到 2000 —— SQLite 不校验类型，无需重建表）。

## 6. 故障隔离自检

| 场景 | 影响面 |
|------|--------|
| `grades.db` 文件损坏/锁定 | 启动时逐库建表容错仅告警；成绩/汇报/考务/证明页面报错；**登录、系统管理、宿舍、教务（除任课映射数展示）不受影响** |
| 成绩模块写入 | 仅写 `grades.db`，无跨库写入、无跨库事务 |
| 读取 system 失败 | 成绩分析显示学生信息受限但不崩溃（快照字段优先） |
| AI 外呼失败 | 仅报告生成失败（错误提示），不影响其他功能 |

### C. 考场分层编排

`app/modules/grades/routes/exam_affairs.py::_arrange(affair, students, rooms, mode, log, layered, rank_map)`：

1. **固定座位优先**（`fixed_room` + `fixed_seat`）占据座位，自动分配跳过
2. 按**选科组合**分组（`selection_mode='selected'`）
3. `layered=True` 时：组内按**上一场同阶段考试**的校内**方向排名**升序 →
   考场按 `room_no` 排序、座位从前往后取**首个空位** → 实现**容量累积分段**
   （前 N 个考场共 M 座 ⇒ 第 1~M 名）
4. 排名来源 `_prev_stage_rank_map(affair)`：同年级 + 同 `exam_type` + 日期更早的最近一场，取总分行的 `rank_dir`；**无数据则退化随机**（不阻断）
5. 入口：考务页「按成绩分层编排」勾选 → `POST /grades/affairs/<aid>/arrange` 带 `layered=1`
6. 验证：`python -m scripts/smoke_affair_arrange`（5 组用例）

### D. AI 智能导入

```
侧栏「成绩导入」→ 页内切换到「AI 智能导入」（同一个入口，两种导入方式）→ 拖入任意格式表（可多选）
   → 服务端 probe（表头按“文本单元格最多且最早出现”的行识别 + 3 行样本）
   → AI 只做“列映射 + 分数类型判断 + 待确认问题”
   → 页面展示 AI 结论，用户确认/微调（每个工作表可改“这份是：赋分/原始/两者”）
   → 确定性引擎解析全量 → 预览 → 写入
```

- **双文件双轨合并**：赋分表进主分、原始表进 `raw_score`；只有原始分的学生主分顶上
- **无 AI Key 时**：跳过 AI，遍历所有列提供“对应字段”下拉，手工指定后同样能导入
- 接口：`POST /grades/exams/<id>/ai-import/analyze`（multipart，`ai` 字段带本机配置）、
  `POST /grades/exams/<id>/ai-import/apply`（`dry_run` 预览 / 正式写入）

### E. 临界生对比

- 页面：`GET /grades/exams/<id>/near-line`（服务端渲染）
- 参数：`direction` / `layer` / `above`（线上 N 分，默认 10）/ `below`（线下 M 分，默认 20），上限 `NEAR_LINE_MAX`
- 计算：复用 `report_warning_service.near_line_report()`（与汇报区「压线提醒」同源）
- 展示：概览卡 → 班级对比矩阵（线下/线上/合计 + 占比条）→ 临界生明细（含各科、距线、方向排名）
- 未划线考试显示提示而非报错
- **范围**：名单只含"账号可见班级 ∩ 总分口径"的班（班主任本班 / 年级长及以上整年级；
  任课班级不含总分口径 → 不计入），页头徽标写明生效范围，详见第 4.5 节
- 导出（2026-10-19）：`GET /grades/exams/<id>/near-line/export`，参数与页面
  相同（`cls` / `direction` / `layer` / `above` / `below`）；Excel 含
  「临界生名单」「班级对比」两张表。数据范围与页面同源
  （`services/near_line_view.load()`），导出不是绕过总分口径的旁路。
