> 适用版本：v1.7.0（2026-08-02）· 宿舍自动分配算法 V20260805

## 快速开始

### 访问地址
```
http://服务器IP:5000
```

### 默认管理员
```

```

系统支持 Docker 全镜像一键部署和阿里云服务器部署，详见 [部署文档](部署文档.md)。

登录后首先进入**欢迎页**，展示三大功能模块入口：

| 模块 | 状态 | 说明 |
|------|------|------|
| 🏠 宿舍管理 | 已完成 | 宿舍分配、床位管理、统计报表 |

> 欢迎页无侧边栏，进入具体模块后才会显示对应侧边栏。

### 1.1 模块数据分离说明

系统采用模块化数据分离设计，各模块数据存储在独立数据库中：

| 模块 | 前端入口 | 数据来源 | 说明 |
|------|---------|---------|------|
| 系统管理 | `/system/` | `system.db` | 学生基础信息、用户、字典等 |
| 宿舍管理 | `/dashboard/` | `system.db` + `dormitory.db` | 基础信息从系统库获取，住宿信息存宿舍库 |
| 成绩管理（待开发） | `/grades/` | `system.db` + `grades.db` | 基础信息从系统库获取，成绩数据存成绩库 |
| 积分管理（待开发） | `/points/` | `system.db` + `points.db` | 基础信息从系统库获取，积分数据存积分库 |

**设计优势**：
- 各部门独立管理自己模块的数据，互不干扰
- 学生基础信息（姓名、学号、性别等）统一维护，避免数据重复
- 模块间通过学生 ID 关联，保证数据一致性

## 三、宿舍管理模块

左侧菜单 → **宿舍管理**（或欢迎页点击"宿舍管理"卡片），进入宿舍仪表盘。

### 3.1 侧边栏导航
进入宿舍管理后，左侧显示宿舍专属菜单：
- 学生查询
- 宿舍列表 / 分配宿舍 / 宿舍报表
- 床位分配
- 宿舍总览
- 统计报表

### 3.2 学生查询
左侧菜单 → **学生查询**，支持按姓名、学号、年级、班级、性别组合搜索。

### 3.3 宿舍列表
查看所有宿舍，按楼栋/性别/楼层/床位数筛选。

**合班宿舍标识**：班级名含 `+`（如 `01班+02班`）即为合班宿舍，列表自动显示黄色"合班"徽标，无需手动设置。

### 3.4 新增宿舍
点击"新增宿舍" → 选择楼栋、房间号、性别、床位数 → 保存。支持批量新增。

**宿舍编辑（分配班级）**：班级选择框支持多选，选中 2 个及以上班级（如 `01班` + `04班`）保存后，系统自动识别为合班宿舍：
- 班级名自动拼接为 `01班+04班`（按班号排序，不分主次）
- 宿舍列表 / 详情 / 可视化分配 / 互换弹窗 / 统计报表 **全站自动显示合班**，无需手动勾选"合班"标记
- 同一宿舍的合班班级，其学生均可入住该宿舍（跨班防护自动放行）
- 手动设置不再影响合班识别，合班详情（各班级人数份额）仅在自动分配时生成

### 3.5 分配宿舍给班级
- **可视化分配**: 拖拽班级到宿舍房间。同一房间拖入多个班级，保存后自动聚合为合班宿舍（如 `02班`+`01班` 自动整理为 `01班+02班`）
- **自动分配**: 选择班级+房间 → 系统计算最优方案 → 预览 → 执行

#### 3.5.1 自动分配（算法 V20260805）

系统采用**平滑动态贪心 + 全局压力等级制**算法，自动决定住宿宽松程度：

| 压力等级 | 说明 | 触发条件 |
|---------|------|---------|
| L=6 宽松 | 8 人间只住 6 人 | 房间充足 |
| L=7 紧张 | 8 人间住 7 人 | 默认优先尝试 |
| L=8 极限 | 8 人间住满 8 人 | L=7 装不下时自动升档重试 |

**核心特性**：
- **宽松优先**：算法优先尝试 L=7（8 人间只住 7 人）；若房间不足（班级收尾占房过多）自动升档 L=8 重试，保证分配成功
- **动态前瞻**：每间房分配时检查后续容量，压力均匀分散
- **S 型序列化**：房间按楼层 S 型连接，班级按（年级→班型→班号）顺序连续切段，高年级优先低楼层
- **合班被动触发**：班级收尾剩 1~3 人时自动与下一班（同性别+同年级+同班型）合并，两班不分主次
- **合班调整优化**：自动拆分链式合班，减少合班宿舍数量（如 16 间 → 13 间），并输出优化日志
- **每班最多发起 1 次合班**（被借不算）

**使用提示**：
- 预览页可查看完整分配明细与算法日志，确认后点击"执行"生效
- 想住得更宽松：**多勾选几间宿舍**（尤其 6 人间），房间越多越容易触发 L=7 宽松模式（8 人间从 8 人降为 7 人）；极限模式下算法用最少房间装下所有人，靠后的房间可能闲置，属正常现象

### 3.6 宿舍报表
查看按年级/性别/班级组织的分配总览，支持导出 Excel。

### 3.7 床位分配
选择年级班级 → 拖拽学生到空床位。支持一键自动分配、搬移、互换。

**限制**: 性别必须匹配、非合班宿舍仅限本班学生。

### 3.8 统计报表
全校/年级/班级三级视图，展示男女比例、住校走读分布。

## 四、系统管理模块

左侧菜单 → **系统管理**（或欢迎页点击"系统管理"卡片），进入学生列表。

> 侧边栏显示系统专属菜单：学生管理、用户管理、字典管理、班型设置、权限组管理、年级管理。
> 无权用户点击受限页面会提示"无权限"。

### 4.1 学生管理
学生的增删改查、批量导入、批量调班。

**新增学生**: 填写姓名、性别、学号（必填）→ 选择年级班级 → 保存。  
**批量导入**: 下载 Excel 模板 → 填写数据 → 上传。必填列：姓名、性别、**学号**、身份证号。学号为跨模块业务主键，必须填写且唯一。  
**批量删除**: 仅管理员可用。

### 4.2 用户管理
新建/编辑用户，设置角色（管理员/宿管教师/班主任/年级长/全校组），重置密码，启用/禁用。

### 4.3 字典管理
管理下拉选项：年级、班级、楼栋、楼层、走读类型等。被引用的值无法删除。

### 4.4 班型设置
设置各班班型、选科方向，用于自动分配时的合班判断。

### 4.5 权限组管理
创建自定义权限组，控制菜单可见范围和数据范围。

### 4.6 年级管理
**毕业操作**: 清空该年级的宿舍和床位分配，同时备份主数据库（`dormitory.db`）和分配历史库（`history.db`）到 `data/backups/`，方便日后追溯。  
**历史查询**: 查看历史毕业备份数据。

### 4.7 寝室分配历史
系统自动记录每次床位分配、取消、搬移、互换、清空操作。记录保存在独立的历史库中，包含学生快照、房间信息、操作人、学期等字段，即使学生被删除仍可追溯。每学期重新分寝时的历史数据永久保留。

## 五、常见问题

**Q: 忘记管理员密码？**  
A: 运行 `python scripts/init_db.py` 仅会补建缺失的数据（管理员、字典、宿舍），不会覆盖已有数据；如需重置密码，请删除数据库后重新初始化（会清空全部数据，务必先备份）。

**Q: 身份证号显示为空？**  
A: AES 加密存储，旧明文数据自动兼容读取。

**Q: 自动分配报"床位不足"？**  
A: 扩大房间选择范围或启用极限模式（8人间满8人）。

**Q: 导入 Excel 报"学号为空"？**  
A: 学号是跨模块业务主键，不能为空。请确保每个学生都有学号。

**Q: 导入 Excel 报"身份证号格式不正确"？**  
A: 身份证号必须 18 位，校验码正确。

**Q: 每学期重新分寝后，之前的分配记录还在吗？**  
A: 在。系统自动在独立历史库中记录所有分配变更，即使重新分寝也不会丢失。毕业操作也会备份历史库。

**Q: 预览时我勾选的宿舍为什么有些没用上？**  
A: 当房间不足触发 L=8 极限模式时，算法按 S 型序列用最少房间装下所有人，序列靠后的宿舍（如顶层）可能闲置，属正常行为。

**Q: 怎么让宿舍住得更宽松一些？**  
A: 多勾选宿舍（尤其 6 人间）。房间总数越多，L=7 宽松模式越容易触发成功（8 人间只住 7 人）；反之房间紧张时会自动进入 L=8 极限（8 人间住满 8 人）。

**Q: 合班宿舍需要手动设置吗？**  
A: 不需要。只要宿舍班级名含 `+`（手动选多班、可视化拖入多班、自动分配生成均可），全站自动识别为合班宿舍并显示，两班不分主次。

**Q: 为什么有些班级出现在两个合班宿舍？**  
A: 班级收尾人数较少时（如 1~3 人），可能被拆分并入两个合班宿舍，这是床位限制下的最优解（如 216 已满员时，多出的 1 人并入前序合班房），不违反"每班最多发起 1 次合班"规则。
