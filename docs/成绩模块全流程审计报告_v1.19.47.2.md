## 〇、总体结论

**主链路（建考试 → 导入 → 排名 → 划线 → 分析 → 汇报 → 考务 → 监考）是完整的**，工程质量高于常见 Flask 项目：快照机制、缓存失效、权限守门、公式注入防护、上传白名单、SSRF 白名单、CSRF 全覆盖都做得扎实；历史审计问题（静默 except、N+1、跨库写入）已有系统性修复痕迹。

**问题集中在三类**：

| 类别 | 数量 | 性质 |
|---|---|---|
| 🔴 安全漏洞（可越权/可注入） | **4** | 单路由缺防线，1~5 行可修 |
| 🟠 数据可信度缺口 | **5** | 缺考/加分/对账——系统"能算"但"算的什么"说不清 |
| 🟡 一致性与体验 | **25+** | 4 套表头、5 种反馈、文档滞后 16 个版本 |

**最需要注意的一句**：系统目前的数字（排名/均分/上线）建立在"缺考按 0 分计入总分"这一未声明的口径上，且没有任何界面告知用户这一点。这是全模块最大的**隐性数据可信度风险**（详见 §3.2）。

## 三、业务流程与功能缺口

### 3.1 🔴 最严重：缺考按 0 分计入总分，且无任何界面告知

- **位置**：[store_service.py:78](file:///d:/Users\lenovo\Desktop\StuLink\app\modules\grades\services\store_service.py#L78)
- **问题**：`total = Σ sel_subs`，`merged.get(s, 0)` —— **未参考科目按 0 分**。一名理科生缺考物理（0 分），总分被扣 100 分，直接掉到年级榜末尾，并把班级均分、去差均分、分数段分布全部拉偏。手工改分路径 `refresh_student_total()`（:117-138）同样按 0 计，两路径一致但都不合理。
- **关键**：系统里**没有任何"缺考不计入 / 记为 null / 记为 0"的口径开关**，也没有在成绩单/分析页上提示"该生有科目缺考，总分按 0 计"。用户看到的数字无法解释。
- **建议**：考试级配置「缺考按 0 / 缺考不计入（按已考科目折算）」，成绩单与分析页明示当前口径。

### 3.2 🔴 缺考名单管理 + 导入后对账：完全缺失

- 现状：缺考只能靠"单元格留空"间接表达（导入时把空单元格当缺考删行）；整行无分只计入 `absent_rows` 计数，**不落库**，预览后即消失（[import_service.py:176-178](file:///d:/Users/lenovo/Desktop/StuLink/app/modules/grades/services/import_service.py#L176-L178)）。
