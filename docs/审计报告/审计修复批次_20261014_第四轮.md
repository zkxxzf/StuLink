## 1. 已修复项（逐条带验证）

### 1.1 SEC-03 调课申请「代办人」标记（中）
- 背景：教务/领导在「单节总览 → 就地代课/调课」替原任课教师发起申请（申请人记原任课教师，
  属业务口径），但单据看不出**实际操作人**，对方收到的通知也像教师本人发的。
- 修复：`ScheduleSwap` 加 `operator_uid` / `operator_name` 两列（`app/models/timetable.py`，
  `to_dict` 用 getattr 兼容旧库）；`apply_exchange_batch(..., operator_uid, operator_name)`
  落库；`inspection.py` 单节总览入口传当前操作人（teacher_service 关联教师编号）；
  `_notify_exchange` 通知对方时点名「（由 XX 代办）」；`swap_detail.html` 加「代办人」行。
- 迁移：`scripts/migrate_swap_operator_20261014.py`（幂等加列，清单 A8/B28 + 执行器）。
- 验证：`AUDIT4` 4 条源码级断言（双向对照见 §2）。

### 1.2 SEC-04 AI 全局 Key 独立权限点（低）
- 背景：`/grades/ai/global-key` 三个端点装饰器为 `grades.view`，真实门禁
  `_guard_key_manage()` 藏在函数体内 —— 一次重构漏拷守卫即让只读账号改写全局 AI Key。
- 修复：新增权限点 `grades.ai_manage`（`permission_map.py`，standalone 单独勾选，
  权限页「成绩管理 → AI 全局 Key」）；三端点装饰器与 `_guard_key_manage` 统一该判据；
  管理员组种子补 key；迁移 `scripts/migrate_ai_key_perm_20261014.py` 给
  「role=admin 或 menu_keys 含 system.users 的组」补齐（**行为不倒退**，清单 A10/B30 + 执行器）。
- 验证：AUDIT4 2 条 + 权限页可见新项（冒烟 38 项含权限矩阵保存链路全绿）。

### 1.4 多身份改造新代码审计（本轮新发现，master 合并带入）
- **中·迁移误删保护**：`migrate_perm_multi_20261014.py` 原只看旧字段 `user.permission_group_id`
  计数组内用户 —— 仅通过 `user_permission_groups` 关联挂在该组的用户会被**误判为空组而删组**；
  「考务数据管理员→考试管理员」合并也不迁移关联。已改为同时统计关联表、合并时迁移/去重
  关联并保 `is_primary`。
- **中·范围口径**：`resolve_scope` 此前只取 UserDataScope 的年级、忽略 `class_name`
  （「仅授权某年级某班」被放大为整年级，与成绩侧 `student_in_scope` 口径分裂）。
  现已吸收班级白名单：纯班级级 → `classes`（精确到班）；混合形态 → 整年级 + `logger.warning`
  提示收敛配置。同步修 `student_scope.apply_student_scope`（学生列表/搜索/导出）与三个
  消费方（dormitory_scope / points / morality）的 origin 分发。
- **低·切换身份不一致**：侧栏「成绩分析」可见性（`base.html`）、考试页第④步落点
  （`exams.py`）、工作台资料页范围文案（`workbench`）原读旧单值 `permission_group`，
  切换多身份后与实际权限不符 —— 统一改 `active_group` / `scope_type_of`。
- **低·悬空关联**：`_set_user_groups` 加组存在性校验（SQLite 不强制外键）。
- **低·P1 迁移**：`migrate_user_groups_p1.py` 对「已有同组关联但未标 is_primary」补标记。
- 验证：AUDIT4 6 条（user_scope_detail / 学生查询吸收白名单 / 组存在性 / 废弃组保护 / P1 补标记）。
