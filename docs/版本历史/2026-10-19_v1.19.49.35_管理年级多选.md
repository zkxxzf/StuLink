# v1.19.49.35 · 2026-10-19 · 管理年级支持多选

## 一句话概述

用户管理里「管理年级」由单选改为**可多选**：年级长可同时管理多个年级，
班主任仍强制只能 1 个（一个班只属于一个年级）；数据范围、成绩权限、
积分、通知、宿舍与学生查询全部按多年级同步生效。

## 改动清单

### 新增

- `User.grades` 属性（逗号串 → 年级列表，兼容中文顿号/逗号与历史单值）、
  `User.set_grades()`、`User.grade_display`（显示用「、」分隔）。
- `scope.get_scope_grades(user)`：年级范围的完整列表，凡「限定到年级」的
  判定与查询统一走它。

### 修复

- 无（本次是功能改造；顺带把各处直接读 `user.grade` 单值的地方统一到
  `grades`，避免多选后范围失真）。

### 优化 / 重构

- 表单：`UserForm.grade` 改 `SelectMultipleField`，编辑页回显按列表预选。
- 保存：`users.py` 新建/编辑把所选年级去重后逗号拼接入库；班主任校验
  从「非空」改为「恰好 1 个」，年级长要求至少 1 个。
- 范围读取改为多年级：`utils/scope.py`、`utils/student_scope.py`、
  `utils/alumni_scope.py`、`grades/services/scope.py`、
  `grades/services/score_guard.py`、`grades/services/exam_guard.py`、
  `grades/services/ai_service.py`、`workbench/services/scope.py`、
  `grades/routes/student_query.py`、`points/routes.py`。
- 年级长看「任课教师分析」改为取**本场考试年级**（`exam.grade`），
  不再依赖用户单值年级：网页 `analysis.py` / `export.py`、小程序
  `wxapi/grades/routes_analysis.py`。
- 通知定向 `grade` 的收件人展开由 SQL `IN` 改为 Python 集合交集
  （逗号串无法用 `IN` 匹配）；通知进度与小程序用户概要显示改用
  `grade_display`。
- 宿舍分配、学生新增的「默认年级」取首个管理年级（班主任场景）。

### 文档

- `docs/规范与说明/数据库迁移清单.md`：新增 A16（说明 `users.grade`
  声明长度 10 → 100，SQLite 动态类型无需执行）。

### 脚本 / 数据库

- 无迁移脚本、无需执行 DDL：SQLite 不校验 `VARCHAR` 长度，
  存量单值数据直接兼容。

## 影响与风险

- 历史单值账号行为不变（`grades` 返回单元素列表）。
- 班主任若历史上被手工写成多个年级，学生范围取首个年级，避免跨年级
  同名班误伤；建议在用户管理里改成 1 个。
- 年级长多选后，成绩/学生/积分/通知范围都会扩大到他管理的全部年级；
  已毕业年级仍按原口径剔除（`score_guard` / `alumni_scope`）。

## 回滚方式

1. 代码回退到本批之前。
2. **数据先行**：回滚前把已存成 `2025级,2026级` 的账号改回单个年级
   （旧代码会把逗号串当成一个年级名，导致范围全部失配）。
3. 无表结构变更，无需回滚数据库。

## 待办与遗留

- 用户管理列表暂未显示多值年级（沿用原列表字段）；如需展示可改用
  `grade_display`。
- 若未来迁 MySQL，需按迁移清单 A16 执行 `ALTER TABLE ... MODIFY`
  把 `users.grade` 扩到 100。
