# 待提交 · 成绩分析「同班型班级相邻」排序（2026-10-21）

> 状态：草稿（待提交）
> 起因：用户反馈「大型考试做成绩分析时应该把同类型的班级放到连续的几行，
> 让他们挨着」——截图指向成绩总览（全年级对比）与年级分析。

## 一句话概述

成绩分析里所有**按班级列出**的表，行序由「班号」改为「**班型分组 → 组内班号**」：
卓越班 → 强基班 → 实验班 → 平行班 → 普通班 → 其它已登记班型（按名称）→
未登记班型（最后）。实测 exam 24（01/02/03 卓越、04/05 强基、06/07 卓越、
…）由交错 01 02 03 04 05 06 07 变成 01 02 03 06 07 08 10 | 04 05 09。

## 改动清单

### 新增

- `app/modules/grades/services/class_order.py`：唯一的班级排序口径。
  - `CLASS_TYPE_PRIORITY`：班型优先级（与前端图表 `CHART_TYPE_ORDER`
    的「卓越班 0 / 强基班 1」保持一致）。
  - `class_no()` / `type_rank()` / `order_key()`：排序键（班型 → 班型名 →
    班号 → 班名），班号取不到时排组末。
  - `type_map_of(data)`：`{班级: 班型}`，成绩快照优先、班级档案回落
    （与 `report_service.trimmed_nos` 的去差口径同源），结果缓存在 ExamData。
  - `teaching_classes(data)`：本场教学班（01班~99班）按班型分组后的列表。

### 修复

- `global_compare_service.global_compare_report()`：班级行序由
  `numeric_classes()`（纯班号）改为 `teaching_classes()`；同时把原先
  `snap_ct` / `live_ct` 两份字典合并为 `type_map_of()` 一份（去差名额与
  「班型」列共用），少一次重复的班型推导。影响：全局对比页表格、打印版、
  Excel 导出的班级顺序（三者同源）。
- `stats_service.class_summary_table()`：年级分析「各班汇总表」行序同上 →
  名次段分布表的班级列、班级汇总图表横轴一并跟随。
- `stats_service.print_summary()`：汇总打印版每个方向的班级行改用同一顺序
  （原 `cls_rows.sort(key=cls)` 会按班名重排、把分组顺序打乱）。
- `tab_service.subject_tab()`：学科分析「各班对比表」由「全表按均分降序」
  改为「**班型分组 → 组内按均分降序**」，图表横轴（各班得分对比）跟随。
  实测 exam 24 语文：卓越班 95.2 → 91.7，其后强基班 99.8 → 96.4。
- `tab_service._heatmap()`：热力图横轴同口径（跨科目无组内均分可比，组内按班号）。

### 优化 / 重构

- 班型 → 班级的推导从「分散在 6 处各自排序」收敛到 `class_order.py`，
  以后要调优先级（例如把强基班提到最前）只改一个常量。
