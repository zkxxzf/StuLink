## 油猴脚本怎么用

1. 浏览器装 Tampermonkey，安装
   `https://dd.sakaay.com/files/stulink-zhixue-import.user.js`；
2. 打开智学网某场考试的「学生成绩」页 → 右下角出现「StuLink · 智学网抓取」面板：
   - **抓取当前科目**：只抓当前视图（单科视图时最省时间）；
   - **抓取全部科目**：有科目标签时逐个切过去、各自翻页；
   - **复制 TSV**：退回手工粘贴用（可粘进 Excel）；
3. 打开 StuLink 该场次的「数据导入」页（`?tab=import`）→ 右下角「StuLink · 一键导入」：
   - 选要导入的科目（会自动把「英语/日语」映射成「外语」）；
   - 点「一键导入」→ 上传 → 确认 → 自动跳到「学生成绩」页；
4. 同科重导 = 整科覆盖（与手工导入同一口径）。

## 实现要点

- 抓取逻辑沿用 `scripts/zhixue/fetch_zhixue.py` 实测过的结构：
  `.tb-pdt`（序号/准考证号/班级/姓名）+ `.tb-num`（两行表头：组名 `th[colspan]`
  + 列名）+ `.page-box.report` 翻页；翻页后等「首行变化 + 两次读数一致」再取，
  避免读到清空中的空页。
- 数据交接走油猴存储 `sli:payload`（同一个脚本跨域共享），
  不依赖剪贴板、不需要保持两个标签页同时打开。
- 导入时在 StuLink 页面拼 CSV（`考号,姓名,班级,分数`），带页面里的
  `csrf_token` POST 到 `/timed/<id>/import/upload`，跟随跳转取出批次
  `token`，再 POST `/import/confirm`；失败会把服务端 flash 原文显示在面板上。
- 学号匹配沿用后端：**考号优先 → 学号兜底**；抓不到分数（缺考/「—」）的行自动跳过。

## 2026-10-21 补丁（用户反馈后）

### ① 匹配要"智能"，不能整表未匹配

原来只认「考号 → `students.zhixue_no`」「学号 → `students.student_number`」，
而智学网成绩表给的是**准考证号**，每场都会重排（同一届 47637703 → 47642671），
于是 441 行全被判"未匹配"。现在 `timed_match` 改成四级：

1. 学号 → `students.student_number`
2. 考号 → `students.zhixue_no`（名单同步进来的准考证号）
3. 同一串号 → `students.zhixue_account`（10 位账号，最稳）
4. **姓名 + 班级**（本年级内唯一才认；同名同班报歧义，不猜）

号码命中但姓名对不上（准考证号被别的学生复用）时**不认这个号**，交给第 4 级，
宁可不匹配也不挂错人。班级做了归一化（`1班` / `高一01班` → `01班`）。

实测（真实数据 2024级 543 人）：随机 `476xxxxx` 号 → 542 人靠姓名+班级命中；
用库内账号 → 543 全中。

### ② 名单同步：学号 ↔ 智学网号

新增 `scripts/sync_zhixue_roster.py`，读智学网导出的名单
（年级/班级/姓名/账号/准考证号/自定义考号），按 **自定义考号 = 学号** 关联：

- `students.zhixue_no` ← 准考证号（8 位）
- `students.zhixue_account` ← 账号（10 位，新增列，自动 ALTER + 建索引）

本次已执行：更新 **1569 人**，15 个"教师班"测试号不在学生表；执行前自动备份
`data/system.db.bak_20261021_104041`。

### ③ 一科一科抓不再互相覆盖

原来 `savePayload()` 直接覆盖整份数据：先抓语文、再抓数学，语文就被冲掉
（导入时"实际导入 0 行"）。现在 `mergePayload()` **按人合并**：同一人同科
覆盖该科，不同科累加；面板显示"已累积 N 人 · 科目：语文、数学"，并新增
**清空已抓数据**按钮。

### ④ 抓取可以随时停止（2026-10-21 用户要求）

原来点了「抓取全部科目」只能等它跑完，点错了没法收手。现在面板固定有一个
**停止抓取**按钮：抓取中才可点，点了以后当前页读完就停（`RUN.stop` 开关，
翻页等待里每 700ms 检查一次），**已抓到的部分照常合并保存**，状态显示
"已停止，累积 N 人"。抓完/停完按钮自动恢复，不会卡在禁用态。

### ⑤ 每次进智学网自动检查更新（2026-10-21 用户要求，v0.3.0）

之前只能靠 Tampermonkey 自己的定时检查（默认一天一次），用户看不到有没有新版。
现在脚本进入**任何**智学网页面都会：

1. `GM_xmlhttpRequest` 拉 `https://dd.sakaay.com/files/stulink-zhixue-import.user.js`
   （加时间戳绕缓存，需要 `@connect dd.sakaay.com`）；
2. 从响应头里取 `@version` 与 `GM_info.script.version` 比大小（按数字段比，
   `0.10.0 > 0.9.9`）；
3. 线上更新 → 右上角弹窗：「线上 0.3.0 ／ 当前 0.2.1，请先在 Tampermonkey 里点
   更新；**60 秒后自动刷新页面**」，按钮有「立即刷新 / 打开安装页 / 暂不刷新」；
4. 60 秒倒计时结束自动 `location.reload()`（刷新后新脚本才生效）。

非油猴环境（没有 `GM_info`）不检查；网络失败静默，不影响抓取。
调试可用 `window.__sliUpdateWait = 3` 把倒计时改成 3 秒。

### ⑥ 顺手修的 bug

上传科目原来传的是智学网写法（"英语"），现在按映射后的九科名（"外语"）上传。

## 影响与风险

- 需要重启服务：是（后端 CSV 支持）
- 数据库迁移：无
- 已知风险：
  - 智学网改版（表格 class / 翻页结构）会让抓取失效，需要按新结构调选择器；
  - 「一键导入」是**整科覆盖**，导错科目会替换该科全部成绩（原导入逻辑如此）；
  - 学生必须能按考号或学号在主库匹配上（`students.zhixue_no` 未维护的届只能走学号兜底）。
- 部署注意：脚本**不要**提交到 Gitee；发布副本放 `eo文档/docs/files/`，由「同步eo.ps1」推到 `/files/`。
- **数据库升级顺序**（其他机器拉代码后必做，否则 ORM 查 students 会报
  `no such column: students.zhixue_account`）：

  ```powershell
  py -3.12 scripts/migrate_20261021_zhixue_account.py   # 只加列 + 索引
  py -3.12 scripts/sync_zhixue_roster.py "名单.xls"     # 灌账号/准考证号（可选）
  ```
