## 实现方式（读路径覆盖，不落库）

`app/modules/grades/services/teacher_snapshot_service.py`

- `_affair_override(exam_id)`：取该场考试**最新**批次（`ExamAffair.id` 倒序，
  与全仓库口径一致）的 `affair_teachers` → `{(班级, 科目): (user_id, 姓名, 年级)}`；
  跳过班主任伪科目、跳过考务侧排除科目（通用技术）、跳过空格子。
- `_merge_affair(rows, override)`：④ 有 → 用④（包成 `_LinkView` 只读替身）；
  ④ 没有 → 保留快照行。**只覆盖不追加**，分析里的科目集合仍由快照决定。
- `links_of()` 末尾统一合并 → `name_map_of` / `teacher_user_map` 自动带上。
- `headteacher_map_of()`：④ 三列（正班主任 / 副班主任1 / 副班主任2，按列序
  顿号连接）→ 快照「班主任」行 → 当前 `UserClassLink`。

为什么用 `_LinkView` 替身而不改 ORM 行：读路径上给 ORM 属性赋值会被
session 自动 flush，把 `exam_teacher_links` 静默改写；替身只暴露同名属性
（`class_name/subject/user_id/teacher_name/grade`），消费方全是属性读。

## 关键口径（后续维护别改坏）

1. **④ 只用不写**：不改 `exam_teacher_links`，不重跑导入；换回④ 的旧值即恢复。
2. **一个考试多个批次**时取最新（id 倒序），与批次详情页、`import_attend` 一致。
3. **④ 的空格子不覆盖**：含义是「没核对 / 不知道」，保留导入快照的姓名；
   要显示空白需另行约定（当前不做）。
4. **权限口径不动**：`scope.teacher_links`（tab 可见性）、`score_guard`（MCP/AI
   的 R1 教师维度）仍读 `TeacherSubjectLink`——改④ 不会改变任何账号能看什么。
5. **班主任**：只影响走了快照的入口（汇报区板块三、全局对比）；汇报区板块二的
   班主任仍读 `UserClassLink`（另一条支线，未纳入本次）。

## 影响与风险

- 需要重启服务：**是**（改了 `.py`）
- 数据库迁移：**无**
- 每次读到分析数据会多 2 条小查询（`exam_affairs` 按 exam_id、`affair_teachers`

  沿用④ 的旧教师 —— 这是「考务为准」的必然结果，需要时点一次重新带入。
