# 待提交 · 限时练「学生成绩 / 学生分析」切班与翻页改局部刷新（2026-10-21）

> 状态：草稿（待提交）
> 起因：用户反馈「点某个班一切换慢死了」

## 一句话概述

两个列表页点班级、翻页、改每页条数时**只换 `#timedPane` 那一块**
（`?partial=1` 返回片段），不再整页重载；鼠标划过班级按钮先预取，
点击基本秒开。

## 实测（真实数据副本，No.43 / 473 人 / 43 场）

| 场景 | 改前（整页导航） | 改后（局部刷新） |
|---|---|---|
| 切到某个班（学生分析） | 68–72 ms | 19–32 ms |
| 切到某个班（学生成绩） | 80–99 ms | 23–40 ms |
| 翻到第 2 页 | 69 ms | 54–62 ms |

服务端本身不慢（热缓存 5 ms / 冷 400 ms），慢在**整页重载**：重新渲染侧栏
与框架、闪白、丢滚动位置。真实机器/网络越慢，这个差距越明显。

## 改动清单

### 新增

- `app/templates/grades/timed/_pane.html`：两个页签的局部刷新容器
  `<div id="timedPane">`，`detail.html` 与 `?partial=1` 共用。
- `app/static/js/timed_pane.js`：
  - 事件委托拦截 `a[data-pane-nav]`（班级 / 全部 / 页码），fetch 片段后
    替换 `#timedPane`，`pushState` 同步地址栏，`popstate` 支持前进后退；
  - 鼠标划过链接时**预取**（30 s 内复用），点击命中缓存直接渲染；
  - 每页条数（`#pageSize`）逻辑从 `_students.html` 的内联脚本搬到此处
    （局部替换后内联脚本不会执行），偏好仍写 `stulink.pref`；
  - fetch 失败或片段异常时**自动退回整页跳转**，不把用户卡死。

### 修复

- `timed.py:timed_detail()`：`tab in (students, trends)` 且 `partial=1` 时
  只渲染 `_pane.html`，不套 base。
- `_students.html` / `_trends.html`：班级、全部、分页链接加 `data-pane-nav`；
  删掉 `_students.html` 末尾的内联脚本（已移入 timed_pane.js）。
- `base.html`：`.timed-pane-loading`（加载中整块压暗，避免白屏感）。
