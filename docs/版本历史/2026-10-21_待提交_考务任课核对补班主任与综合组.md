## 一句话概述

考务批次④「核对任课教师」从 9 列扩成 **17 列**：9 文化科 + 综合组 5 科

## 关键口径（后续维护别改坏）

1. **班主任是伪科目**：`正班主任 / 副班主任1 / 副班主任2` 只存在于
   `affair_teachers.subject`，**不写回** `TeacherSubjectLink`，也不进考试科目字典。
2. **考试科目仍只有 9 科**：环节⑤ 时间表科目、同科回避白名单 `_SUBJ_SET`
   一律不动；否则「体育」会被当成考试科目去回避。
3. **教师池里班主任的伪科目不进 `subjects`**：`subjects` 是同科回避的匹配键，
   混进去会让同一位老师同时出现在「语文」和「正班主任」两组；改用 `is_head`。
4. **通用技术只在考务侧隐藏**（`AFFAIR_EXCLUDED_SUBJECTS`）：任课映射页 / 导入
   模板 / 学科组长仍按六科走，既有映射不丢；同步进来时会跳过被排除的科目。
5. **一节课表最多 3 位班主任**：按 `UserClassLink.id` 升序取前 3 位
   （正班在前，与教师映射导入顺序一致）。
6. **拼音码由后端下发**（`py` 全拼 / `ini` 每字首字母），前端只做字符串匹配，
   不引第三方 JS；`pypinyin` 缺失时退化为只按姓名匹配。

## 影响与风险

- 需要重启服务：**是**（改了 `.py` 与模板）
- 数据库迁移：**无**
- 数据增量：打开任一老批次④/⑥ 时会**自动补**该批次年级的班主任行（source=sync）
- 已知边界：一个班超过 3 位班主任只显示前 3 位；监考表格子里「回避」只做提示，
  真正拦截仍在保存接口（与改造前一致）。
- 部署注意：浏览器强缓存旧 CSS 时浮层样式可能不对，`?v=` 已随启动刷新。
