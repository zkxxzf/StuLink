# v1.19.49.35 · 成绩复核改为「搜学生 → 全科改分 → 提交」（2026-10-19）

> 状态：草稿（待提交）
> 相关：[成绩复核](../设计手册/成绩管理设计手册.md)

## 一句话概述

「成绩复核」提交页不再让人先选班级、再从下拉里挑学科、再手算增减
分：现在**输学号或姓名 → 直接显示该生全科成绩 → 在成绩表里填新分数
→ 一条理由提交**（一次可改多科），审批链与「批准并应用」不变。

## 改动清单

### 新增

- `app/modules/grades/routes/score_review_entry.py`：
  - `GET /grades/reviews/api/student`：按考试 + 学号/姓名模糊搜学生，
    返回**全科成绩**（只返回 `score_guard` 范围内可查看的科目；无权限的
    科目只回名字，前端提示），精确命中排前，最多 20 人；
  - `POST /grades/reviews/submit`：前端把「修改后分数」打包成 JSON
    （payload），服务端换算成 `delta = 新分 - 当前分` 后落库 ——
    模型仍只存增减分，审批与手动改分链路零改动；
  - 一次提交可含多科，**任一科不合法则整批拒绝**（不落半批）。

### 修复

- 搜索按成绩行 `limit` 时只覆盖前几个班（400 行 ≈ 44 人），搜单姓会
  漏掉后面班的学生 → 改为 `distinct` 后按**学生**限 20 人。

### 优化 / 重构

- 删除旧接口 `GET /reviews/api/students`（学生 × 科目平铺）与
  `POST /reviews/new`（单科 + 手填增减分），模板同步重写；
  旧地址现在 404（页面是唯一调用方，无外部依赖）。
- 提交页去掉「班级」下拉与「查询学生」两步操作：输入即搜（350ms
  防抖），命中 1 人直接展开成绩表，多人时给候选列表。
- 每行显示「当前分 / 修改后 / 题号 / 变化」，底部实时给「将提交 N 科」；
  未变化、超满分、无成绩行的科目不参与提交。

## 影响与风险

- 需要重启容器：是（新增 `.py` + 模板）
- 数据库迁移：无
- 已知副作用：旧提交接口 `/grades/reviews/new` 与
  `/grades/reviews/api/students` 已删除；「我的申请」列表结构不变。
- 部署注意：模板有进程内缓存，必须重启服务。
