# 宿舍管理设计手册

> 版本：v1.18.1.0（2026-09-23）｜状态：**可用**（占位文档，待补全文）
> 所属模块：`dormitory`（独立库 `dormitory.db`）｜页面前缀：`/dashboard`、`/rooms`、`/assignments`、`/statistics`
> 文档体系：`设计文档.md`（总手册）→ 本手册（模块手册）→ `宿舍分配算法手册.md`（算法手册）

## 1. 模块定位与边界

**做什么：** 宿舍房间管理、床位分配（自动分配算法 v8）、合班管理、床位可视化、统计报表。
**不做什么：** 不修改学生基础信息（只读快照）；住宿相关数据全部独立存于 `dormitory.db`。

## 2. 数据库设计（dormitory.db，3 张表）

| 表 | 说明 |
|----|------|
| `rooms` | 房间信息（楼栋、楼层、房号、容量、性别）；分配字段：`grade`（年级）、`class_name`（主班级名，合班取第一个）、`combined_class`（合班名如"07班+08班"，非合班为空）、`combined_details`（合班各班份额 JSON 如 `[{"class_name":"07班","count":4}]`） |
| `bed_assignments` | 床位分配记录（房间 × 床位 × 学生） |
| `student_accommodation` | 学生住宿信息（学号快照、住/走读类型、教材、教师备注） |

**快照关联：** 学号 → `system.db / students`（不建跨库外键）。
**历史库：** 分配变更流水在 `history.db / assignment_history`（跨模块共享，与往届查询系统共读）。

## 3. 权限与数据范围

**子功能三档（permission_map.py）：** 查看统计（`dormitory.view`+`statistics.view`）/ 房间管理（`dormitory.manage`+`dormitory.import`）/ **宿舍分配**（`dormitory.assign`）/ **床位分配**（`dormitory.beds`）——后两者独立控制（如班主任可床位分配、不可宿舍分配）。
**数据范围：** 组级 `scope_type`；用户级 `UserDataScope` 的宿舍侧过滤〔待补：宿舍模块接入用户级范围——当前按组级范围与角色分支处理〕。

## 4. 核心流程与页面

- 宿舍总览 `/dashboard`：入住情况、容量统计、性别分布
- 房间管理 `/rooms`：房间 CRUD、批量导入、床位可视化
- 宿舍分配 `/assignments`：自动分配算法 v8（严格分级初稿 → 迭代爬山 → 全局评分选优；7 项权重可调；收敛检测）、合班管理
- 统计报表 `/statistics`：床位使用率、班级/年级分布、报表导出

## 5. 与其他模块的数据交互

- **读入：** `system.db / students`（学号、姓名、班级、年级、性别快照）
- **对外提供：** `history.db` 的分配流水供往届查询系统（:5001）只读；教师工作台（规划）展示班主任宿舍相关工作〔待补〕
- 无代码级依赖其他业务模块。

## 6. 故障隔离自检

| 场景 | 影响面 |
|------|--------|
| `dormitory.db` 损坏 | 宿舍相关页面报错；登录/系统管理/成绩/教务不受影响（逐库建表容错） |
| 写入范围 | 仅 `dormitory.db` 与 `history.db`（分配流水），无跨模块事务 |
