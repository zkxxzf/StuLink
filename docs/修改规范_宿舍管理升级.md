## 问题清单与修改方案

### 修改1：合班宿舍位置 — 算法修复（HIGH）

**问题**：合班宿舍被安排在最后的房间，不符合"合班宿舍挨着原班级宿舍"的规则。

**根因**：`_try_allocate_with_combine` 先给所有班级分配连续房间，再从**剩余房间**（`free_rooms`）中选合班房。由于低楼层已被各班占用，剩余房间都在高层/最后位置。`_pick_combine_room` 虽尝试在两班房间之间找中间位置，但仅当两班同楼层时才生效，否则回退到 `room_pool[mid]`。

**修改方案**：重构合班房间选择策略 — **合班房间在班级分配阶段预留插入**：
1. 在步骤2（分配具体房间）之前，先识别哪些班级会有剩余学生需要合班
2. 为这些合班组预留一间房间，插入到两个班级的房间段之间
3. `_pick_combine_room` 改为：在 `all_rooms_sorted` 全集中寻找两个班级房间之间的最近空房，而非仅从 `free_rooms` 中选

**修改文件**：`app/modules/dormitory/services/room_assignment_v4.py`
- `_try_allocate_with_combine`（步骤2-4 重构）
- `_pick_combine_room`（增强中间位置选择逻辑）

### 修改2：床位不足 — 算法容量校验修复（HIGH）

**问题**：自动分配后，2025级5班、6班男生床位不足，7班女生床位不足。

**根因**：`_calc_class_room_counts_compact` 的紧凑模式预留过多房间给合班（`reserve = max(1, min(rooms_to_use // 8, 3))`），导致各班实际分到的房间数不足。加上 `rooms_to_use = max(min_total_rooms, total_rooms - 2)` 也额外扣减2间。

**修改方案**：
1. 减少预留房间数：`reserve` 改为 `max(0, min(rooms_to_use // 10, 1))`
2. `rooms_to_use` 不再额外减2：`rooms_to_use = min(total_rooms, min_total_rooms)`
3. 增加容量校验：分配后检查每班 `房间数 × 有效容量 ≥ 人数`，不足时从富余班级调剂

**修改文件**：`app/modules/dormitory/services/room_assignment_v4.py`
- `_calc_class_room_counts_compact`（减少预留）
- `_try_allocate_with_combine`（第551行 rooms_to_use 计算）

### 修改3：已转出班级不应分配宿舍（HIGH）

**问题**：房间145被分配给了 class_name='已转出' 的学生，无住校学生的班级不应分配宿舍。

**根因**：`_group_by_gender` 函数查询住校学生时未过滤 `enrollment_status`，"已转出"/"已毕业"等非在读学生被计入。

**修改方案**：在 `_group_by_gender` 的 Student 查询中增加 `Student.enrollment_status == '在读'` 过滤条件。

**修改文件**：`app/modules/dormitory/services/room_assignment_v4.py`（第1211-1216行）
