# 权限体系多身份改造 · 执行计划

> 版本：v1.19.49.29（2026-10-13）｜配套设计：[权限体系多身份改造设计.md](权限体系多身份改造设计.md)
> 原则：**每阶段独立可发布、可回滚、可验证**；不追求一次性完成，宁可多阶段小步走。

---

## 0. 阶段总览

| 阶段 | 名称 | 风险 | 依赖 | 可独立发布 |
|---|---|---|---|---|
| **P0** | 基线采集与备份 | 极低 | — | — |
| **P1** | 多对多数据模型 + `has_perm` | 中 | P0 | ✔（行为等价） |
| **P2** | 数据范围唯一口径收敛 | **高** | P1 | ✔ |
| **P3** | 身份切换（session + UI） | 中 | P1 | ✔ |
| **P4** | 种子 11 组 + 存量库迁移 | 中 | P1·P2 | ✔ |
| **P5** | 管理界面（组范围 / 用户多组） | 中 | P1·P4 | ✔ |
| **P6** | 回归验证与发布 | 中 | P1–P5 | — |

> 关键顺序约束：**P2 必须在 P5 之前**（先把范围口径收敛，再开放多组配置，否则多组一旦上线会放大范围口径缺陷）。
> P1 与现状**行为等价**（每人仍只有主组），是后续一切的基础。

## P0. 基线采集与备份

**目标**：把「改造前长什么样」钉死，作为一切对比的基准。

**动作**
1. 跑现有回归，记录基线通过率：
   ```
   python tests/sec_regression.py
   python tests/dormitory_regression.py
   ```
2. 导出生产权限组与用户映射快照（只读）：

3. 备份生产 `system.db`（`scripts/_db_backup.backup_db`）。
4. 记录 `docs/权限体系说明.md` §8.6（存量库与种子脱节）为已知状态。

**完成标准**：基线报告 + 快照 + 备份齐备；回归全绿或已知失败项已登记。

**回滚**：无（只读）。

## P1. 多对多数据模型 + `has_perm`

**目标**：引入「一人多组」的数据结构，但**行为与现状完全等价**（每人只有主组）。

**改动清单**
- 新增 `app/models/user_permission_group.py`（关联表，见设计 §2.1）
- [app/models/user.py](../app/models/user.py)：
  - `permission_groups`（relationship，多组）
  - `primary_group`（主组，取 `is_primary` 或回落 `permission_group_id`）
  - `active_group`（**本阶段 = `primary_group`**，切换留到 P3）
  - `has_perm` 改为 `active_group.has_menu(key)`；`role=='admin'` 仍恒 True
- [app/models/permission_group.py](../app/models/permission_group.py)：`users` 关系调整 + 关联变更时失效菜单缓存
- [app/models/__init__.py](../app/models/__init__.py)：导出新模型
- 新增迁移脚本 `scripts/migrate_user_groups_p1.py`：
  1. `CREATE TABLE user_permission_groups`
  2. 逐条把 `users.permission_group_id` 灌入（`is_primary=True`）
  3. 幂等（已存在则跳过）；改库前 `backup_db`

**注意（同样按组查用户的旁路）**
- [inspection_service.py](../app/modules/academic/services/inspection_service.py) 与 [inspection.py](../app/modules/academic/routes/inspection.py) 用 `User.permission_group_id.in_(gids)` 找组内用户 → 改为按关联表 `join`；
- 本阶段先**保留** `permission_group_id` 字段并保持同步写入（双写），减少改动面。

**验证**
- 脚本对比：P1 前后对**每个用户 × 每个权限点**的 `has_perm` 结果应**完全一致**；
- 回归套件全绿。

**回滚**：回代码 + 删除新表（旧字段仍在，功能不受影响）。

**完成标准**：新表就位、`has_perm` 走新路径、权限判决与基线零差异。

## P2. 数据范围唯一口径收敛（高风险）

**目标**：把现有 **6 套**范围解析收敛为唯一口径，消除口径漂移。

  - `apply_scope(query, grade_col, class_col, user)` — 通用条件注入
- 6 处**函数体**改为委托（**保留原函数名/签名**，调用点零改动）：
  - [app/utils/student_scope.py](../app/utils/student_scope.py) `apply_student_scope`
  - [app/modules/grades/services/scope.py](../app/modules/grades/services/scope.py) `get_scope / visible_grades / visible_classes / check_exam_visible / student_in_scope`
  - [app/modules/workbench/services/scope.py](../app/modules/workbench/services/scope.py) `managed_class_pairs / class_allowed / student_no_allowed`
  - [app/utils/dormitory_scope.py](../app/utils/dormitory_scope.py) `resolve_scope / room_scope_query / class_in_scope / student_in_dorm_scope`
  - [app/modules/points/routes.py](../app/modules/points/routes.py) `_scope / _apply_scope / _in_scope`
  - [app/modules/morality/services/reward_service.py](../app/modules/morality/services/reward_service.py) `scope_of / apply_scope / can_see`
  - [app/modules/portrait/services/portrait_service.py](../app/modules/portrait/services/portrait_service.py) 校级判定
- 顺带处理**与范围相关的 `role` 硬编码**（设计 §3.3）：
  - [student_scope.py](../app/utils/student_scope.py#L27-L42)、[workbench/scope.py](../app/modules/workbench/services/scope.py#L32-L43)、
    [assignments.py](../app/modules/dormitory/routes/assignments.py#L44)、[dashboard.py](../app/modules/dormitory/routes/dashboard.py#L210)
- **保留** `UserDataScope`；`self_teaching` 无任课记录时回落用户勾选年级（设计 §2.3）

**验证（本阶段最重）**
- 用 P0 快照构造「角色 × 模块」用例，逐角色核对可见数据集合；
- 重点回归：学生列表/导出、成绩分析页考试下拉、宿舍房间与床位、积分、奖惩、画像；
- 跑 `dormitory_regression.py` + `sec_regression.py`；
- **先本地库全绿再谈上线**。

**回滚**：回代码（旧实现仍在 git 历史）；本阶段不改数据结构日志，无数据风险。

**完成标准**：6 处委托完成、全角色可见范围与基线一致或按设计有意变更、回归全绿。

## P3. 身份切换（session + UI）

**目标**：多身份用户可自行切换「当前身份」，菜单与数据范围随之变化。

**改动清单**
- session 键 `active_group_id`；`User.active_group` 读取并**校验归属**（不属于本人则回落主组）；
- [app/modules/auth/routes.py](../app/modules/auth/routes.py) 新增 `POST /switch-identity`（校验 + 写 session + 返回）；
- [app/templates/base.html](../app/templates/base.html)：顶栏身份切换下拉（仅当组数 > 1 显示）；
- [app/modules/workbench/routes/__init__.py](../app/modules/workbench/routes/__init__.py)：工作台「身份切换」页签 + **按身份渲染卡片**（设计 §4.3）；
- 切换后失效菜单缓存（若按身份缓存）。

**验证**
- 造多组测试账号（本地库），验证：切换后侧栏/工作台/数据范围三段一致变化；
- 越权验证：以「班主任」身份访问宿管功能应 403/无入口；
- `admin` 不受影响。

**回滚**：移除切换入口，`active_group` 固定回落主组（等价 P1）。

**完成标准**：切换即时生效、无 session 时回落主组、无越权入口。

## P4. 种子 11 组 + 存量库迁移

**目标**：把系统预置身份落成 P1–P3 的新模型。

**改动清单**
- [app/__init__.py](../app/__init__.py) `PERMISSION_GROUPS` 重排为 **11 组**（设计 §5），每组带 `scope_kind`；
- 迁移脚本 `scripts/migrate_perm_multi_2026xxxx.py`：
  1. 旧 `scope_type` → `scope_kind`（`grade`→`self_grade`）
  2. **删除** 校长/副校长/备课组长/教研组长/学生发展中心（**先校验无用户**，有则先转移）
  3. 「考务数据管理员」→ **更名并入「考试管理员」**
  4. 补齐缺失的系统组（**不覆盖**已有自定义组）
  5. 打印变更清单供人工核对；幂等；改库前 `backup_db`

**验证**
- 迁移前后对比：各组权威配置 vs 设计 §5 矩阵；
- 用户归属无丢失（每人至少一组）；
- 生产执行后：`/login=200`、`healthy`、各组用户数合理。

**回滚**：从 `system.db.bak-*` 恢复。

**完成标准**：生产 13 组 → 11 组 + 自定义组；无孤立用户；核验通过。

## P5. 管理界面（组范围 / 用户多组）

**目标**：把新模型开放给管理员配置。

**改动清单**
- [app/modules/system/routes/perm_groups.py](../app/modules/system/routes/perm_groups.py)：
  - 范围列 4 档 → **7 档**（全校/指定年级/指定班级/本人年级/本人班级/本人任课/无）
  - 「指定年级/班级」展开多选
  - 第二张表改名「专职行政人员管理年级」（保留 `UserDataScope`）
  - 组用户数统计改走关联表
- [app/modules/system/routes/users.py](../app/modules/system/routes/users.py)：
  - 用户列表按**主组**分组；组内可标主组
  - 姓名后「管理年级」勾选（**仅无任课安排时可用**）
- [app/forms/user_forms.py](../app/forms/user_forms.py)：权限组 **多选**（`SelectMultipleField`）
- 模板：`system/perm_groups/manage.html`、`system/users/form.html`、`system/users/list.html`

**验证**
- 新建自定义组：可选全部 7 种范围类型（用户关切点）；
- 给一个人挂 2–3 个组，主组标记、切换生效；
- 专职行政勾选年级 → 数据范围正确。

**回滚**：界面回退；数据（多组关联）可保留。

**完成标准**：管理员可自助配置组范围与用户多组，且与设计一致。
