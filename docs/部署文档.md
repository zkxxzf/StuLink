# StuLink — 部署文档

> **版本说明**：v1.9.1（2026-09-14，成绩模块持续完善 + 积分模块上线）通过**轻量更新**发布：直接更新容器内代码 + 重启，未重建镜像。
> 下文镜像包名仍为最新可用镜像 v1.8.0（GitHub Releases）；自行构建镜像时使用 `stulink:v1.9.1`（含最新代码）。

## 部署方式总览

| 方式 | 适用场景 | 难度 |
|------|---------|------|
| Docker 双容器部署 | NAS / Linux 服务器 / 本地快速启动（主应用 + 往届查询） | ⭐ 简单 |

## 一、Docker 部署（推荐）

### 1.1 部署流程

系统包含两个容器，镜像包托管于 **GitHub Releases** 附件（[下载页](https://github.com/zkxxzf/StuLink/releases)），`deploy/` 目录结构如下：

```
deploy/
├── stulink-v1.8.0.tar        # 主应用镜像（在校生系统 :5000）
├── stulink-alumni-v1.0.0.tar # 往届查询镜像（:5001）
└── docker-compose.yml        # 双容器编排配置
```

**步骤：**

```bash
# 1. 从 GitHub Releases 下载 stulink-v1.8.0.tar 与 stulink-alumni-v1.0.0.tar，
#    连同 docker-compose.yml 上传到服务器的任意位置，如 /opt/stulink/

# 2. 导入镜像
cd /opt/stulink
docker load -i stulink-v1.8.0.tar
docker load -i stulink-alumni-v1.0.0.tar

# 3. 启动两个容器（首次启动会自动创建数据库）
docker compose up -d

# 4. 确认运行
docker ps | grep stulink
```

首次启动后，系统会在 `stulink-data/` 目录下自动生成数据库和密钥文件。

- 在校生系统：`http://服务器IP:5000`
- 往届查询：`http://服务器IP:5001`

### 1.2 NAS 部署（绿联 UGOS）

**前置**：NAS 已开启 SSH（绿联 UGOS：设置 → 终端机 → 启用 SSH），已安装 Docker 套件。

#### ① Windows 上构建并导出镜像

```powershell
docker build -t stulink:v1.8.0 .
docker save stulink:v1.8.0 -o deploy/stulink-v1.8.0.tar
```

`deploy/` 目录产物（镜像包不纳入 git 版本控制，发布时上传至 GitHub Releases 附件）：
```
deploy/
├── stulink-v1.8.0.tar    # 镜像（含全部应用代码）
└── docker-compose.yml    # 仅挂载数据目录
```

#### ② NAS 上创建目录

```bash
ssh root@你的NAS的IP -p 922
mkdir -p /volume1/docker/stulink
cd /volume1/docker/stulink
mkdir stulink-data
```

#### ③ 上传文件（SMB）

Windows 资源管理器地址栏输入 `\\你的NAS的IP`，将 `deploy/` 下两个文件上传到 `/volume1/docker/stulink/`。

#### ④ 导入镜像并启动

```bash
cd /volume1/docker/stulink
docker load -i stulink-v1.8.0.tar
docker compose up -d
docker ps   # 确认 stulink 状态为 Up
```

#### ⑤ NAS 上升级

```bash
cd /volume1/docker/stulink
docker compose down
docker rmi stulink:v1.8.0
# 通过 SMB 上传新版本 tar
docker load -i stulink-v1.8.0.tar
# 更新 docker-compose.yml 中的 image 版本号
docker compose up -d
```

### 1.3 升级方法（通用）

```bash
# 1. 停止旧容器
docker compose down

# 2. 替换镜像（删除旧镜像，导入新 tar）
docker rmi stulink:v1.8.0
docker load -i stulink-v1.8.0.tar

# 3. 更新 docker-compose.yml 中的 image 版本号

# 4. 启动
docker compose up -d
```

> ⚠️ `stulink-data/` 目录**绝对不能删除或覆盖**，所有业务数据都在其中。

### 1.4 常用运维命令

```bash
docker compose down          # 停止服务
docker compose up -d         # 启动服务
docker compose restart       # 重启服务
docker logs -f stulink       # 实时查看日志
docker exec -it stulink sh   # 进入容器 shell
```

### 1.5 自定义端口

修改 `docker-compose.yml` 中的 `ports` 即可，如改为 8080：

```yaml
ports:
  - "8080:5000"
```

### 1.6 更新方式怎么选（增量热更新 / 轻量整包更新 / 重建镜像）

三种方式并存，**按改动内容选**，不要一律打包 tar：

| 方式 | 脚本 | 适用场景 | 中断 | 能否跑数据库迁移 |
|------|------|---------|------|----------------|
| **增量热更新** | `deploy/hot_update.ps1`（本地 PowerShell） | 日常小改动：纯 Python / 模板 / JS / CSS | 约 5~10 秒重启 | ❌ 不能 |
| **轻量整包更新** | `deploy/nas_update_vX.Y.Z.sh` | 版本发布、**含数据库迁移**、新增依赖、一次改几十上百个文件 | 停容器 + 迁移耗时 | ✅ 停容器后按序执行 |
| 重建镜像 | `docker compose down/up` | 依赖（requirements.txt）或基础镜像变化 | 分钟级 | ✅ |

**选用规则**

1. 只改了代码/模板、且**没有** `scripts/migrate_*.py` 要跑 → 用**增量热更新**（最省事，无需打包）。
2. 版本里带了迁移脚本（新表/新列/分库/数据回填）→ 必须用**轻量整包更新**，因为迁移要在
   **应用停止**状态下执行，增量脚本只做「传文件 + 重启」。
3. `requirements.txt` 有变 → 重建镜像（或进容器 `pip install`）。

**增量热更新用法**（在本地仓库执行）

```powershell
# 日常：改完 → commit → push 后，一条命令搞定
powershell -ExecutionPolicy Bypass -File deploy\hot_update.ps1

# 只看这次会传哪些文件（不动远端）
powershell -ExecutionPolicy Bypass -File deploy\hot_update.ps1 -DryRun

# 指定基准提交 / 只更新不重启 / 附带删除容器内已移除的文件
powershell -ExecutionPolicy Bypass -File deploy\hot_update.ps1 -From 5c9306d -NoRestart
powershell -ExecutionPolicy Bypass -File deploy\hot_update.ps1 -Delete
```

链路：`git diff 取变更 → 本地暂存 → scp 上传 NAS _hot → docker cp 进容器 → 重启 → 验收 → 记录已部署提交`。
基准提交缺省读 NAS 上的 `/volume1/docker/stulink/.deployed_commit`，整包脚本可写入：

```bash
ssh NAS 'bash -s -- <commit>' < deploy/nas_update_vX.Y.Z.sh    # 末尾记录"已部署提交"
```

**前提与注意**

- 容器 `/app` **不是**宿主机挂载目录（只有 `stulink-data → /app/data` 是 bind），
  所以 `scp` 到宿主机**不会生效**，中间必须有 `docker cp`；tar 只是传输介质，可以省。
- 只处理**已 commit** 的增量；工作区未提交的改动不会被上传。
- 该 NAS（绿联 UGOS）**没有 git**、有 rsync；`scp` 需加 `-O` 走 legacy 协议
  （新协议在本机实测会报 `dest open ... No such file or directory`）。
- `hot_update.ps1` 必须存为 **UTF-8 with BOM**，否则 PowerShell 5 按 ANSI 读取，
  中文会导致语法解析失败。
- 回滚：整包脚本自动备份 `code_backup_vX_* / stulink-data-backup-*`；
  增量热更新不带备份，需要回滚时用整包脚本的备份目录覆盖。

## 二、阿里云 ECS 部署

### 2.1 前置条件

- 阿里云 ECS 实例（CentOS 7+ / Ubuntu 20.04+ / Alibaba Cloud Linux）
- 安全组已放行 **5000** 端口（或自定义端口）
- 已安装 Docker 和 Docker Compose

### 2.2 安装 Docker（CentOS 7 示例）

```bash
# 安装 Docker
yum install -y yum-utils
yum-config-manager --add-repo http://mirrors.aliyun.com/docker-ce/linux/centos/docker-ce.repo
yum install -y docker-ce docker-ce-cli containerd.io docker-compose-plugin

# 启动 Docker
systemctl enable docker
systemctl start docker

# 验证
docker --version
```

### 2.3 安装 Docker（Ubuntu 示例）

```bash
apt update
apt install -y docker.io docker-compose-v2
systemctl enable docker
systemctl start docker
```

### 2.4 上传部署文件

```bash
# 方法一：scp 上传（在本机执行）
scp -r deploy/ root@你的ECS公网IP:/opt/stulink/

# 方法二：使用阿里云 OSS 中转
# 先将 deploy/ 上传到 OSS，再在 ECS 上下载
```

### 2.5 部署启动

```bash
cd /opt/stulink
docker load -i stulink-v1.8.0.tar
docker compose up -d
```

### 2.6 配置安全组

在阿里云控制台 → 网络与安全 → 安全组 → 添加规则：

| 方向 | 协议 | 端口 | 授权对象 |
|------|------|------|---------|
| 入方向 | TCP | 5000 | 0.0.0.0/0 |

### 2.7 配置域名（可选）

1. 在 DNS 服务商将域名 A 记录指向 ECS 公网 IP
2. （推荐）使用 Nginx 反向代理，实现 80 端口访问 + HTTPS：

```nginx
# /etc/nginx/conf.d/stulink.conf
server {
    listen 80;
    server_name your-domain.com;

    location / {
        proxy_pass http://127.0.0.1:5000;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    }
}
```

```bash
# 安装并启动 Nginx
yum install -y nginx    # CentOS
apt install -y nginx    # Ubuntu
systemctl enable nginx
systemctl start nginx

# 测试配置
nginx -t
systemctl reload nginx
```

### 2.8 配置 HTTPS（推荐）

使用 Certbot 免费 SSL 证书：

```bash
# CentOS 7
yum install -y certbot python3-certbot-nginx
# Ubuntu
apt install -y certbot python3-certbot-nginx

# 自动配置 Nginx + SSL
certbot --nginx -d your-domain.com

# 设置自动续期
echo "0 3 * * * root certbot renew --quiet" >> /etc/crontab
```

### 2.9 配置开机自启

`docker-compose.yml` 已设置 `restart: unless-stopped`，Docker 服务自启即可：

```bash
systemctl enable docker
```

## 三、生产环境配置建议

### 3.1 修改默认密码

首次登录后立即修改 admin 密码：右上角 → 改密码。

### 3.2 设置 SECRET_KEY

编辑 `docker-compose.yml`，将 `SECRET_KEY` 设为强随机值：

```bash
python3 -c "import secrets; print(secrets.token_hex(32))"
# 将输出填入 docker-compose.yml 的 SECRET_KEY=
```

### 3.3 数据备份

```bash
# 手动备份（复制整个数据目录）
cp -r stulink-data stulink-data-backup-$(date +%Y%m%d)

# 定时备份（添加到 crontab，每天凌晨 2 点）
0 2 * * * cp -r /opt/stulink/stulink-data /opt/stulink/backups/stulink-data-$(date +\%Y\%m\%d)
```

### 3.4 资源要求

| 指标 | 最低 | 推荐 |
|------|------|------|
| CPU | 1 核 | 2 核 |
| 内存 | 512MB | 1GB |
| 磁盘 | 1GB（不含数据） | 10GB+ |
| 系统 | CentOS 7+ / Ubuntu 20.04+ | Alibaba Cloud Linux 3 |

## 四、故障排查

**Q: 容器启动后立即退出？**
```bash
docker logs stulink  # 查看错误日志
```

**Q: 5000 端口被占用？**
修改 `docker-compose.yml` 中 `ports` 为其他端口，如 `"8080:5000"`，同时更新安全组规则。

**Q: 数据库被锁定（database is locked）？**
SQLite 仅支持单进程写入，确保只有一个 stulink 容器在运行：
```bash
docker ps -a | grep stulink
docker rm -f stulink  # 清理旧容器后重新启动
```

**Q: 外网无法访问？**
1. 检查安全组是否放行端口
2. 检查防火墙：`firewall-cmd --add-port=5000/tcp --permanent && firewall-cmd --reload`
3. 确认容器正在监听 `0.0.0.0:5000`：`docker logs stulink`

**Q: 忘记 admin 密码？**
在宿主机上运行：
```bash
docker exec -it stulink python scripts/init_db.py
```
> ⚠️ 此操作会重置 admin 密码为 admin123，但**不会**影响已有数据。
