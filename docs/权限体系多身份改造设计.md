## 0. 本次设计要解决的问题

一位老师可能身兼数职，例如：

> 2026级 02班 历史老师（任课教师） **+** 考务管理员（考试管理员） **+** 宿管

现状**做不到**，因为：

| 约束 | 现状 |
|---|---|
| 功能权限 | [User.permission_group_id](../app/models/user.py#L19) 是**单值外键** → 只能挂一个组 |
| 权限判定 | [has_perm()](../app/models/user.py#L55-L62) 只读 `self.permission_group` 一个组 |
| 数据范围 | `scope_type` 挂在**组**上 → 一个用户只有一套范围 |
| 代码依赖 | `role`（单值）在 **35 个文件、108 处**被硬编码当身份判断用 |

### 用户给定约束

1. 支持一人多组；
2. **不允许单人授权，权限归权限组**（不做「给张三单独开一个 key」）；
3. 可自行新增权限组（现已支持，本次保留）；
4. 系统自带 11 个组：管理员（默认）、教务主任、教务员、考试管理员、年级长、班主任、任课教师、生活处、宿管、政教主任、政教员；
   - **生活处 / 宿管**：只管住校相关（宿舍）；**生活处是宿管的上级**；
   - **政教主任 / 政教员**：只管德育（积分 + 奖惩）；
   - 原「校长 / 副校长 / 备课组长 / 教研组长 / 学生发展中心」**已确认删除**。
5. **班主任与任课教师都只能管理本班级**；
6. **专职行政**（无任课安排，如专职教务员、专职考务管理员）需能**单独勾选管理年级**；
7. 多身份用户在**工作台**提供**身份切换**页签，可自行切换；工作台内容随身份变化；
8. 学生画像也需要权限控制；
9. **可自行新增权限组**，新建组与预置组**同权**——范围类型可选：全校 / 本人年级 / 本人班级 / 本人任课 / 指定年级 / 指定班级 / 无。

## 1. 设计原则

### 1.1 三层权限模型

```
① 功能档位   不可见 / 只读 / 写入        （挂在组上）
② 数据范围   类型（组）× 值（用户）      （见 1.2）
③ 字段敏感级 明文 / 脱敏 / 可否导出       （字段级权限点，单独授权）
```

### 1.2 「权限类型」与「范围值」的区分（关键）

| 概念 | 归属 | 载体 |
|---|---|---|
| 有哪些功能权限 | 权限组 | `PermissionGroup.menu_keys` |
| 范围**类型**（全校/任课自动/指定年级/本人班级…） | 权限组 | `PermissionGroup.scope_kind` |
| 范围**值**（具体哪个年级、哪个班） | **用户侧** | 任课安排表 / `UserClassLink` / 用户级勾选年级 |

范围值的**两种来源**（按优先级）：

1. **任课教师** → 自动取「任课安排表」（`TeacherSubjectLink`）中的班级/年级；
2. **无任课安排的专职行政**（专职教务员、专职考务管理员等）→ 在用户后**单独勾选管理年级**。

> ⚠️ **修正**：原稿曾写「教务员组范围 = `self_grade`，取 `user.grade` 字段」，
> 这与「教务员/考试管理员应为**指定年级**」冲突 —— `user.grade` 只有一个值，
> 无法表达「三位考务管理员各管一个年级」。因此范围值必须是**用户级的年级集合**，
> 不能是单值字段。这也是 `UserDataScope` 不能删除的根本原因（见 §2.3）。

### 1.3 「当前身份」语义（核心决策，本稿替代「范围并集」）

```
当前身份 = 用户在多个组中选择的一个（默认 = 主组 is_primary）

可见功能 = 当前身份组的 menu_keys
可见范围 = f( 当前身份组.scope_kind , 用户侧范围值 )
```

- **侧栏菜单、工作台内容、数据范围都随当前身份变化**；
- 切换入口：**顶栏**与**工作台「身份切换」页签**；
- 未主动切换时默认主组；
- **不做「默认全部身份可见」开关**（定稿裁决）：一律按当前身份渲染；
- **基础能力**（如通知收件箱 `workbench.notifications_view`）恒定可用，不随身份变化。

> **为什么不用「并集」？** 并集会让「班主任 + 宿管」在任何页面都同时享有本班与全校两种范围，
> 无法表达「我现在以什么身份做事」，且极易把窄范围放大成宽范围（越权）。
> 身份切换语义更贴近真实岗位，也天然规避放大。

| 场景（班主任·本班 ＋ 宿管·全校） | 以「班主任」身份 | 以「宿管」身份 |
|---|---|---|
| 侧栏菜单 | 班级/学生/本班宿舍 | 全校宿舍/分配 |
| 学生列表 | 本班 | 全校 |
| 班级概览 | 本班 | 无此入口（该组无权限） |
| 宿舍分配 | 无此入口 | 全校 |

## 2. 数据模型设计

### 2.1 新增：用户 ↔ 权限组 多对多关联表

```python
# app/models/user_permission_group.py（新增）
class UserPermissionGroup(db.Model):
    __tablename__ = 'user_permission_groups'
    id = db.Column(db.Integer, primary_key=True)
    user_id = db.Column(db.Integer, db.ForeignKey('users.id'), nullable=False, index=True)
    group_id = db.Column(db.Integer, db.ForeignKey('permission_groups.id'), nullable=False,
                         index=True)
    is_primary = db.Column(db.Boolean, default=False)   # 主组：默认身份 + 显示文案
    created_at = db.Column(db.DateTime, default=datetime.now)
    __table_args__ = (db.UniqueConstraint('user_id', 'group_id', name='uq_user_group'),)
```

- `User.permission_group_id` **保留一个版本做兼容**（迁移期作为主组来源），下个大版本再删；
- 新增 `User.permission_groups`（多组）与 `User.primary_group`（主组）；
- 删除组时校验关联表；`users.py` 列表页按「主组」分组展示。

### 2.2 权限组：范围**类型**（`scope_kind`）

```python
scope_kind = db.Column(db.String(16), nullable=False, default='none')
#   —— 绝对范围（写死，与当前用户无关）——
#   school        全校
#   pick_grades   指定年级（值来自组级 scope_grades 或用户级勾选）
#   pick_classes  指定班级（值来自组级 scope_classes）
#   —— 相对范围（跟人走）——
#   self_grade    本人年级（user.grade）
#   self_class    本人所辖班级（UserClassLink）
#   self_teaching 本人任课自动（TeacherSubjectLink；无记录则回落用户勾选年级）
#   —— 无 ——
#   none          空集（fail-closed）
scope_grades  = db.Column(db.Text, default='[]')  # JSON: ["2025级"]
scope_classes = db.Column(db.Text, default='[]')  # JSON: [{"grade":"2025级","class":"02班"}]
```

> **任何组（含自定义新建组）都从以上 7 种里选一种**，与是否预置无关。
> 权限组管理页的「范围」下拉即这 7 项（用户可见文案：全校 / 指定年级 / 指定班级 /
> 本人年级 / 本人班级 / 本人任课 / 无）。

**旧 `scope_type` 兼容映射**（迁移脚本自动转换，已修正）：

| 旧 `scope_type` | 新 `scope_kind` | 说明 |
|---|---|---|
| `school` | `school` | 全校 |
| `grade` | `self_grade` | 取 `user.grade`（如年级长） |
| `class` | `self_class` | 本人所辖班级 |
| `none` | `none` | 空集 |

### 2.3 保留 `UserDataScope`：降级为「专职行政的范围值来源」

**撤回原稿的删除建议**（采纳评审意见）。理由：

- 专职教务员/考务管理员**没有任课安排**，无法自动推导范围；
- 同一身份组内不同人分管**不同年级**，组上无法区分；
- 故必须有一个「**用户级范围值**」的落点。

语义调整：

| | 旧语义 | 新语义 |
|---|---|---|
| `UserDataScope` | 用户级**权限授权**（单人开权限） | 用户级**范围值**（口径类型仍由组决定） |

**范围解析优先级（用户侧）**：

```
1. 任课安排表有记录      → 范围 = 任课班级/年级（自动）
2. 否则存在用户级勾选年级 → 范围 = 勾选年级
3. 否则                  → 回落组的 scope_kind（school / pick_classes …）
4. 都没有                → 空集（fail-closed）
```

> 这不违反「权限归组」：功能权限仍 100% 来自组；用户级只填**年级值**，
> 且仅在「该组的 `scope_kind` 允许用户级值」时才生效。

## 3. 权限判定改造

### 3.1 `has_perm`：按**当前身份**

```python
def has_perm(self, perm_key):
    if self.role == 'admin':
        return True
    g = self.active_group          # 当前身份（默认主组）
    return bool(g and g.has_menu(perm_key))
```

> 「当前身份」存于 session（服务端），随切换更新；基础能力（通知收件箱）单独放行。

### 3.2 数据范围：收敛为**唯一口径**模块

现状有 **6 套独立实现**，口径互有漂移（历史 bug 来源）：

| 现状实现 | 位置 |
|---|---|
| `apply_student_scope` | [student_scope.py](../app/utils/student_scope.py) |
| `get_scope / visible_grades / check_exam_visible / student_in_scope` | [grades/services/scope.py](../app/modules/grades/services/scope.py) |
| `managed_class_pairs / class_allowed` | [workbench/services/scope.py](../app/modules/workbench/services/scope.py) |
| `_resolve / scope_kind / room_scope_query` | [dormitory_scope.py](../app/utils/dormitory_scope.py) |
| `_scope / _apply_scope` | [points/routes.py](../app/modules/points/routes.py#L23-L57) |
| `scope_of / apply_scope / can_see` | [morality/services/reward_service.py](../app/modules/morality/services/reward_service.py#L56-L109) |

**改造：新增 [app/utils/scope.py](../app/utils/scope.py) 作为唯一口径**，6 处改为薄封装委托：

```python
# app/utils/scope.py（新增）

    grades: set        # kind=grades 时有值

def resolve_scope(user) -> Scope:
    """按『当前身份』解析范围（§1.3）；基础能力组不计入范围。"""
    g = user.active_group
    return _resolve_kind(g.scope_kind, g, user)   # 值取用户侧（任课表 / 勾选年级）

def apply_scope(query, model_grade, model_class, user):
    """把范围条件加到任意查询上（各模块统一调用）"""
```

- 各模块：`apply_student_scope(q, user)` → 内部改为 `apply_scope(q, Student.grade, Student.class_name, user)`；
- `scope_kind=self_teaching` 时：无任课记录 → 回落用户勾选年级 → 仍无 → 空集。

> ⚠️ **本次改造最大的工作量与风险点**。必须逐模块核对，否则出现「有权限但看不到数据」的回归。

### 3.3 `role` 的处理（渐进策略）

| 阶段 | 做法 |
|---|---|
| 本期 | `role` 降级为「主身份标签」，仅供显示与兜底；鉴权改走 `has_perm` + `resolve_scope` |
| 本期 | 把**与数据范围相关**的 `role` 判断（[student_scope](../app/utils/student_scope.py#L27-L42)、[workbench/scope](../app/modules/workbench/services/scope.py#L32-L43)、[assignments](../app/modules/dormitory/routes/assignments.py#L44)、[dashboard](../app/modules/dormitory/routes/dashboard.py#L210)）改为按范围函数判定 |

> `role == 'admin'` 特判**保留**（管理员是系统保留身份，天然全校全权限）。

## 5. 系统自带 11 个权限组建议配置

> 图例：读=只读；写=可编辑；◈=standalone 单独授权；范围见末列。

| # | 组名 | 学生 | 宿舍 | 成绩 | 德育 | 教务 | 画像 | 工作台 | 系统 | 范围 |
|---|---|---|---|---|---|---|---|---|---|---|
| 1 | **管理员**（默认） | 全部+明文+导出 | 全部 | 全部+改分◈ | 全部 | 全部+教师手机◈ | 全部 | 全部 | 全部 | 全校 |
| 2 | **教务主任** | 读+非敏感导出 | 读 | 读+教学管理 | 读 | 读+录入+课表+调课+统一调课+查课导出+问卷 | 读 | 通知 | — | 全校 |
| 3 | **教务员** | 读 | 读 | 读+教学管理 | 读 | 读+录入 | 读 | 通知 | — | **指定年级** |
| 4 | **考试管理员** | 读 | — | 读+教学管理(含划线 `grades.settings`)+**改分◈**+任课映射 | — | 读 | — | 通知 | — | **指定年级** |
| 5 | **年级长** | 读+编辑 | 读+床位 | 读+教学管理 | 读+积分录入 | 读+调课+调课审批(一级) | 读+编辑 | 班级概览+考勤(读) | — | 本人年级 |
| 6 | **班主任** | 读+编辑+明文◈ | 读+床位 | 读+个人查询 | 读(+积分录入) | 读+调课 | 读+编辑 | 全部 | — | **本人班级** |
| 7 | **任课教师** | 读 | — | 读+个人查询 | 读+录入 | 读+调课 | — | 班级概览 | — | **本人班级** |
| 8 | **生活处**（宿舍主管） | 读（脱敏） | 读+统计+房间管理+宿舍分配+床位分配 | — | — | — | — | 通知 | — | 全校 |
| 9 | **宿管** | 读（脱敏） | 读+统计+床位分配 | — | — | — | — | 通知 | — | 全校 |
| 10 | **政教主任** | 读（脱敏） | — | — | 全部（积分+奖惩+规则+导出） | — | — | 通知 | — | 全校 |
| 11 | **政教员** | 读（脱敏） | — | — | 读+录入+导入 | — | — | 通知 | — | 指定年级 |

**要点**：
- **生活处 / 宿管**：均**只管宿舍**，全校范围；生活处为上级，**需要统计报表 / 分配方案等决策功能**（含房间管理与宿舍分配），宿管只做床位分配；
- **政教主任 / 政教员**：**只管德育**，不碰成绩/教务/画像；主任全校（含规则与导出），政教员指定年级；
- **考试管理员**：**给** `grades.settings`（划线模板，含在「教学管理」档内）；**改分归考试管理员**（`grades.score_edit`◈）；
- **教务主任**：**不给**改分（成绩仅「读+教学管理」，无 `score_edit`）；
- 教务员 / 考试管理员 / 政教员 = **指定年级**（各组内不同人可分管不同年级，值在用户侧勾选）；

- 相对现状新增：考试管理员、生活处、政教主任、政教员；**删除**：校长、副校长、备课组长、教研组长、学生发展中心；
- 存量自定义空组「考务数据管理员」→ **更名并入「考试管理员」**。

## 6. 如何「更精确地划分权限」（方法论）

### 6.1 三个正交维度

**维度一：功能档位** —— 先问「能看到吗」，再问「能改吗」
- 三档：不可见 / 只读 / 写入；铁律：**写权限必须配套读权限**。

**维度二：数据范围** —— 先定**类型**，再定**值**
- 类型（组）：全校 / 任课自动 / 指定年级 / 本人班级 / 指定班级 / 无；
- 值（用户）：任课表自动，或专职行政手动勾选年级；
- 原则：**能自动就自动**（任课教师取其课表），减少人工维护。

**维度三：字段敏感级** —— 敏感字段**独立授权**，不跟模块走
- standalone 权限点：`students.view_id_card`、`students.view_phone`、`academic.view_teacher_phone`、`grades.score_edit`；
- 铁律：敏感列导出需「查看 + 导出」双权限。

### 6.2 划分动作清单

1. **先定「处室」再定「人」**：教务处、德育处、总务处、年级组、班级；
2. **每组画「模块 × 档位」表**（第 5 节矩阵），只勾职责所需；
3. **学生个人信息默认脱敏**，仅班主任（本班）与管理员给明文；
4. **批量/导出/删改单独确认**，不因「能看」顺手给「能导」；
5. **范围类型+值分离**：类型归组、值归人（§1.2）；
6. **换岗即换组**，不给人单独开功能权限。

### 6.3 常见坑

| 坑 | 规避 |
|---|---|
| 多身份用「并集」→ 范围被放大 | 用**身份切换**，按当前身份取范围 |
| `none` 被当成「全校」 | `none` 必须是**空集**（fail-closed） |
| 只给写不给读 | 写必配读 |
| 敏感字段有查看权但导出漏控制 | 导出走双权限 |
| 专职行政无任课安排 → 范围为空 | 用户级勾选年级兜底（§2.3） |
| 用户级单值 `grade` 表达多年级 | 用**年级集合**，不用单值 |

## 8. 迁移方案（存量库）

生产 `system.db` 现况：**13 组**（含自定义空组「考务数据管理员」）；班主任组 69 人。

步骤（脚本化、幂等、改库前 `backup_db`）：

1. `CREATE TABLE user_permission_groups`，把现有 `users.permission_group_id` 逐条迁入（`is_primary=True`）；
2. 旧 `scope_type` → 新 `scope_kind`（§2.2 映射，`grade`→`self_grade`）；
3. **保留** `UserDataScope` 记录不动（语义转为范围值）；如需，按 §2.3 优先级校验；
4. 重建 11 个系统组（**不覆盖已有自定义组**，仅补齐/改名缺失项）：
   - 「考务数据管理员」（空组）→ **更名并入「考试管理员」**（迁其已有用户到新组）；
   - 删除 校长 / 副校长 / 备课组长 / 教研组长 / 学生发展中心（**先校验组内无用户**，有则先转移）；
5. 校验：每用户至少一组；范围合法；打印变更清单供人工核对。

> ⚠️ 生产库权限组与种子已整体脱节（见[权限体系说明 §8.6](权限体系说明.md)）。
> 迁移脚本**不得批量覆盖**现有组配置，只做「结构升级 + 缺失补齐」。

## 9. 风险与回滚

| 风险 | 等级 | 缓解 |
|---|---|---|
| 6 处范围解析改委托，口径漂移致「有权限看无数据」 | **高** | 逐模块回归；保留旧函数签名；先本地库灰度 |

| 菜单 300s 缓存未失效 | 低 | 保存/切换后主动 `invalidate_group_menu_cache` |

**回滚**：代码回退 + 从 `system.db.bak-*` 恢复；新增表/字段不影响旧逻辑。
