## 一、维护规则（强制，每次库改动都要写）

**只要发生下列任一改动，就必须在本文件「三、待执行清单」或「四、生产执行记录」追加条目：**

1. 新增 / 修改 `scripts/` 下的库结构脚本（`migrate_*`、`add_*`、`backfill_*`，不限命名）；
2. 模型层增删表、增删列、改类型、改唯一键 / 索引（`app/models/**.py`）；
3. 需要回填、修数据、删表、删列的清理动作。

**每个条目至少写清 5 件事**（照抄表格列即可）：

| 字段 | 说明 |
|------|------|
| 脚本 | `scripts/xxx.py` 相对路径（没有脚本、纯手工 SQL 的要写清 SQL） |
| 库 · 表 | 如 `academic.db / subject_leaders`，多库要全列 |
| 作用 | 一句话（为什么需要这次改动） |
| 运行要求 | 能否在应用运行时跑；**重建表 / 大批回填 / 删表一律要求停应用** |
| 状态 | `⬜ 待执行` → 上线后改 `✅ 已在生产执行 · YYYY-MM-DD` |

**同步动作（缺一不可）：**

- 把脚本加进执行器 `deploy/nas_migrate_pending.sh` 的 `run_mig` 清单（否则上线时会漏跑）；
- 脚本本身要**幂等**（列已存在则跳过 / 回填只处理未处理行），并调用 `scripts/_mig_log.py`
  登记执行结果（新脚本必须带，见第六节模板）；
- 上线执行后在「四、生产执行记录」补一行日期与批次说明。

## 五、执行方式（三种场景）

| 场景 | 用什么 | 要点 |
|------|--------|------|
| 只改代码 / 模板，**无**库改动 | `deploy/hot_update.ps1` | SSH 增量热更新；改 Python 或模板**必须重启容器** |
| 含库改动（加列 / 建表 / 回填） | `deploy/nas_migrate_pending.sh` | 现状快照 → 停容器 → 备份数据 → 临时镜像按序跑迁移 → `check_columns --fix` 兜底 → 启动 → 复核 |
| 版本含大量改动 / 新依赖 | `deploy/nas_update_<版本>.sh`（整包） | 停容器后按序跑迁移 |
| **重建表 / 删表 / 大回填** | 只能用上面两种「停应用」方式 | ⚠️ 应用运行中改 SQLite 会写锁或半迁移 |

要点补充：

- 容器 `/app` **不是**宿主机挂载目录（只有 `stulink-data → /app/data`），`scp` 到宿主机不生效，
  必须再 `docker cp` 进容器；
- 一次性容器跑迁移时**不能**把新代码挂到 `/app`（会盖掉镜像内依赖），正确做法是先把停下的容器
  `docker commit` 成临时镜像再跑；
- 数据回滚：`docker stop` → 用备份目录覆盖 `stulink-data` → `docker start`；
- **新装环境不需要跑这些一次性脚本**：`create_all` + 权限组种子已含最新结构；
  权限组类脚本（`migrate_*_perm_*`）只对存量库有意义。
