# 备份与恢复 SOP（P1 M-09）

> 状态：SOP 文档，本批不执行任何备份删除/异地复制。生产操作按本文逐项确认后执行。
> 文档不写生产地址、账号、口令；执行时用 `<生产数据目录>` / `<备份介质>` 占位。

## 1. 资产清单

| 类别 | 内容 | 频率 | 备注 |
|---|---|---|---|
| 主库 | `system.db`（用户/权限/学生/日志/回收站） | 每日 | 含 PII，必须加密 |
| 成绩库 | `grades.db`（考试/成绩/划线/复核/考务） | 每日 | 最大库，优先校验 |
| 教务库 | `academic.db`（教师/课表/调课/业绩/表单） | 每日 | 调课审批依赖 |
| 其它业务库 | `dormitory.db`、`timetable.db`、`points.db`、`morality.db`、`inspection.db`、`achievement.db`、`forms.db`、`portrait.db`、`history.db` | 每日 | 按实际绑定库清单核对 |
| 上传附件 | `app/static/uploads/`（或后续 `instance/uploads`） | 每日 | 含学生材料，单独加密 |
| 密钥 | `.secret_key`、`.encryption_key`、`.alumni_secret_key`、`.env` | 变更时 | **与数据分开存放**，离线/受控目录 |
| 配置 | `config.py`、`deploy/`、`.env.example` | 变更时 | 不含真实密钥 |

## 2. 3-2-1 原则

- **3 份**：生产库 + 本地备份 + 异地/离线备份；
- **2 种介质**：NAS 卷 + 外置盘/对象存储（加密后上传）；
- **1 份异地**：不同楼宇/不同账号，断网可读；
- 备份文件必须加密（至少 AES-256），密钥不与备份同介质；
- 保留：日备 30 天、周备 12 周、月备 12 个月；迁移前备份单独保留到验收后。

## 3. 日常检查（建议每日 09:00）

1. 最近一次备份时间 < 24h，大小与上一份差异 < 30%；
2. `PRAGMA integrity_check` 返回 `ok`；
3. 关键表计数（students / exam_scores / users）与生产一致；
4. 备份目录剩余空间 > 20%；
5. 失败/缺失立即在企业微信/短信告警（当前无监控，先人工看板）。

## 4. 恢复演练（季度）

> 目标 RPO ≤ 24h，RTO ≤ 2h（单库）；演练在沙箱进行，不覆盖生产。

1. 从异地介质取一份加密备份，校验 sha256；
2. 解密到临时目录，`PRAGMA integrity_check`；
3. 用 `config.py` 的沙箱副本启动（端口避开 5000/5055/5060），检查登录、学生列表、
   成绩单、考务、宿舍 5 个关键页；
4. 对比关键表计数与备份时点记录；
5. 记录演练时间、耗时、失败点、改进项，归档到 `docs/测试报告/`；
6. 演练完成后销毁临时明文副本（安全删除/覆盖）。

## 5. 故障处置

### 5.1 数据库损坏

1. 立即停应用（避免 WAL 继续写）；
2. 保留现场：复制 `.db`、`.db-wal`、`.db-shm` 到隔离目录；
3. 用最近可用备份恢复到新文件，`integrity_check` 通过后再切换；
4. 对比丢失窗口内的操作日志，人工补录；
5. 复盘：磁盘/同步盘/并发写/断电，更新监控项。

### 5.2 密钥丢失

- **加密钥丢失 = 历史身份证/手机号密文不可解**；不要重新生成后继续写入（会造成
  新旧密文混用且旧数据永久不可读）。
- 先从离线密钥备份恢复；确认 key 长度 32 字节、sha256 与记录一致；
- 无备份时，只能从备份库恢复密文，并接受丢失窗口；同时通知数据责任人。

### 5.3 误删

- 优先用回收站 `trash_records`（30 天）恢复；
- 回收站没有的，用最近备份 + 操作日志定位；
- 物理删除前必须先 `archive()` 或导出快照（项目铁律）。

### 5.4 勒索/同步盘污染

1. 断开同步盘与网络共享；
2. 保留只读副本，不要在原目录解密/覆盖；
3. 从离线备份恢复；
4. 轮换所有密钥/口令，检查 `data/` 是否仍被同步。

- 数据责任人：系统管理员；密钥保管人：另指定一人（双人原则）；

- 记录存放 `docs/测试报告/` 或运维台账，不写口令与密钥值。
