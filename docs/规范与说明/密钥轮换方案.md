# 密钥轮换方案（P1 M-08，设计稿）

> 状态：设计稿，**本批不执行轮换**。现行代码已完成密钥路径显式化与缺失 fail-fast
> （见 H-07），但仍是单密钥；直接换钥会导致历史密文与盲索引同时失效。

## 1. 现状与风险

| 项 | 现状 | 风险 |
|---|---|---|
| 加密算法 | AES-256-CBC，随机 IV（身份证/手机号） | 算法本身可用 |
| 密钥来源 | `ENCRYPTION_KEY` 环境变量 > `data/.encryption_key` | 单钥、无版本；换钥无过渡 |
| 盲索引 | `blind_index` / `id_card_index` 的 HMAC key 由 `_ENCRYPTION_KEY` 派生 | **换加密钥会同时改变所有索引**，精确查询立即全落空 |
| 密文格式 | 无前缀 base64（前 16 字节 IV） | 无法区分密钥版本，无法多钥并行解密 |

结论：**不能只加一个 `v2` 前缀就轮换**。必须把「加密钥」与「索引钥」解耦，
并准备重加密 + 重建索引的停机迁移。

## 2. 目标设计

### 2.1 密钥环

```text
ENCRYPTION_KEYS = {"1": "<base64 32B>", "2": "<base64 32B>"}
ENCRYPTION_KEY_ID = "2"          # 新写入使用的 key_id
INDEX_KEY = "<base64 32B>"       # 盲索引专用，独立于加密钥，长期稳定
```

- `ENCRYPTION_KEYS` 只放受控目录/密钥管理服务，不进同步盘、不进 git；
- `INDEX_KEY` 与加密钥分开保管：索引钥泄露只能做等值碰撞，不能解密；
- 旧 key 保留在 keyring 中至少一个备份周期，用于解密历史数据。

### 2.2 密文格式

```text
v2:<key_id>:<base64(iv + ciphertext)>
```

- 无前缀 = 旧格式（单钥时代），按 `LEGACY_KEY_ID` 解密；
- `decrypt()` 先看前缀，再按 key_id 取钥；未知 key_id 明确报错，不回传密文；
- 新写入一律 `v2`，旧数据可渐进重加密。

### 2.3 盲索引

- 索引键固定用 `INDEX_KEY`，**不随 `ENCRYPTION_KEY_ID` 变化**；
- 若必须轮换索引键：需要双索引列/双写过渡，或一次性重建全部 `phone*_idx` /
  `id_card_idx`；重建期间精确查询会短暂失效，必须停机。

## 3. 轮换步骤（未来执行）

1. **备份**：`scripts/_db_backup.py::backup_db` 备份 system.db / academic.db /
   grades.db 等全部含密文的库，记录 sha256；另存密钥环副本到离线介质。
2. **加新钥**：把新 key 加入 `ENCRYPTION_KEYS`，`ENCRYPTION_KEY_ID` 指向新钥；
   重启后新写入即 `v2`，旧数据仍可解。
3. **重加密（分批）**：写一次性迁移脚本，按 500 行/批把旧格式密文重加密为
   `v2:<new_id>:`；每批提交并记录进度；失败可从备份/断点续跑。
4. **校验**：抽样解密、统计 `LIKE 'v2:%'` 覆盖率、跑身份证/手机号精确查询回归。
5. **观察期**：至少一个备份周期内保留旧 key；确认无旧格式读取后再移除。
6. **索引**：若 `INDEX_KEY` 未变，无需重建；若变了，按 2.3 重建并校验。

## 4. 回滚

- 代码回滚 + 保留旧 key：`decrypt` 仍能解旧格式；新格式行需要新代码才能解，
  因此**不要在没有恢复备份的情况下回滚到不认识 `v2` 的旧版本**。
- 数据回滚：恢复轮换前备份；确认 `PRAGMA integrity_check` 与关键表计数。
- 索引回滚：恢复备份中的 `*_idx` 列，或重跑重建脚本。

## 5. 代码改造清单（下一批）

- `app/utils/crypto.py`：`_get_encryption_keys()`、`encrypt_rand` 写 `v2`、
  `decrypt` 按前缀选钥、`blind_index`/`id_card_index` 改用 `INDEX_KEY`；
- `app/models/student.py`、`app/models/academic.py`：无需改列，透明读写；
- 新迁移 `scripts/migrate/reencrypt_v2_*.py`：重加密 + 覆盖率校验 + `_mig_log`；
- 测试：多钥解密、未知 key_id、旧格式兼容、索引稳定性、回滚演练。

## 6. 明确不做

- 本批不生成新钥、不改 `data/.encryption_key`、不重加密任何生产数据。
- 不把密钥写入文档、日志、聊天记录或 `.env.example`。
