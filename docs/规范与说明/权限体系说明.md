## 1. 权限模型（三层）

| 层级 | 载体 | 回答的问题 | 优先级 |
|------|------|-----------|--------|
| ① 功能权限 | `PermissionGroup.menu_keys`（JSON 数组） | **能不能进这个功能** | 基础 |
| ② 数据范围（组级） | `PermissionGroup.scope_type` | 进了之后**能看多大范围** | 低 |
| ③ 数据范围（用户级） | `UserDataScope`（年级 + 可选班级） | 在已获权限内**进一步收窄** | **高**（配置即覆盖组级） |
| ④ 字段权限 | 同 ①（`standalone` 权限点） | 敏感字段**看明文还是脱敏** | 与 ① 同级，独立勾选 |

### 1.1 判定链路

```
路由装饰器 @perm_required('key')
    → current_user.has_perm('key')
        → role == 'admin' ? 恒 True
        → 否则查 PermissionGroup.menu_keys 是否含该 key
    → 不满足 403
```

**要点：**
- 用户**不直接持有**功能权限，必须通过权限组获得；
- `role == 'admin'`（系统管理员）**绕过全部权限点**，配置时无需逐项勾选；
- 权限组变更**即时生效**（菜单缓存 300s TTL + raw 字符串自校验，见 `permission_group.py`）。

### 1.2 数据范围判定顺序

```
admin（全校）
  → UserDataScope（用户级，配置了就以它为准）
    → 权限组 scope_type（组级）
      → 班主任 UserClassLink / 任课 TeacherSubjectLink（模块级补充）
        → 无任何范围 = 空集（fail-closed，不回落全校）
```

### 1.3 scope_type 取值语义

| 值 | 含义 | 典型身份 |
|----|------|---------|
| `school` | 全校 | 管理员组 / 宿管组 / 校长 / 副校长 / 教务主任 |
| `grade` | 仅本人 `user.grade` 年级 | 年级长组 |
| `class` | 仅所辖班级（`UserClassLink`，部分模块回落 `user.grade/class_name`） | 班主任组 / 任课教师组 |
| `none` | **空集**（fail-closed，须靠 `UserDataScope` 授权） | 教务员 / 备课组长 / 教研组长 / 学生发展中心 |

> ⚠️ `none` 是**空集**而非"全校"。这是项目所有范围函数的统一口径（`apply_student_scope`、`room_scope_query`、`check_exam_visible` 等），
> 也是历次审计的整改结论——早期多处 "无权限组回落全校" 是漏洞，已全部收敛。

## 2. 权限档位与自动展开

权限配置页（系统管理 → 权限管理）按「**模块 × 子功能 × 三档**」勾选，保存时由
`permission_map.py` 的三个纯函数转换：

| 档位 | 展开结果 |
|------|---------|
| 不可见 | 空集 |
| 只读 | 该子功能的 `read` keys |
| 写入 | 该子功能的 `read` + `write` keys |

**模块级批量勾选**（`module_levels_to_item_levels`）规则：
- 模块**写入** → 该模块**全部子功能**写入（等于拿到该模块所有 key）；
- 模块**只读** → 仅"有只读档"（`read` 非空）的子功能为只读，其余不可见；
- **例外：`standalone=True` 的子功能不随模块档位批发**，只能单独勾选，默认不可见。

> `standalone` 是"高危/敏感能力"的保护机制：目前有 4 个
> ——`grades.score_edit`（成绩改分）、`students.view_id_card`、`students.view_phone`、
> `academic.view_teacher_phone`（后三个为敏感字段明文查看）。
> 后果：**教务主任/教务员**即使学生模块取"写入档"，也**不会**顺带拿到 `students.view_id_card` /
> `view_phone`（见 §4 与 §5.2 的相互作用）。

## 4. 敏感字段字段级权限（v1.19.49.46）

**背景：** 学生身份证号 / 联系电话此前只有**导出**维度有权限点，**页面展示**维度完全没有控制 ——
只要拿到 `students.view`，学生详情页的身份证号、学生列表 / 宿舍床位卡的联系电话就是明文。

**三个"查看"级权限点**（均为 `standalone`，不随模块写入批发）：

| 权限点 | 归属子功能 | 无权限时显示 |
|--------|-----------|-------------|
| `students.view_id_card` | 学生管理 → 查看身份证号 | `110***********1234` |
| `students.view_phone` | 学生管理 → 查看联系电话 | `138****8000` |
| `academic.view_teacher_phone` | 教务管理 → 教师手机号明文 | `138****8000` |

**实现口径（唯一入口 [sensitive.py](../../app/utils/sensitive.py)）：**
- 模板用 Jinja 全局 `field_value(value, 'id_card'|'phone'|'teacher_phone')` 取值 ——
  **后端决定明文/脱敏**（不是前端隐藏），无权限时直接调接口也只拿得到脱敏值；
- 覆盖 9 个展示点：学生列表 / 详情 / 编辑 / 查询、宿舍床位卡、住宿查询页、
  历史与校友归档页、教师名单 / 课表查询 / 教师编辑页；
- **编辑页保护**：无查看权时手机号渲染为只读脱敏值 + `hidden` 保留原值（否则保存会清空号码）；
- **导出需「查看 + 导出」双权限**（`export_helpers.py` 的 `view_perm`）——
  看不到明文就不允许导出明文，导出弹窗勾选框同步按双权限置灰。

**预置授予（用户口径 2026-10-13：默认只有管理员与班主任可看学生身份证号 / 联系电话）：**

| 权限点 | 管理员组 | 班主任组 | 其他身份 |
|--------|:---:|:---:|:---:|
| `students.view_id_card`（身份证明文） | ✔ | ✔（本班） | ✘ 一律脱敏 |
| `students.view_phone`（联系电话明文） | ✔ | ✔（本班） | ✘ 一律脱敏 |
| `academic.view_teacher_phone`（教师手机号明文） | ✔ | ✘ | ✘ |

> 宿管组原先给过 `students.view_phone`（联系住宿学生），已按该口径**收回** ——
> 宿舍侧的学生敏感字段一律脱敏展示。

> ⚠️ 与 §2 的相互作用：教务主任/教务员因学生模块取"写入档"而持有
> `students.export_id_card` / `export_phone`，但**不含** `students.view_id_card` / `view_phone`
> （standalone 不批发）→ 双权限门槛生效，**实际导不出明文**。这是有意设计。

## 5. 预置身份矩阵

### 5.1 12 个预置权限组

| 组名 | role | 组级范围 | 定位 |
|------|------|---------|------|
| 管理员组 | `admin` | school | 系统保留身份，`has_perm` 恒 True（不可改名/改权限/删除） |
| 年级长组 | `grade_leader` | grade | 本年级学生数据与统计 + 调课一级审批 |
| 班主任组 | `homeroom_teacher` | class | 本班学生与床位 + 工作台全套 |
| 宿管组 | `dorm_manager` | school | 全校宿舍分配与床位 |
| 任课教师组 | `teacher` | class | 所教班级查看 + 个人调课 |
| 校长 / 副校长 | `staff` | school | 全校只读（学生/宿舍/成绩/德育/教务） |
| 教务主任 | `staff` | school | 学生/成绩/教务写入，其余只读 |
| 教务员 | `staff` | none | 成绩/教务写入（数据范围按 `UserDataScope` 勾选） |
| 备课组长 / 教研组长 | `staff` | none | 成绩写入（范围按勾选） |
| 学生发展中心 | `staff` | none | 积分/画像写入 + 学生只读（范围按勾选） |

> 五个 `staff` 系身份的差异**全在 `menu_keys`**，`role` 相同 —— 身份不写死，权限页可随时新增/调整。

1. **通知收件箱全员默认**：所有身份自动追加 `workbench.notifications_view`

   `academic.swap_approve`，与"一级审批应由年级长承担"的设计冲突 → 种子中显式剔除，
   二者只保留终审+执行（`academic.timetable`）。

**读 `UserDataScope` 的模块（已接入）：** 成绩、学生、宿舍、教务、工作台、积分、奖惩、画像、往届、MCP 授权。
**已知未接入（见 §8.3）：** 宿舍统计页已在本轮收口；表单管理/业绩库、成绩任课矩阵与考场房间库仍未接。

## 7. 审批链路（跨模块三条，互不相通）

| 审批类型 | 模块 | 权限点 | 主体（默认） | 级数 | 数据范围 |
|---------|------|--------|-------------|------|---------|
| 调课审批 | 调课 | `academic.swap_approve`（一级）→ `academic.timetable`（终审+执行） | 年级长 → 教务 | 1–2 级（`swap_approval_mode` 可配） | 年级长=本年级；教务=全校 |
| 表单提交审核 | 收集 | `academic.edit` | 教务 | 1 级 | 全校 |
| 业绩审核 | 业绩库 | `academic.edit` | 教务 | 1 级 | 全校 |

**要点：** 审批权不互通；表单/业绩未设独立审批权限点（**能管表单/业绩的人自动能审**）；
调课是唯一多级、可配置、数据范围收敛的审批链。

**两人换课（v1.19.49.46）不新增权限点**：发起仍用 `academic.swap`，但额外要求**对方本人先确认**
（`partner_status='pending'` 时不进待审队列）；确认/拒绝接口仅 `partner_uid` 本人（或管理员）可调。

## 8. 已知问题与死键（诚实记录，供裁决）

### 8.1 口径不一致（非"未过滤"但不统一）

1. **班主任"本班"取数三套不一致**：`student_scope` 用用户表字段（`user.grade/class_name`）；
   `dormitory_scope` 用 `UserClassLink` 且空则回落用户字段；成绩侧 `student_in_scope` 用
   `UserClassLink`（无回落）。**建议后续统一**。
2. **任课教师未纳入宿舍模块范围**——宿舍 `_resolve` 无 `TeacherSubjectLink` 分支。

### 8.2 死键（定义了但无路由使用）

| 权限点 | 位置 | 现状 | 建议 |
|--------|------|------|------|
| `academic.inspection_export` | permission_map 教务·查课导出 | 查课导出路由实际挂 `academic.edit` → 勾选"查课导出"**不生效**，管理端"能录入即能导出" | 让路由改用该 key，或从映射删除 |
| `academic.forms` / `academic.forms_view` | permission_map 教务·问卷收集 | 表单管理端实际用 `academic.edit`、填写端用 `academic.view`；`forms_view` 仅被工作台待办数读取（`todo_service.py`）→ **半死** | 同上 |

### 8.3 未做范围收敛

- **表单管理 / 业绩库**：列表/统计/导出均为全校口径，仅凭 `academic.view`/`academic.edit` 控制，
  `UserDataScope` 不生效 —— 被授予 `academic.edit` 且范围限定某年级的教务员仍能看全校表单与业绩。
- **成绩任课矩阵**（`grades/routes/teachers.py`）与**考场房间库**（`exam_rooms.py`）无范围守卫
  （当前仅管理员组持有相应权限，风险低但口径缺失）。

### 8.4 权限点缺失（有意设计）

- 工作台首页 / 个人信息 / 改手机号 / 提交业绩：仅需登录（本人自助），未设权限点。

### 8.5 种子数据偏差（✅ 已修复 2026-10-13）

**管理员组种子 `menu_keys` 曾漏列 `academic.edit`**（实测：注册表 56 个权限点，管理员组列出 55 个，
唯一缺口为 `academic.edit`）。

- **影响面：仅权限页显示** —— 权限矩阵中「管理员组 × 教务管理 × 录入管理」显示为**不可见**，
  与其"拥有全部权限"的描述不符；其余 40 个子功能均正常显示写入。
- **实际无功能影响**：管理员 `role='admin'`，`has_perm()` 恒为 True，绕过 `menu_keys`。
- **修复**：`app/__init__.py` 管理员组补 `academic.edit`（现 56/56 全覆盖，矩阵无「不可见」项）；
  存量库执行 `scripts/migrate/migrate_admin_perm_academic_edit_20261013.py`（纯显示修正，幂等，改库前自动备份）。
  已部署库若已含该 key，脚本会输出 `[SKIP]` 直接退出。

### 8.6 存量库权限组与种子**整体脱节**（环境事实，非代码缺陷）

**这是本项目的既有特征，配置前必须知道：** `PERMISSION_GROUPS` 种子**只在 `permission_groups`
表为空时写入**，之后不再同步 —— 已部署库的权限组由**人工在权限页维护**，与种子可以任意偏离。

实测某部署库（13 个组，注册表 56 个权限点）：

| 组 | 实际 keys | 与种子的偏离 |
|----|----------|-------------|
| 管理员组 | 45 / 56 | 缺 11 个（`academic.forms*`、`academic.swap*`、`inspection_export` 等）—— 因 `role=admin` 恒放行，**仅权限页显示 11 个子功能为「不可见」**，功能不受影响 |
| 教务主任 | 21 / 56 | 缺 `academic.swap` / `swap_bulk` / `forms*` 等 —— **功能上真的缺失**（如无法提交统一调课） |
| 年级长 / 班主任 / 任课教师 / 宿管 / 校长等 | 7–14 | 普遍少于种子 |
| 考务数据管理员 | **0** | 库中第 13 个**自定义组**（种子无此组），当前未授予任何 key |

**结论与操作建议：**
- **不要**用种子去"批量覆盖"存量库权限组 —— 生产组的偏离可能是**有意收紧**，
  批量同步会意外放开权限；
- 需要对齐时，**按组、按 key 逐项确认后**写针对性补丁脚本（改库前 `backup_db()`）；
- 权限页的「不可见」对 `role=admin` 的组**不代表真的没权限**（恒放行），排查权限问题时先看 `role`。

## 9. 权限变更的落地流程

`app/__init__.py` 的 `PERMISSION_GROUPS` 种子**只在 `permission_groups` 表为空时写入**，
**已部署库不会自动同步** —— 任何权限点/授权变更都必须配一份存量库补丁脚本。

**标准三步：**

1. 改权限注册表 `permission_map.py`（新增/调整子功能与 key）+ 种子 `PERMISSION_GROUPS`；
2. 写幂等补丁脚本 `scripts/<动作>_perm_<日期>.py`（**改 `system.db` 前必须
   `from scripts._db_backup import backup_db` 自动备份**）；
3. 部署时在容器内执行该脚本，再重启服务。

**历史补丁脚本清单：**

| 脚本 | 作用 |
|------|------|
| `init_permission_groups.py` | 首次初始化权限组 |
| `migrate_permissions.py` | 权限体系迁移（早期） |
| `add_role_groups.py` | 补充角色权限组 |
| `add_academic_perm.py` | 教务模块权限点 |
| `add_student_query_perm.py` | 个人成绩查询权限 |
| `migrate_workbench_perms.py` | 工作台权限点 |
| `migrate_score_edit_perm_20261011.py` | 成绩改分 `grades.score_edit`（standalone） |
| `migrate_swap_perm_roles_20261011.py` | 年级长补 `academic.swap` + `swap_approve`；教务主任/教务员剔 `swap_approve` |
| `add_morality_perm.py` | 德育奖惩 `morality.view` / `morality.edit` |
| `migrate_sensitive_perm_20261013.py` | 敏感字段字段级权限 + 最小权限重排（⚠️ 明文授予口径已被 v2 取代） |
| `migrate_sensitive_perm_v2_20261013.py` | **学生敏感字段明文收敛为「仅管理员 + 班主任」**（班主任补身份证、宿管收回联系电话） |
| `migrate_admin_perm_academic_edit_20261013.py` | 管理员组补漏列的 `academic.edit`（纯显示修正，见 §8.5） |

## 10. 权限配置操作指引

1. **配置入口**：系统管理 → 权限管理（`system.perm_groups`），按「模块 × 子功能 × 三档」勾选，
   保存写入 `PermissionGroup.menu_keys`。
2. **数据范围**：权限管理页第二张表（`UserDataScope`）为用户勾选年级/班级，**优先于**组级 `scope_type`
   （`scope_type=none` 的身份完全依赖此表）。
3. **生效方式**：权限组变更即时生效；**新增权限点/装饰器需重启服务**；前端请 `Ctrl+F5` 强刷。
4. **管理员例外**：`admin` 绕过全部权限点，无需逐项勾选。
5. **配置前先看死键**：`查课导出`、`问卷收集`、`问卷收集（查看）` 当前**不生效**（§8.2）。
6. **敏感字段默认最严**：4 个 `standalone` 子功能（成绩改分 + 三个明文查看）默认所有人不可见，
   必须单独勾选 —— 这是"最小权限"的落点，勿图省事批量放开。

### 常见场景配置示例

| 想要的效果 | 配置方式 |
|-----------|---------|
| 某人能看全校学生但**看不到身份证/电话明文** | 给 `students.view`（+ 需要的导出档），**不勾** `查看身份证号` / `查看联系电话` |
| 某人只能改本年级学生、不能导入 | 组级范围 `grade`（或用 `UserDataScope` 勾年级），只给 `students.edit`，不给 `students.import` |
| 班主任看本班身份证号 + 电话 | 组级范围 `class` + `UserClassLink` 配班级，勾 `查看身份证号` + `查看联系电话`（**默认已给**） |
| 宿管管宿舍但看不到学生敏感字段 | 给 `dormitory.*` + `students.view`，**不勾**任何明文查看项（**默认已如此**） |
| 只给床位分配、不给宿舍分配 | 给 `dormitory.beds`，**不给** `dormitory.assign` |
| 教务员管成绩但只管 2025 级 | 组级范围 `none` + `UserDataScope` 勾"2025级"，给 `grades.edit`/`grades.import`/`grades.settings` |
| 让某人能导出成绩单明文改分 | **必须单独勾** `成绩修改（改分）`（standalone，不随模块写入批发） |
