# 教务管理设计手册

> 版本：v1.19.48.29（2026-10-13）｜状态：**核心流程已实现**
> 所属模块：`academic`（独立库：`academic.db` 师资基础 / `timetable.db` 课表与值班 / `inspection.db` 查课 / `achievement.db` 业绩 / `forms.db` 问卷收集 —— 2026-10-10 按「一个功能一个库」拆分）｜页面前缀：`/academic`
> 文档体系：`设计文档.md`（总手册）→ 本手册（模块手册）

## 1. 模块定位与边界

**做什么：**
- 教师名单（基础数据）：Excel 导入、随机唯一编号、身份证加密可后补、账号自动匹配/建号
- 查课统计：巡课记录录入与按年级/教师统计
- 教师业绩库：证书/课题/论文/荣誉/培训记录的录入与审核（教师工作台提交 → 教务审核）
- 学期课表（v1.16.0 起）：学期档案 / 节次与作息配置（一页，含 A4 打印；**节次数量不限**，
  常规时长 **早读 40 / 正课 45 / 晚自习 50 分钟**，可存为「全局作息模板」供各学期复用） /
  班级·年级·教师·全校总课表 /
  整班原样导入（按班级 + 周次批量） / 调课申请与执行 / 历史课表（归档回看） /
  变更历史（版本快照） / 打印（2026-10-10 起原「大课表」页下线，并入「全校总课表」）
- 表单与填报汇总（v1.16.0 起，`/academic/forms`）
- 为教师评分与教师工作台提供基础数据支撑（规划）
- 权限子功能（v1.19.48.29）：`academic.view` / `academic.edit` / `academic.timetable` / `academic.swap` /
  `academic.swap_bulk`（统一调课）/ `academic.swap_approve`（调课审批一级）/
  `academic.inspection_export`（查课导出）/ `academic.forms_view` + `academic.forms`（问卷收集）

**不做什么：** 不直接管理登录账号的密码/权限（账号体系归系统管理）；不做自动排课算法
（只做手工排课 + Excel 导入 + 调课流程）。

## 2. 数据库设计（2026-10-10 分库：academic / timetable / inspection / achievement / forms）

| 库 / 表 | 说明 |
|----|------|
| `academic.db` / `teachers` | 教师名单（`teacher_uid` 随机唯一编号、姓名、身份证密文 id_card_enc（唯一可空）、手机号、学科、状态、user_id 快照） |
| `academic.db` / `subject_leaders`、`work_records`、`attendance_records` | 备课组长登记 / 班主任工作记录（班会/家访/谈话）/ 考勤导入记录 |
| `data/timetable.db`（独立库） | **学期课表（唯一课表体系）**：`term_schedules`（学期/起止日期/教学周）、`period_defs`（节次/作息，**数量不限**，可存为全局模板复用）、`schedule_entries`（条目，含周次范围与软删除）、`schedule_swaps`（调课）、`schedule_versions`（版本快照）、`night_duties`（晚自习值班） |
| `inspection.db` / `inspection_records` | 查课记录（日期、**年级**、节次、教师、班级、科目、结果、检查人、备注） |
| `achievement.db` / `teacher_achievements`、`achievement_attachments` | 教师业绩（类别、名称、级别、取得时间、颁发单位、状态：待审核/已通过/已驳回、提交人/审核人）+ 附件材料 |
| `forms.db` / `form_templates` 等 6 张 | 问卷收集：模板 / 收集轮次 / 题目 / 提交 / 答案 / 分类 |

**分库说明（2026-10-10）：** 原 `academic.db` 一库混装四件事，现按「一个功能一个库」拆为 师资基础 / 查课 / 业绩 / 问卷 四库（课表与值班原已在 `timetable.db`）。跨库只按逻辑键（user_id / teacher_uid / 学号）关联、不建跨库外键；问卷提交与答案（未来最大的两张表）独立成库并补齐索引；迁移脚本 `scripts/migrate_split_academic_20261010.py`（幂等、自动备份、逐表行数校验）。

**快照关联：** `user_id` → `system.db / users`（教师账号关联）；`teacher_uid` 为教务侧主标识。

## 3. 权限与数据范围

**权限边界（permission_map.py）：** 查看（`academic.view`：名单/查课/课表查看）/ 录入管理（`academic.edit`：教师名单、查课、业绩和表单管理）/ 课表管理（`academic.timetable`：学期排课、审批与执行）/ 调课申请（`academic.swap`）。
**字段级（2026-10-13）：** `academic.view_teacher_phone`（standalone）——教师手机号明文查看。
无此权限时，教师名单 / 教师课表查询 / 教师编辑页 / 教师名单导出统一显示脱敏值（`138****5678`，
唯一入口 `app/utils/sensitive.py` 的 `field_value`）；编辑页无权限时手机号只读 + `hidden` 保留原值。
详见《系统管理设计手册》§3.1。
**数据范围：** 查课、实时/新版课表复用成绩模块的 `visible_grades()`，并按可见班级进一步过滤；用户级年级/班级授权和权限组中的班主任、任课教师映射保持一致。教师名单与业绩仍是全校基础数据。调课申请还须匹配申请人的任课课程或负责班级。

**教师-学科关系的唯一依据（2026-10-10）：** 以「任课教师映射」（`TeacherSubjectLink`，页面 `/academic/teacher-links` 与 `/grades/teachers`，权限 key `grades.teachers`）为准；原「任课安排」表 `/academic/duty`（按课表实时聚合，含 `/academic/duty/export` 与 `/academic/api/duty`）已整功能下线、旧地址 404，不再参考或依赖。备课组长（`/academic/leaders`）与晚自习值班（`/academic/schedule/<sid>/night-duty`）不受影响。
**典型身份：** 教务员（成绩/教务写入 + 学生/积分只读，按勾选年级如"仅 2025 级"）；教务主任（全校写入）。

## 4. 核心流程与页面

- **教务工作台** `/academic/`（首页；2026-10-12 用户口径改为**六项实时数据**，取代原静态/占位 KPI）：
  - KPI 六项：**①今日查课 / 本月累计查课**（附**今日查课覆盖率**）· **②今日迟到 / 本月迟到人次** · **③今日缺勤 / 本月缺勤人次**
    · **④待审批调课申请**（按批次折叠，与调课列表、待审徽章同一口径）· **⑤教师业绩待审核** · **⑥材料回收**（回收率 / 待回收份数 / 进行中收集数）
  - **口径**：查课/迟到/缺勤记录经 `apply_academic_scope` 按用户数据范围过滤（与查课页一致）；
    **覆盖率 = 今日已查 ÷ 今日应查**，分母 `_today_expected_cells()` ＝ 启用学期**当天周课表格子数**（全校口径），与查课页 `coverage` 完全一致；当天无课时显示「—」而非 0%。
  - **材料回收** = 对**所有 `status='open'` 的收集**汇总应交/已交（驳回待重交**不算**已交），复用 `form_summary_service.get_submission_stats`；
    **需 `academic.edit`**，无权限者显示「—」；统计异常只记日志、降级渲染（不拖垮工作台）。
  - 待办三项均带一键跳转；下方为「教务主流程」三块（课表 / 查课 / 调课）+ 最近动态（审计日志，按权限过滤）。
- **教师名单** `/academic/teachers`：下载模板 → 上传解析（匹配优先级：身份证 > 手机号 > 姓名）→ 预览确认（新增/更新/冲突/建号计划）→ 落库 + 初始密码清单（CSV）；支持搜索、编辑（身份证仅管理入口可更新）
- **查课** `/academic/inspection`：录入（日期/年级/节次/教师/班级/结果）→ 列表筛选 → 月度统计（次数/异常/按教师）；`/academic/inspection/live-schedule` 按日期和节次核对实时课表，并叠加当天已执行的临时调课。
- **业绩库** `/academic/achievements`：教务录入（直接生效）/ 审核教师提交（通过/驳回）→ 列表筛选
- **学期课表** `/academic/schedule`：创建草稿 → 配置作息和学期日期 → 整班原样导入（一个 sheet 一个班，可按班级 + 周次批量）或手工排课 → 检查班级/教师冲突 → 激活发布 → 归档（写快照并移入「历史课表」只读回看）。新学期默认作息为早读、上午 5 节、下午 4 节和晚自习 3 节（午休不占节次号）；课表格支持学科/教师和自习课。支持单双周、多视图、打印和变更历史；作息表视图内嵌在「作息时间」页（可 A4 打印）。
- **调课闭环** `/academic/swap`：教师或负责班级的班主任提交个人/统一申请 → 课表管理员复核（再次检查冲突）→ 通过后执行。永久调课生成新周课表条目并保留原记录；临时调课只对所选日期生效。普通申请人只能看自己的申请。
- **调课只有两个页面（v1.19.48.29 再次合并，用户口径 2026-10-13）**：
  用户指出「普通调课」与「两人换课」其实是**同一个动作** —— 都是把我的课挪到另一格，
  差别只在于**那一格现在有没有人**：空着就是我挪过去，有人就是和他换（多一步对方确认）。
  因此 2026-10-12 拆出的「两人换课」独立页已**删除**，对调能力并入调课页：

  | Tab | 路径 | 端点 | 干什么 |
  |---|---|---|---|
  | 调课（含与同事对调） | `/academic/swap/apply` | `academic.swap_apply` | 我的课 → 挪到某一格（**空档直接调 / 有人的格就和他对调**），可多节、可与多位老师换 |
  | 请人代课 | `/academic/swap/cover` | `academic.swap_cover` | 我的课 → 请某位老师来上（**可一次请多人代多节**；时间/班级不动） |

  目标格四类（前端 `renderSlots`，接口 `get_available_slots` 逐格返回
  `swappable / swap_self / swap_entry_id / swap_teacher_*`）：

  | 颜色 | 判定 | 点下去的效果 |
  |---|---|---|
  | 绿 | 本班与我都无课（`available`） | 直接调过去 |
  | 黄 | 本班那节是**同事**的课（`swappable` 且非本人） | 与他对调，**需他确认** |
  | 紫 | 本班那节是**我自己**的另一节课（`swap_self`） | **我这两节互换**，不需要任何人确认 |
  | 红 | 我在别处有课（真冲突） | 不可用 |

  紫格（2026-10-13 新增）对应"我自己的两节课对调"：提交**一行**即可（`partner_entry_id`
  指向自己的另一节），后端判 `partner_uid == applicant_uid` → 不设 `partner_status`、
  不发通知、不进"待对方确认"队列，执行时两条一起换位置。
  一次提交可**混着来**（几节调空档 + 几节和不同老师换），共享 `batch_id` 整批审批
  （`apply_swap_batch`）。

- **「无需对方同意确认」默认勾选（v1.19.48.29，用户口径 2026-10-13）**：
  与同事对调时，清单行上有一个选项 —— **默认就是「无需对方同意确认」**：
  - 保持默认（不勾）→ 申请**直接进教务审批队列**，教务通过即生效，对方只收到一条
    **知会通知**（不阻塞流程）；
  - 勾选「需要对方同意确认」→ 才走「对方确认 → 教务审批 → 执行」，未答复前教务看不到。
  落库：`need_partner_confirm = False/True`；免确认时 `partner_status='agreed'` 并写入
  `partner_responded_at`，详情页显示「确认方式：无需对方确认 / 需对方同意」。
  仍强制拦截的情形不变：非授课教师本人发起、同一节课已有待处理申请、与临时调课产生的
  条目对调、两个对调勾选全不勾。

- **教师工作台直接调课（v1.19.48.29）**：`/workbench/` 的「调课」卡片（原「我的调课」）现在能闭环 ——
  - 入口：**调课 / 与同事换课**（`/academic/swap/apply`）、**请人代课**（`/academic/swap/cover`）、**查看记录**；
    入口按 `academic.swap` 权限显示（无权限时只留"查看记录"，与 `perm_required` 同口径，避免点了 403）。
  - **待我确认**：同事发起、指定我配合的换课 / 代课（`get_partner_pending(uid)`），**逐条列出**
    （换课每条各自确认，所以不按批次折叠），可在卡片里直接【同意】【拒绝】（拒绝必填原因，
    走 `academic.swap_partner_respond`）。
  - **我的申请**：一条 `ScheduleSwap` + `batch_rep_filter()` 折叠，一批只占一行。
- **统一调课不再"拉得很长"（v1.19.48.29）**：`/academic/swap/bulk`
  - **按班级分组**：列表按班分组，组头可**整班勾选**、可折叠该班；
  - **只看第几节**：新增节次筛选 —— 一整天的课按节次一筛，列表立刻变短；
  - **吸底操作栏**：已选数量 + 【提交】【清空】常驻底部，不必滚到页面最底；
  - **整体平移 N 节**：新增 `period_offset` 模式，每条落到「自己原节次 + offset」（后移 / 前移 1~3 节），
    解决"一整天的课一起挪、但统一落到同一格必然冲突"的问题；原「统一落到同一格」保留为另一种模式。
    落库口径不变：不平移时留空仍写 `NULL`（执行时沿用原值）。

  三页**共用同一套交互骨架**（修掉"上面能点选、下面却是下拉"的不一致）：
  ① 卡片点选「我的课」（多选）→ ② 清单表格逐行配置（普通调课配目标时段网格 / 换课配对方教师 + 对方的课 + 双方日期 / 代课配代课教师 + 日期）→ ③ 范围与理由 + 预览 → 提交 `items_json`。

  - **取消「换时段 / 换班上课」三选一**（用户反馈二者重复）：统一为「两人对调」语义 + 两个勾选项
    **☑ 对调上课时间（`swap_time`） ☑ 对调上课班级（`swap_class`）**，至少一个：

    | swap_time | swap_class | 语义 | 旧称 |
    |---|---|---|---|
    | ✔ | ✔ | 整条互换：我去上他那节课、他来上我这节课 | 换班上课 |
    | ✔ | ✘ | 只换时间：各上自己的班 | 换时段 |
    | ✘ | ✔ | 只换班级：时间不动，两人去上对方的班 | （本次新增） |

  - **换课有两个日期**（`swap_date` 我这天 / `partner_swap_date` 对方那天）：临时换课不再只认我这一边的日期；
    执行时两侧按各自日期生成「当天条目」（`_execute_exchange_temp` 各取自己的 `isoweekday()`）。
  - **批量**：一次可与**多位老师**换/代**多节** —— 全部记录共享 `batch_id`（整批审批 / 执行 / 撤销），
    每条记录有自己的 `partner_uid` → **各自确认**；`review_swap_batch` 遇到「还有 N 条未确认」时拒绝整批通过；
    提交全成全败（任一行不过则整批不入库）。
  - **流程**：**授课教师本人发起 → 对方在调课管理里确认（同意 / 拒绝）→ 教务审批 → 执行**；
    对方未确认前**不进教务待审队列**（`can_review` / `count_pending` 双重拦截，工作台待办数也不计）。
  - **落位规则** `exchange_plan(e1, e2, kind, swap_time, swap_class, cover_uid, cover_name)`：
    勾了 time 才互换 `(weekday, period_number)`，勾了 class 才互换 `(grade, class_name, subject, room)`，
    **教师始终各归各位**；cover 只替换我方条目的教师。
  - **执行**：临时 → 两侧各生成一条当天条目（`target_entry_id` / `partner_target_entry_id`），查课与今日课表按当天实时叠加、不进常规周课表；
    永久 → 软删两条原条目（各写快照）并各建一条新条目，**撤销执行时两侧一起回退**。
  - **校验** `check_exchange_conflicts`：两侧按各自日期算单双周；本批参与条目整体排除后仍不得与第三方同格撞车；
    两节课**单双周设置必须一致**；批量时额外传 `extra_yield_ids` 避免批内互撞。
    另外拒绝：非授课教师本人发起、同一节课已有待处理申请、与临时调课产生的条目对调、两个勾选全不勾。
  - **数据**：`exchange_kind` 收敛为 `exchange` / `cover`；新增 `swap_time`、`swap_class`、`partner_swap_date` 三列，
    迁移 `scripts/migrate_swap_exchange_v2_20261012.py`（幂等加列 + 旧 `time`/`class` 回填）。
  - **服务入口**：`apply_exchange_batch(items, kind, is_permanent, reason)`（取代原单条 `apply_exchange`）；
    展示：`exchange_content_text()` 产出「整条互换 / 只换时间 / 只换班级」，列表与详情均显示两个日期。
- **统一调课 = 一条记录（2026-10-10）**：一次勾选 N 门课提交后，N 条 `schedule_swaps` 共享一个 `batch_id`，**列表 / 工作台「我的调课」/ 待审徽章都按批次折叠成一条**（`swap_service.batch_rep_filter()`），详情页列出本批全部课程；**通过 / 驳回 / 撤销 / 执行点一次即整批生效**（逐条再次校验冲突，全成全败）。这样"一次调 260 门课"在审批人眼里就是一条记录，不必点 260 次。历史（`batch_id` 出现之前）的批量记录由 `scripts/migrate_swap_batch_20261010.py` 按"同一次提交（微秒级 created_at 相同）+ 同目标条件"回填批次号。
- **新版课表入口：** `/academic/schedule/<sid>/overview` 是全校总课表（查看类页面 2026-10-10 起不再按年级限制，所有年级的课表均可显示；录入 / 导入 / 调课等写入操作仍按授权范围校验）；入口在**学期管理页的学期卡片**上（2026-10-12 起侧栏不再单独挂该入口，原无 sid 的 `/academic/schedule/overview` 跳转路由随之下线、旧地址 404）；`/academic/schedule` 是课表管理员的排课与学期管理入口。
- **课表查询（2026-10-12 新增，统一入口在教务工作台的「课表」块）**：工作台点「课表查询」进入，页内用 tab 在三页之间切换（三个 URL 各自独立，可收藏 / 分享 / 后退；侧栏不再分挂）：`教师课表` `/academic/schedule/teacher`（不带 `?uid=` 是选择态：按学科分组的有课教师墙 + 全量教师下拉；带 `?uid=` 直接出该教师课表）、`备课组课表` `/academic/schedule/lesson-group?grade=&subject=`（年级×学科）、`教研组课表` `/academic/schedule/subject-group?subject=`（学科跨年级）。三个页面**不带 sid**：学期用 `?sid=`（默认当前生效学期，可回看历史学期），星期 `?day=1..7`、周次 `?week=N`。组课表形态为「行＝教师、列＝节次」，格内＝学科 + 任教班级，并给出**当天全组共同空档**（安排集体备课/教研活动用）。成员口径：**按本学期课表条目聚合**（教这个年级/学科的老师就是该组成员），不另建组织关系表，与课表天然一致；组长/教研组长标注取自 `SubjectLeader`（落库数据，仅作标签，不参与成员筛选）。查看类页面，只要求 `academic.view`（与全校总课表同口径），写入仍按 `academic.timetable` 校验。
- **旧版课表** `/academic/timetable`：独立的历史课表库，仍保留导入、增删改能力；与新版课表不联动。旧数据维护时使用，新的学期排课统一使用新版。

**审批权限提示：** 课表管理员持有 `academic.timetable`，可进入审批队列并审批/执行；有 `academic.swap` 的申请人可查看自己的记录并提交申请。两项权限分别管理。

## 5. 与其他模块的数据交互

- **读入：** `system.db / users`（账号匹配：手机号 == username 优先，姓名唯一匹配；`UserDataScope` 数据范围）
- **复用成绩模块服务：** `grades/services/user_account.py`（拼音建号 + 随机密码）——教务导入自动开户共用
- **对外提供：** 教师工作台（我的信息/我的业绩/我的课表，`teachers.user_id` 关联）；成绩模块任课映射经 user_id 自动打通（名单页显示映射数）

## 6. 故障隔离自检

| 场景 | 影响面 |
|------|--------|
| `academic.db` / `inspection.db` / `achievement.db` / `forms.db` / `timetable.db` 任一损坏 | 仅对应功能报错（教师名单 / 查课 / 业绩 / 问卷 / 课表与值班），其余教务功能与其它模块不受影响；教师工作台显示"未关联"提示 |
| 写入范围 | 各功能写各自的库（师资基础 / 查课 / 业绩 / 问卷 / 课表）；建号时写 `system.db`（经用户服务，失败仅该行跳过） |
| 依赖 grades 服务 | 代码级依赖 user_account（若成绩模块代码异常，教务导入受影响；只读使用不涉及数据耦合） |
