# 宿舍自动分配 — 使用手册

> 适用版本：StuLink v1.7.0 · 算法版本 V20260805（平滑动态贪心）

---

## 一、功能概述

宿舍自动分配是 StuLink 的核心功能，帮助宿管人员一键完成全校/全年级的宿舍分配。

**核心思路**：你只需选择「哪些学生要分配」和「哪些宿舍可用」，系统会自动计算最优方案，将班级分配到连续的房间中。

**算法特点**：
- 同班级学生尽量住在同楼层、连续房间（S型序列连续切段）
- 自动处理人数不够一间房的情况（合班机制）
- **全局压力等级制（L=6/7/8）**：宽松优先，床位不足自动升档
- **合班宿舍调整**：自动分解链式合班，合班宿舍更少、管理更方便
- 支持多年级同时分配，高年级低楼层、低年级高楼层

---

## 二、操作入口

```
侧边栏 → 宿舍列表 → 分配宿舍（/rooms/assign-auto）
```

或直接访问：`http://服务器IP:5000/rooms/assign-auto`

---

## 三、操作步骤（4步向导）

### 第1步：选择年级和性别

页面左侧显示所有在校年级（按新→旧排列），每个年级下展示各班级的男生/女生住校人数。

**操作**：
1. 勾选要参与分配的年级（可多选）
2. 系统自动列出该年级所有班级的住校男/女人数
3. 点击「全选男生」/「全选女生」快速勾选
4. 也可单独取消某个班级的某个性别

> 💡 只有标记为"住校"的学生才会出现在列表中。走读生不参与宿舍分配。

### 第2步：选择宿舍房间

**操作**：
1. 选择目标楼栋（如"男生宿舍楼"、"女生宿舍楼"）
2. 选择楼层（可多选，如2层、3层、4层）
3. 系统列出符合条件的所有空闲房间
4. 勾选要使用的房间（或全选）

**页面会实时显示**：
- 已选宿舍数量、床位数（分男/女）
- 剩余空余宿舍数
- 容量是否充足的提示

> ⚠️ 如果提示"有效容量不足"，说明所选房间的床位总数少于学生人数，需要增选宿舍。

### 第3步：预览分配方案

点击「生成预览」后，系统自动计算并展示：

- **分配结果表**：每间房分配到哪个班级、预计住几人
- **宽松/紧张模式**（L=6/7/8，见下文）
- **合班宿舍**（如果有）：用特殊颜色标注
- **日志信息**：详细的计算过程（含合班宿舍调整记录）

**在预览页面你可以**：
- 查看每间房的分配详情
- 如果有合班宿舍，可以手动调整其位置（推挤排序）
- 确认无误后点击「执行分配」

### 第4步：执行分配

点击「确认执行」后：
- 系统将班级信息写入房间记录
- 房间标记上年级、班级、合班信息
- 后续可在「分配床位」页面为具体学生安排床位号

> ⚠️ 执行后如需重新分配，可选择"覆盖模式"清除已有分配。

## 四、分配算法详解

### 4.1 核心原则

| 原则 | 说明 |
|------|------|
| 同班集中 | 同一班级的学生分配在同楼层连续房间 |
| 性别隔离 | 男/女生完全分开计算和分配 |
| 年级分层 | 班级按（年级、班型、班号）排序，高年级先分配 → 低楼层 |
| 宽松优先 | 全局压力等级 L 从 6 开始尝试，能6人绝不7人 |
| 压力均匀 | 所有房间（含合班房）统一按 min(L, 容量) 入住，无“有的房6人、有的房8人”失衡 |

### 4.2 全局压力等级（L=6/7/8）

系统自动计算“全局压力等级”L，决定每间宿舍住多少人：

| 等级 | 模式 | 8人间住几人 | 合班房上限 | 说明 |
|------|------|:---------:|:---------:|------|
| L=6 | 宽松 | ≤6 | ≤6 | 优先：舒适优先，8人间也只住6人 |
| L=7 | 紧张 | ≤7 | ≤7 | 床位不足时整体升档 |
| L=8 | 极限 | ≤8 | ≤8 | 最终兜底：住满 |

- 系统从 L=6 开始，取第一个满足“床位总数 ≥ 学生人数”的等级作为最终方案
- 若实际分配时“房间不足”（收尾班级占房过多），会自动升档重试（每间住更多人、房间消耗更少）
- **所有房间（含合班房）统一升档**：普通房住7时合班房也最多7人，不会出现“普通房6人、合班房8人”的失衡

### 4.3 什么是"合班"？

当一个班级的剩余人数不够单独占一间房时（如只剩3人），系统可能将两个班的剩余学生合并到一间房。

**合班规则**：
- 只有同年级、同班型（普通班/卓越班/强基班分开）的班级才能合班
- 每班最多发起 1 次合班（被借出的班不算发起，可继续发起合班）
- 合班宿舍会记录每个班级各占几个床位
- 例如：`07班+08班` 的房间，可能07班住4人、08班住4人
- 后续分配床位时，会按这个限额分配，防止一个班抢占所有床位

**合班宿舍调整（自动优化）**：
当多个班级连续收尾时，可能产生“链式合班”（如 01班+02班、02班+03班 连续两间合班房，02班在合班房只有1人）。算法在最后会自动执行**合班宿舍调整**：把中间班独立成房，两端班级重组合班，减少合班宿舍数量，管理更方便。例如：

```
调整前: 01班+02班(02班1人)、02班+03班(03班1人)、03班+04班(04班1人) → 3间合班
调整后: 01班+04班(04班1人) + 02班独立6人 + 03班独立6人 → 1间合班
```

调整不改变学生人数、房间数量与宽松/紧张模式，仅在预览日志中记录（`[V20260805-女优化] 合班调整: …`）。

### 4.4 房间分配顺序

房间按 **S 型序列**排序使用：
```
偶数层正向（201→202→…→223）、奇数层反向（323→322→…→301），楼层升序连接
```

同一班级的房间在序列上连续（物理相邻），跨楼层时按 S 型自然衔接。

### 4.5 多年级分配策略

当同时选择多个年级时：
- 班级按（年级、班型、班号）排序：高年级（先入校）优先分配低楼层
- 同班型班级相邻，收尾合班时“下一班”天然满足班型条件，最大化合班可行性
- 各年级在同一全局序列上顺序切段，无需人工分配房间比例

## 五、两种分配模式

在执行分配时，可选择：

| 模式 | 说明 | 适用场景 |
|------|------|---------|
| **保留已有** | 跳过已分配的房间，只分配空房间 | 补充分配（如新增学生） |
| **覆盖全部** | 清除所有已选房间的分配信息，重新来过 | 重新分班、学期调整 |

> ⚠️ "覆盖全部"会同时清除这些房间内的床位分配记录，请谨慎使用。

## 六、常见问题

### Q1：提示"有效容量不足"怎么办？

说明你选择的宿舍房间总床位数 < 学生人数。解决方法：
- 增选更多楼层/房间
- 或减少参与分配的学生（取消某些班级）

### Q2：为什么出现了合班宿舍？

说明在当前房间数量下，无法让每个班都独占整数间房。系统会将两个班的零散学生合并到一间房。这是正常现象，算法会尽量减少合班数量。

### Q3：分配后如何调整？

- **调整房间**：在「宿舍列表」页面可以手动修改某间房的班级
- **调整床位**：在「分配床位」页面可以拖拽/手动安排具体学生到具体床位
- **重新分配**：再次进入自动分配，选择"覆盖全部"模式

### Q4：为什么某些学生没有出现在分配列表中？

只有同时满足以下条件的学生才会出现：
- 住宿类型为"住校"（走读生不参与）
- 班级不是"已转出"或"不分班"
- 年级未被标记为"已毕业"

### Q5：分配结果不满意，可以只重新分配某个年级吗？

可以。在第1步只勾选需要重新分配的年级，模式选"覆盖全部"即可。其他年级的房间不会被影响（只要不选择那些房间）。

### Q6：8人间什么时候住满8人？

系统采用**宽松优先**：默认所有房间（含8人间）只住6人；只有当所选房间的床位不足以容纳学生时，才整体升档为 7 人/8 人。所有房间（含合班房）统一升档，不会出现“有的房6人、有的房8人”的失衡。

## 七、操作建议

1. **先分高年级再分低年级**：如果宿舍楼有限，建议先给毕业班分配（低楼层），再给新生分配
2. **预留空房**：不要把所有房间都选上，预留几间作为后续调整空间
3. **同楼栋同性别**：选择房间时确保楼栋性别与学生性别匹配
4. **分配后检查**：预览阶段仔细查看合班宿舍是否合理，不满意可调整后重新预览
5. **学期初统一分配**：建议在全员到校后一次性分配，避免频繁覆盖
