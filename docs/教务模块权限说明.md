## 0. 权限基础设施（各模块共用）

### 0.1 判定链路

```
路由装饰器 @perm_required(key)  →  current_user.has_perm(key)  →  403
```

`has_perm(key)` 规则（[user.py L55-L62](file:///d:/00同步文件/00程序/stulink/app/models/user.py#L55-L62)）：

1. `role == 'admin'` → **恒为 True**（管理员绕过一切权限点）；
2. 否则查用户所属 `PermissionGroup.menu_keys` 是否包含该 key；
3. 用户**不直接持有**功能权限，必须通过权限组获得。

### 0.2 两层范围模型

| 层级 | 载体 | 作用 | 优先级 |
|---|---|---|---|
| 功能权限 | `PermissionGroup.menu_keys` | "能不能进这个功能" | 基础 |
| 数据范围（组级） | `PermissionGroup.scope_type` | `class`=所管班级 / `grade`=所管年级 / `school`=全校 / `none`=按用户级配置 | 低 |
| 数据范围（用户级） | `UserDataScope`（grade + class_name，class_name 空=整年级） | 在已获权限内收窄可见范围 | **高**（配置即覆盖组级） |

判定顺序：`admin`（全校） → `UserDataScope`（用户级） → `scope_type`（组级） → 班主任 `UserClassLink` / 任课 `TeacherSubjectLink`。

### 0.3 权限档位与自动展开

权限配置页按"模块 × 子功能 × 三档（不可见/只读/写入）"勾选，`module_levels_to_item_levels()` 统一展开：

- 模块**写入** → 该模块**全部子功能**写入（即拿到该模块所有权限 key）；
- 模块**只读** → 仅"有只读档"的子功能为只读，其余不可见。

> ⚠️ 此展开规则是理解"教务主任/教务员为何持有全部教务权限"的关键（见 §8）。

### 0.4 角色清单

| role 值 | 中文名 | 说明 |
|---|---|---|
| `admin` | 管理员 | **系统管理员即此角色**（内置账号 `admin` 的 `real_name='系统管理员'`，权限组名"管理员组"）；恒放行 |
| `school_viewer` | 全校组 | 全校只读 |
| `grade_leader` | 年级长 | 组级范围=本年级 |
| `homeroom_teacher` | 班主任 | 组级范围=本班 |
| `teacher` | 普通教师 | 组级范围=所教班级 |
| `dorm_manager` | 宿管教师 | 全校区 |
| `staff` | 教职人员 | 承载 校长/副校长/教务主任/教务员/备课组长/教研组长/学生发展中心 等**自定义身份**，权限各不相同 |

> **"系统管理员"与"管理员"是同一角色**（`role='admin'`），不存在独立的"系统管理员"角色。

### 0.5 教务工作台（首页 `/academic/`）

- 页面本身：`@perm_required('academic.view')` —— 「教务管理」模块**只读及以上**即可进入。
- 页面内各区域按权限分级（同一页面不同人看到的内容不同，源码 `academic/routes/home.py`）：

| 区域 | 口径 | 要求 |
|---|---|---|
| 今日/本月查课、迟到、缺勤、今日覆盖率 | 记录经 `apply_academic_scope` 过滤（与查课页一致）；**覆盖率分母＝全校当天课次**（不随数据范围缩小） | `academic.view` |
| 待审批调课申请 | 审批人（`admin` 或持 `academic.timetable`）见**全部**待审（按批次折叠）；仅持 `academic.swap` 者只见**自己的**申请；两者都无恒为 0 | 进页面 `academic.view`，数字按左列规则 |
| 教师业绩待审核 / 材料回收（回收率、待回收份数） | 不满足时数字为 0 / 「—」 | `academic.edit` |
| 最近操作动态 | 审批人见全部教务日志；其他用户**仅见本人**操作（按 `OperationLog.user_id` 过滤） | `academic.view` |

## 2. 调课模块权限

源码：[swap.py](file:///d:/00同步文件/00程序/stulink/app/modules/academic/routes/swap.py)、[swap_service.py](file:///d:/00同步文件/00程序/stulink/app/modules/academic/services/swap_service.py)

### 2.1 权限点

| 权限点 | 中文名 | 含义 |
|---|---|---|
| `academic.swap` | 调课管理 | 提交 / 撤销**个人**调课申请 |
| `academic.swap_bulk` | 统一调课 | 批量（整批）调课申请（2026-10-11 从 `academic.swap` 拆出） |
| `academic.swap_approve` | 调课审批（一级） | 分级审批第一级（默认年级长），只审本年级 |
| `academic.timetable` | 课表管理 | 分级审批终审 + **执行调课**（真正落库改课表） |

> 三类权限对应：**普通调课申请** → `academic.swap`；**调课审批** → `academic.swap_approve` + `academic.timetable`；**统一调课** → `academic.swap_bulk`（2026-10-11 起独立，见 §9 问题 1）。
>
> **两人换课（v1.19.47.10）不新增权限点**：发起仍用 `academic.swap`、审批链不变，但额外要求 **对方（partner）本人先确认** ——
> `partner_status='pending'` 时 `can_review()` 直接返回 False（不进待审队列，工作台待办数也不计）；
> 确认 / 拒绝接口 `POST /academic/swap/<id>/partner-respond` 仅当 `_applicant()` 的教师编号 == `sw.partner_uid`（或管理员）时放行，否则 403/闪回。

### 2.2 审批链（可配置）

由系统设置 `swap_approval_mode` 控制：

| 模式 | 链路 |
|---|---|
| `two`（默认） | ① 调课审批（年级长，`academic.swap_approve`）→ ② 课表管理（教务，`academic.timetable`，终审+执行） |
| `one` | 仅 ② 课表管理一级（`academic.timetable`） |

`can_review(sw, user)`：当前用户须持有当前级权限点**且**该调课年级在其可见范围内（管理员与课表终审为全校口径）。

### 2.3 操作主体 / 操作范围 / 约束条件

| 操作 | 操作主体 | 操作范围 | 约束条件 | 权限点 |
|---|---|---|---|---|
| 提交个人调课申请 | 教师（本人任教课程或负责班级） | 仅 `swap_entry_authorizer` 放行的课程 | 须有在用学期课表；须填理由 | `academic.swap` |
| 提交统一调课（批量） | 教务 | 授权范围内课程，多条共享 `batch_id` | 需 `academic.swap_bulk`；任一条越权则整批拒绝 | `academic.swap_bulk` |
| 撤销调课（未执行） | 申请人本人 | 本人记录；带 `batch_id` 时整批 pending 一起撤销 | 仅 `pending` 可撤销 | `academic.swap` |
| 撤销执行（已执行回退） | 教务 / 管理员 | 单条或整批（同 `batch_id`） | 仅 `executed` 可撤销；回退课表后回到「已通过」可重执行 | `academic.timetable` |
| 查看队列/详情/统计 | 申请人 或 任意级审批人 | 申请人看自己；一级审批人看"轮到本级"+自己提交；终审/管理员看全部 | 越界按年级拦截 | 内联 `_require_swap_access()` |
| 一级审批（通过/驳回） | 年级长 | **本年级**，仅 `pending` 且停在本级 | 驳回必填理由；approve 复检冲突 | `academic.swap_approve` |
| 终审 + 执行调课 | 教务 | 全校，仅 `pending` 且走到本级 | 执行前校验状态防重复 | `academic.timetable` |
| 联动 API（可选课程/时段） | 申请权限持有者 | 权限内课程 | — | `academic.swap` |
| 发起两人换课（换时段/换班/代课） | 教师 —— **仅授课教师本人** | 本人的课 + 对方任意一节课（`partner-teachers` / `partner-entries` 只读接口） | 必填理由；两节课单双周须一致；同课已有待处理申请则拒绝；非本人发起拒绝 | `academic.swap` |
| 对方确认换课（同意 / 拒绝） | **对方教师本人**（或管理员） | 本人作为 `partner_uid` 的申请 | 仅 `partner_status='pending'` 且记录仍 `pending`；拒绝必须填原因（会通知发起人） | `academic.swap` |

## 3. 审批 / 审核能力总览（跨模块）

教务侧共有三条相互独立的"审批/审核"链路，权限点与审批主体各不相同：

| 审批类型 | 所在模块 | 审批权限点 | 审批主体（默认） | 级数 | 数据范围 |
|---|---|---|---|---|---|
| **调课审批** | 调课 | `academic.swap_approve`（一级）→ `academic.timetable`（终审） | 年级长 → 教务 | 1–2 级（可配） | 年级长=本年级；教务=全校 |
| **表单提交审核** | 收集 | `academic.edit` | 教务 | 1 级 | 全校 |
| **业绩审核** | 业绩库 | `academic.edit` | 教务 | 1 级 | 全校 |

要点：

- 三条链路的**审批权不互通**：持有调课审批权 ≠ 能审表单/业绩。
- 表单与业绩的"审核"未设独立权限点，与"录入/删除"共用 `academic.edit`，即：**能管表单/业绩的人，自动能审表单/业绩**。
- 调课审批是唯一的**多级、可配置、数据范围收敛**的审批链（`swap_approval_mode` + `review_visible_grades`）。
- **撤销执行**（2026-10-11 新增）：已执行的调课（状态 `executed`）可由持 `academic.timetable` 者撤销，回退课表改动（软删生成条目、恢复被软删原条目），状态回到"已通过"可重执行；统一调课按 `batch_id` **整批回退**。

## 9. 发现的问题（口径不一致 / 待裁决）

以下为**代码实测与设计意图不一致**之处。其中第 1、5、6、8 项已按裁决修复（见各项标注），其余未擅自改动代码，供确认后处理：

1. **「统一调课」无独立权限点**（✅ 已修复 2026-10-11）。原 `/swap/bulk` 与 `/swap/apply` 同挂 `academic.swap`，权限层无法区分"申请"与"统一调课"，普通教师会因可申请个人调课而顺带获得整批调课能力。
   - 修复：[permission_map.py](file:///d:/00同步文件/00程序/stulink/app/utils/permission_map.py) 新增独立权限点 `academic.swap_bulk`（"统一调课"），`/swap/bulk` 改挂该 key；种子与迁移脚本为 管理员 / 教务主任 / 教务员 补 `academic.swap_bulk`，普通教师、班主任、年级长均不具备。

2. **`academic.forms` / `academic.forms_view` 是死键**。在 [permission_map.py L101-L102](file:///d:/00同步文件/00程序/stulink/app/utils/permission_map.py#L101-L102) 定义为"问卷收集"写/读档，但全仓库无任何路由使用（管理端实际用 `academic.edit`、填写端用 `academic.view`）。
   - 影响：配置页勾选"问卷收集"不产生任何效果。
   - 建议：让路由改用这两个 key，或从映射中删除。

3. **`academic.inspection_export` 是死键**。定义在 [permission_map.py L99-L100](file:///d:/00同步文件/00程序/stulink/app/utils/permission_map.py#L99-L100)，但导出路由 [inspection.py L328](file:///d:/00同步文件/00程序/stulink/app/modules/academic/routes/inspection.py#L326-L329) 实际用的是 `academic.edit`。
   - 影响：勾选"查课导出"不生效；"能录入查课"即"能导出查课"，无法只给导出权不给录入权。
   - 建议：让导出路由改用 `academic.inspection_export`，或在映射中删除。

4. **表单管理/业绩库未做数据范围收敛**。列表/统计/导出均为全校口径，仅凭 `academic.view`/`academic.edit` 控制，`UserDataScope` 对这两个模块**不生效**。
   - 影响：被授予 `academic.edit`、数据范围限定为某年级的教务员，仍能查看/导出全校表单与业绩数据。（查课与调课**已**做范围收敛，二者口径不一致。）

5. **年级长不能提交调课申请**（✅ 已修复 2026-10-11）。年级长组种子权限缺 `academic.swap`，[swap.py L86](file:///d:/00同步文件/00程序/stulink/app/modules/academic/routes/swap.py#L84-L87) 会对其申请入口 `abort(403)`。

6. **教务主任/教务员意外持有调课一级审批权**（✅ 已修复 2026-10-11）。因"模块写入"展开把 `academic.swap_approve` 一并赋权，与"一级审批应由年级长承担"的设计表述存在口径差。
   - 修复：[__init__.py](file:///d:/00同步文件/00程序/stulink/app/__init__.py#L289-L294) 新增后处理循环，显式从 教务主任/教务员 组剔除 `academic.swap_approve`（二者仅保留终审+执行）。实测现有部署库中两组本就无该 key，故无回退风险。

7. **工作台首页 / 手机号 / 业绩提交无权限点，仅登录即可**。属有意设计（本人自助），但安全基线依赖"是否为本人数据"的隐式判断，建议在清单中显式登记为"自助免权限项"。

8. **现有部署库权限组整体滞后于种子，导致一级审批在生产失效**（✅ 已修复 2026-10-11）。种子只在 `permission_groups` 表为空时写入，已部署库不同步；实测库中年级长组同时**缺** `academic.swap` 与 `academic.swap_approve`，而 `swap_approval_mode` 为默认 `two`，故除管理员/教务（`academic.timetable`）外无人能审第一级。
   - 修复：`scripts/migrate_swap_perm_roles_20261011.py` 为年级长组补齐 `academic.swap` + `academic.swap_approve`。

## 10. 附：权限配置操作指引

1. **配置入口**：系统管理 → 权限管理（`system.perm_groups`），按"模块 × 子功能 × 三档（不可见/只读/写入）"勾选，保存后写入 `PermissionGroup.menu_keys`。
2. **数据范围**：权限管理页第二张表（`UserDataScope`）为用户勾选年级/班级，**优先于**组级 `scope_type`（教务员等 `scope_type=none` 身份依赖此表）。
3. **生效方式**：权限组变更即时生效（菜单缓存 300s TTL + raw 自校验）；新增装饰器/新权限点需重启服务。
4. **管理员例外**：`admin`（系统管理员）绕过全部权限点，配置时无需逐项勾选。
