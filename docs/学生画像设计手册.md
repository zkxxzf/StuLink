## 1. 模块定位与边界

**规划做什么（方向）：**
- 学习画像：成绩趋势、学科均衡度、进退步分析（数据来源 `grades.db`，按学号只读汇聚）
- 行为画像：积分表现、宿舍表现、出勤记录等综合表现（来源 `points.db` / `dormitory.db`）
- 成长档案：荣誉、教师评语、关键事件记录（本模块自有数据）

**边界原则：** 画像数据**按学号只读汇聚**各模块数据，不改写来源模块；任一来源模块异常时画像降级展示（缺该维度）而非崩溃。

## 2. 数据库设计（portrait.db，3 张表）

模型定义：`app/models/portrait.py`（v1.19.47.29，2026-10-10），建表迁移 `scripts/migrate_portrait_tables.py`。
**注意：早期规划里的 `student_profiles` 占位表在代码中不存在**（只残留在旧版本文档里），实际是三张下表：

| 表 | 说明 |
|----|------|
| `student_portraits` | 画像计算结果：`student_no`（唯一索引 `uq_portrait_student`）、年级/班级快照、`academic_score` / `behavior_score` / `dormitory_score` / `attendance_rate`（Float）、`overall_level`（A~D）、`last_updated` |
| `portrait_comments` | 教师评语：`student_no`、`teacher_id`、`comment_type`（学期评语/操行评语/班主任评语）、`content`、`term`、时间戳；索引 `idx_comment_student`、`idx_comment_term` |
| `portrait_events` | 关键事件：`student_no`、`event_type`（荣誉/违纪/活动/其他）、`title`、`description`、`event_date`、`evidence`（附件路径）、`created_by`、时间戳；索引 `idx_event_student`、`idx_event_type`、`idx_event_date` |

**评分口径（`services/portrait_service.py`，文档补记）：**

| 维度 | 权重 | 计算 |
|------|------|------|
| 学业 `academic_score` | 0.40 | 取最近一场 `subject == TOTAL_SUBJECT` 且 `rank_dir` 非空的成绩；`percentile = (total_count - rank_dir) / total_count * 100`；分段映射 ≥90→100 / ≥70→85+(p-70)×0.75 / ≥50→70+(p-50)×0.75 / else 50+p×0.4。无成绩→50；`total_count<=1`→80 |
| 行为 `behavior_score` | 0.25 | 积分总和 `t`：≥50→100 / ≥30→85+(t-30)×0.75 / ≥10→70+(t-10)×0.75 / ≥0→50+t×2 / 负分 max(0, 50+t×2) |
| 宿舍 `dormitory_score` | 0.15 | **当前硬编码两值**：无宿舍记录→100，有记录→80（宿舍模块暂无检查扣分数据源，该维度实际恒为 100，无区分度） |
| 出勤 `attendance_rate` | 0.20 | 由 `points.db` 中 `category=='纪律'` 的负分积分反推：`max(60, 100 - 扣分合计 × 2)`；无记录→100。**命名与语义不符**（实为"纪律扣分折减率"，无独立考勤表） |

**总分与分级：** `overall = 学业×0.4 + 行为×0.25 + 宿舍×0.15 + 出勤×0.2`；≥90→A，≥75→B，≥60→C，其余 D。
**落库：** upsert `student_portraits`（`IntegrityError` 时 rollback 后重查）；详情/列表按需计算，`/api/<no>/refresh` 可强制重算。

## 3. 权限与数据范围

**实际实现（2026-10-13 校订，原为"待定"占位）：**

| 项 | 口径 |
|---|---|
| 查看 | `portrait.view`（管理员组 / 年级长组 / 班主任组均已含）；写入（评语/事件）`portrait.edit` |
| 数据范围 | 列表与详情统一走 `app/utils/student_scope.py::apply_student_scope`（H-2 唯一口径）：<br>admin / 全校范围 = 原样；年级长 = 本年级；班主任 = 本班；任课教师 = 班级映射 > 任课映射年级 > 组级范围；**无任何范围 = 空集**（不回落全校） |
| 详情守卫 | 每个按学号的入口（详情 / 评语 / 事件 / API）先过 `_assert_student_in_scope`，越权按 404 处理（H-3） |
| 列表可见性 | 排除**已离校**学生：`enrollment_status` 或 `class_name` 被标记为「学籍已转出 / 已转出 / 离校」；**学籍为空（NULL）视为未标记、正常保留** —— 与宿舍模块同一写法（`is_(None)` + `notin_`），严禁裸 `notin_`（SQL 三值逻辑会把 NULL 行整行剔除，2026-10-13 修复：主库 2114 人中 1419 人学籍为空，列表曾只剩 695 人） |
| 分页 | 列表页 20 人/页（翻页保留筛选条件）；JSON `api_list` 的 `per_page` 可传 |
| 画像生成 | 详情/列表按需计算并落 `student_portraits`（`/api/<no>/refresh` 可强制重算） |

## 4. 核心流程与页面

单蓝图 13 条路由（`app/modules/portrait/routes/portrait.py`）：

**实际实现：** 列表页 `/portrait/`（筛选：年级 / 班级 / 评级 A~D + 分页 20 人/页卡片网格，卡上展示画像等级与
学业/行为/宿舍/出勤四条得分条）→ 详情页 `/portrait/<学号>`（维度雷达图 + 成绩趋势 + 积分饼图 + 评语与关键事件管理）；
首页卡片状态仍标"规划中"（文案待同步）。

**图表（echarts 本地 `app/static/js/echarts.min.js`，逻辑因需 Jinja 变量而内嵌在 `detail.html`）：**
- 维度雷达图：四维 `学业/行为/宿舍/出勤`，max 100
- 成绩趋势：**分类轴折线图**（非 timeline 组件），两条 series「总分」实线 + 「年级平均」虚线，取最近 10 场；
  空数据时显示"暂无成绩数据"
- 积分类别饼图（`initPointsPieChart`）

**API：** `/api/<no>/data`（画像完整数据）、`/api/list`（列表 JSON，`per_page` 可传）、`/api/<no>/refresh`（单学生重算，`portrait.edit`）、`/api/options`（筛选项，600s TTL 缓存）。
**输入约束：** 评语类型白名单 `COMMENT_TYPES` + 长度上限（`term`≤32、`content`≤2000）；事件日期格式校验。

## 5. 与其他模块的数据交互

| 来源模块 | 数据 | 方式 |
|---------|------|------|
| 成绩管理 | 历次考试分数/排名/趋势 | 按学号只读（grades.db） |
| 德育管理 | 积分记录/汇总（`behavior_score` 与出勤估算的唯一来源） | 按学号只读（points.db） |
| 宿舍管理 | 住宿与分配表现（当前仅有"有无记录"二值，无扣分数据源） | 按学号只读（dormitory.db） |
| 系统管理 | 学生基础信息 | 按学号只读（system.db） |

## 6. 故障隔离自检

- 独立库 `portrait.db`，来源模块只读汇聚，写入仅本库
- 任一来源模块异常 → 对应维度显示"暂无数据"，其余维度正常
- 本模块损坏不影响任何其他模块（含系统管理）
