## 一、本轮修掉的问题（13 项）

### P0 · 考务 4 条子资源端点只校验「子资源属于该批次」，不校验批次年级归属 → 跨年级越权读写

- 位置：`app/modules/grades/routes/exam_affairs.py` 的 `affair_student_attend`(768)、
  `affair_student_detail`(786)、`affair_room_detail`(947)、`affair_room_delete`(1112)。
- 机理：这 4 处只有 `row.affair_id != aid → 403`；同文件其余 20+ 处都先走
  `_get_affair_checked(aid) → assert_grade_visible(affair.grade)`（H-4 的主入口修了、旁路残留）。
  持 `grades.edit` 的**受限账号**（年级范围 / 班级范围）只要枚举 `aid`，即可读外年级考场与
  学生明细、改写外年级参考标记、**删除外年级考场**（直接影响监考编排依据）。
- 修复：4 处补 `_get_affair_checked(aid)`（`affair_student_fixed` 本就正确，一并核对）。
- 验证（`tests/_archive/qa_20261016/verify_privilege_matrix.py`）：
  - 4/4 跨年级请求 → **403**；
  - **运行时负向对照**：把 `_get_affair_checked` 打成 no-op 后同一请求 **200 且返回 `room_no`**
    —— 证明这条守卫真的在起作用，而不是被权限点顺带挡住的假象；恢复后再 403；
  - 数据层复核：外年级考场仍在、外年级学生 `is_attend` 未被改写；
  - **不误伤**：同一账号访问本人年级考场 → 200。
- 夹具说明：沙箱内没有 grade_leader，测试自建「考试管理员」权限组
  （`scope_kind=pick_grades` + 指定年级）。负向对照**必须**用「功能权限有、范围受限」的账号 ——
  否则去掉守卫后仍被权限点 403 挡掉，对照就成了假象（本次一开始就踩了这个坑）。

### P1 · 查课页「就地调课 / 代课」POST 无任何功能权限点

### UI / 动效面（27 条，摘要）

- **P0**：`base.html` 没有全局弹窗基建（`_openModal` 只有 2 份局部实现、延时还不一致）；
  `exam_detail` 三处裸调 `show()`（成绩单改分是高频 A 关→B 开路径）；
  `.fx-stagger` 硬编码 `opacity:0 + forwards`（动画没跑起来就永久隐身）；
  `bedSwap` 100% 停在橙色 `box-shadow`（当前 fill-mode none 无害，日后加 forwards 即成 bug）。
- **P1**：`transition: all` 共 15 处；`exam_detail` / `grades/index` 工具栏按钮分层违规，
  且有两个**同图标**的「打印」按钮；`bands.html` 10 行说明文字违反「细则进 ⓘ」；
  `stuToast` 落地率极低（35 个模板仍用原生 `alert()`，深色下是系统亮色窗、且阻塞主线程）；
  `.view-pane` 动画挂在常驻类上，重排时会重放。
- **P2/P3**：`table_cols.js` 的 `attach()` 是死代码且有 3 处兼容瑕疵；
  自检的引号正则不跨行；`flex gap` 在旧 X5 会丢间距；打印页 `#999` 对比 2.85:1；
  `.ai-hero-sub` 用 `opacity:.85` 压低对比度。
