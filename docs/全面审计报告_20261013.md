## 1. 一句话结论

> **防御基座依然是这个项目最扎实的部分**（480 个端点 0 处漏保护、CSRF 全局生效、无注入面、密钥无明文兜底、808 项回归全绿）；

> 结构债（超长文件/函数、6 套 scope、重复实现）与 2026-10-10 架构审计时同源，**本轮未继续恶化，但也未收敛**。
>
> **P0 + 部分 P1 已施工（2026-10-13 当天）**：H-1、M-1、M-2、M-7、**H-2、M-3、M-4** 全部修复并附回归；

## 3. 发现清单

> 格式：现象 → 证据（绝对路径:行）→ 影响 → 建议。**🔴 高 / 🟠 中 / 🟡 低**

### 🔴 H-1 · 业绩附件删除缺归属校验（越权删除） ✅ 已修复（2026-10-13，见第 6 节）

**现象**：`academic.edit` 持有者可删任意人上传的业绩附件——只按附件 id 取对象，未做 `can_view` 判定。
**证据**：`app/modules/academic/routes/achievements.py:469-480`（`att = db.session.get(AchievementAttachment, fid)` → 直接 `delete_attachment`）；**同一文件**的预览/下载已经收敛：`:493-498` 调 `ach_svc.can_view(rec, att, current_user)`。
**影响**：跨年级/跨人的**写**操作（附件物理删除不可恢复），是本次唯一"高"。
**建议**：删除前补 `rec = db.session.get(TeacherAchievement, att.achievement_id)` + `if not ach_svc.can_view(rec, att, current_user): abort(403)`（与 `:493-498` 同款）；补回归断言"他人附件删除 → 403"。

### 🔴 H-2 · 跨库写无补偿（写一半成功即不一致） ✅ 已修复（2026-10-13，见第 6 节）

**现象**：同一请求里写两个 bind 的库，SQLAlchemy 各引擎各自提交，中途失败即留下半成品；多数路径无 try/rollback。
**证据**：
- 学生导入同时写 `students`(system) 与 `student_accommodation`(dormitory)：`app/modules/system/routes/students.py:1000-1016、1046-1062`
- 考务同步写 `affair_students`(grades) 与 `students`(system)：`app/modules/grades/routes/exam_affairs.py:761-764`
- 毕业归档先提交 history.db（`:163、:192`）再改 system/dormitory；失败时 `:205` 只 rollback 主库，**历史库已落库行不可撤**（好在 2026-10-12 已修成"归档失败硬中止"，空归档也会拒绝）
**影响**：静默不一致数据（"学生已调班但记录丢失"这一类）。不影响安全，影响**可信度**。
**建议**：① 多步写用 `with db.session.begin()` 或"先算后写 + 失败整体 rollback"；② 归档改"历史库最后提交"或用 staging 表 + 完成后置标记；③ 逐步消灭 246 次裸 commit（当前 rollback 只有 105 次）。

### 🟠 M-1 · 划线模板绑定/解绑考试不校验年级 ✅ 已修复（2026-10-13，见第 6 节）

**现象**：`grades.settings` 持有者可给**任意年级**的考试绑定/解绑分层模板、删模板时还会自动解绑跨年级考试。
**证据**：`app/modules/grades/routes/band_templates.py:256-278`（`Exam.query.get_or_404(exam_id)` 后直接 `set_band_template`，无 `check_exam_visible`/`assert_grade_visible`）；同文件 `:230-253` 删模板时的解绑循环同样不校验。
**对照**：`app/modules/grades/services/exam_guard.py:22-31、34-66` 就是现成口径（`assert_exam_visible` / `assert_grade_visible`，`exams.py:785` 已在用）。
**建议**：两处各加 `assert_exam_visible(exam_id)`；补回归。

### 🟠 M-2 · 考务"从房间库生成考场"绕过范围校验 ✅ 已修复（2026-10-13，见第 6 节）

**现象**：24 处考务路由里 23 处走 `_get_affair_checked(aid)`（校验年级），**这 1 处没有**。
**证据**：`app/modules/grades/routes/exam_affairs.py:1042-1050`（注释里写着 `ExamAffair.query.get_or_404(aid)  # 批次存在性校验`，仅验存在）；对照实现 `:46-55`。
**影响**：可向他年级考务批次写入考场/容量。
**建议**：改调 `affair = _get_affair_checked(aid)`。

### 🟠 M-3 · 宿舍导入错误日志"仅登录即可下载" ✅ 已修复（2026-10-13，见第 6 节）

**现象**：任何登录用户（含普通教师）拿到 key 即可下载含学号/姓名的导入错误明细。
**证据**：`app/modules/dormitory/routes/statistics.py:809-826`（只 `@login_required`）；对照同类功能 `app/modules/system/routes/students.py:1102-1104` 要求 `students.import` 权限。
**建议**：补 `@perm_required(...)`，或把 key 与当前用户绑定后再校验。

### 🟠 M-4 · 日志脱敏只覆盖 8 个显式 logger，31 处未覆盖 ✅ 已修复（2026-10-13，见第 6 节）

**现象**：`MaskingFilter` 是按 **logger 名**安装的，名单只有 `stulink*` + `bands`；而各模块普遍使用 `logging.getLogger(__name__)`，其名称形如 `app.modules.system.routes.students`，**不在名单里**。
**证据**：`app/utils/log_mask.py:54-61`（按名安装）、`app/__init__.py:519-524`（安装名单）；`getLogger(__name__)` 实测 **31 处**（`system/routes/students.py:27`、`utils/helpers.py:15`、`academic/routes/schedule.py:42`、`grades/routes/bands.py:23`…）。
**影响**：这些 logger 打出的异常栈/上下文若含身份证、手机号，会**原样落盘**（`logs/` 下）。
**建议**：把 filter 挂到 **handler**（`logging.getLogger().handlers` 与 `app.logger.handlers`）而不是 logger 名——handler 过滤器对所有传播到它的记录生效，一次覆盖全仓；补一条回归：用 `logging.getLogger('app.modules.xxx')` 打一条含手机号的日志，断言输出已掩码。

### 🟠 M-5 · MCP 服务在局域网 0.0.0.0 暴露 + 无第二道准入 + 失败即锁号

**现象**：MCP 实际配置 `host=0.0.0.0`、`port=8766`、`auth_mode=account`、`require_token=false`、`login_fail_limit=5`（锁 300 秒）。
**证据**：`mcp_server/config.py:15-37`（默认值）；实际 `mcp_server/config.json`（本次**只读解析**，未读取/未输出令牌本体）。
**影响**：① 唯一准入就是真实教师账号口令，局域网任意设备都能反复尝试（无第二道准入）；② **5 次失败锁定作用于真实账号** → 可把某个老师的账号锁死 300 秒（DoS）；③ 服务本身只是降级——口令若泄漏，**成绩数据仍可被读取**。
**已核实不构成风险的部分**：主仓库 MCP 是**只读**成绩分析服务，12 个工具全是查询（`mcp_server/smoke_scores.py:35-40`、`mcp_server/tools/score_analysis.py:2`），未注册任何写工具，故 `allow_write=true`（`mcp_server/config.json`）目前是**预留在 `mcp_server/core/toolkit.py:35-42` 的空开关**。
**建议**：① 改成 `require_token=true`（双重准入）或把 host 收回 `127.0.0.1`；② 认证失败锁定区分来源 IP（或 MCP 侧只做退避延迟、不锁主站账号）；③ 不常用就直接停掉该服务。

### 🟠 M-6 · 7 处 Excel 上传未走统一 `upload_guard`

**现象**：这些点直接 `request.files.get('file')` → `io.BytesIO(file.read())` → openpyxl 解析，**不校验扩展名、不做 magic 嗅探**。
**证据**：`app/modules/grades/routes/exams.py:788-795`（**已逐行复核**：无 guard，直接解析）、`app/modules/academic/routes/timetable.py:106`、`academic/routes/teachers.py:176`、`academic/routes/schedule.py:963`、`grades/routes/teachers.py:241`、`dormitory/routes/dashboard.py:409`、`dormitory/routes/statistics.py:709`（其余 6 处为 `request.files` 直读命中点，抽查 `timetable/schedule/dashboard` 三处写法一致）。
**影响**：不落盘，故无路径穿越；主要风险是**压缩炸弹/畸形文件**在 16MB 限制内耗尽内存（`MAX_CONTENT_LENGTH=16MB` 见 `config.py:45`）。
**建议**：统一改走 `app/utils/upload_guard.py`（已有白名单 + magic 嗅探），每处约 2 行。

### 🟠 M-7 · 现网缺 3 个模型声明的索引 ✅ 已修复（2026-10-13，见第 6 节）

**现象**：`scripts/check_indexes.py` 实测：`academic.teachers` 的 `idx_teacher_status(status)`、`idx_teacher_subject(subject)`、`idx_teacher_user_id(user_id)` 模型有声明、现网不存在（`create_all` 不给已存在表补索引）。
**影响**：`Teacher.query.filter_by(user_id=…)` 是全站高频路径（工作台/教务/成绩多个模块），教师表增大后明显变慢。
**建议**：跑 `py -3.12 scripts/check_indexes.py --fix`（脚本会先备份对应库）；之后把 check_indexes 纳入发布前检查。
