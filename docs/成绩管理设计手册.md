## 1. 模块定位与边界

**做什么：**
- 考试数据管理：考试创建（状态机 draft/imported/dirty）、成绩 Excel 导入（双模板识别、分批覆盖、差异预览）、排名计算（方向内排名）
- 四大分析：年级分析 / 班级分析 / 学科分析 / 任课教师分析（表格 + ECharts 图表）
- 自由透视表：行/列/指标任意组合的交叉表分析
- 划线分层：总分线、单科三线（模板批量应用，比例自动换算为分数线）
- 成绩汇报区：面向校级汇报的五大板块表格 + PPT/HTML 交付物导出
- 考务管理：考场编排（考号规则、选科分组、固定考场）与打印交付（桌签/名单 PDF）
- 个人成绩查询与成绩证明：按权限查询学生成绩、生成带防伪码的证明（公开核验）
- AI 分析（BYOK）：考题分析报告与多轮对话（个人 Key 或全局 Key，数据按权限收敛）

**不做什么：**
- 不修改学生基础信息（学号/姓名/班级等仅作快照引用，写操作只发生在 `grades.db`）
- 不承担教务排课、日常考勤（教务模块职责）
- 成绩证明核验页为公开只读端点（限流 + 脱敏），不做登录要求
- **不做主观评价**：界面不出现对教师/班级/学生的评价性文字，只呈现数值（变动列仅用颜色标注）

## 2. 数据库设计（grades.db，23 张表）

| 分组 | 表 | 说明 |
|------|----|------|
| 考试数据 | `exams` | 考试主档（1 场考试 = 1 年级 × 1 次）；`status`：draft/imported/dirty；`config_json`：分数段宽 band_width、名次段界 rank_bands、科目三线 subject_lines 覆盖、**科目满分覆盖 full_marks**、**考试↔划线模板绑定 band_template_id/band_template_name**；另有 `import_draft`/`import_token`/`import_info`/`operator_id`（导入批次与操作人） |
| | `exam_scores` | 成绩明细**窄表**（一学生一科目一行，含伪科目"总分"行）；快照冗余（姓名/年级/班级/方向/选科），统计/排名无需跨库；唯一约束 `(exam_id, student_no, subject)`；排名列 rank_class/rank_dir/move_rank |
| | `exam_bands` | 划线分层（考试 × 方向 × 科目 × 层序 seq；seq=1 最高层无上界；subject='总分' 为总分线）；`lower_mode`：score/ratio（换算后落库为 score） |
| | `band_templates` | 划线模板（比例/分数模式、层定义、适用考试类型） |
| | `exam_teacher_links` | **考试任课快照**（v1.18.6.0）：考试 × 班级 × 科目 → 当时任课教师（含班主任，用伪科目 `班主任` 占位）；`source`：import/excel/backfill |
| | `score_change_logs` | **分数修改留痕**（v1.19.47.6）：改分/标记缺考的前后值 + 操作人 + 时间；只增不改不删 |
| 教师映射 | `teacher_subject_links` | 年级 × 班级 × 科目 → `user_id`（唯一约束 (年级,班,科)；active 停用保留历史） |
| 考场维护 | `exam_room_groups` | **考场分组**（v1.19.0）：按年级默认高一/高二/高三考场等，跨批次复用 |
| | `exam_room_group_map` | 分组 ↔ 房间库多对多映射 |
| AI 分析 | `ai_keys` / `ai_global_keys` | 个人/全局 API Key（AES 随机 IV 加密存储，接口只回显掩码后 4 位）。**注：主路径已改为「Key 只存本机浏览器」**（`static/js/ai_local.js` + localStorage，服务器不留存），服务端两表仅为兼容保留，见 4.8 |
| | `ai_reports` / `ai_chat_messages` | 分析报告（快照固化，含图表数据；本人可见，管理员可见全部）/ 多轮对话 |
| 成绩证明 | `certificates` | 证明记录（防伪码、快照 content_json（落库前 AES 加密 enc:: 前缀）、生成人/时间、作废标记） |
| | `cert_signing_keys` | HMAC 签名密钥（AES 加密落库） |
| 考务 | `exam_affairs` | 考务批次（编排模式 0/1/2、选科前缀、状态机、`invig_slots` 每考场监考人数 1/2/3） |
| | `affair_rooms` / `affair_students` | 考场 / 考务学生（含编排结果：考场/座号/考号） |
| | `affair_room_libs` | 考场房间库（跨批次复用） |
| | `affair_teachers` | **环节④ 任课核对**（v1.19.43.2）：本场 × 班级 × 科目 → 当时任课教师快照；仅涉及本次考试，不回写全局映射 |
| | `affair_schedules` | **环节⑤ 考试时间表**：时间段 → 考试科目（环节⑥「同科回避」的依据） |
| | `affair_invigilators` | **环节⑥ 其他监考员**：可为无账号的校外老师，仅本场使用 |
| | `affair_invigilations` | **环节⑥ 监考安排结果**：一场次 × 考场 × 监考位 → 教师（一人一格） |

> **表数量说明**：上表共 23 张。早期文档写「15 张」，漏列 `exam_teacher_links`、
> `score_change_logs`、`exam_room_groups`、`exam_room_group_map` 与考务环节④⑤⑥ 的
> 4 张附表（2026-10-12 审计修正）。

**快照关联（跨库无外键）：**
- `student_no`（学号）→ `system.db` 的 `students`：成绩、考务均以学号快照关联，学号不可变
- `user_id` → `system.db` 的 `users`：任课映射与报告归属；被教务模块经 `user_id` 读取（教师任课映射数）
- 换班/转科不影响历史考试统计（"当时在哪个班就以哪个班统计"）；主库改名不追溯历史成绩姓名

> **班级口径（易错点，v1.19.47.6 明确）**：`exam_scores` 里 **总分行** 的 `class_name`
> 是「考试当时的班级」（导入时按 Excel 列写入，是班级统计的唯一依据）；
> **科目行** 的 `class_name` 是「导入那一刻的学生当前班级」。判班级一律用总分行，
> 不要用科目行。

**索引要点：** `exam_scores` 按 (exam_id, subject, class_name)、(exam_id, student_no) 及覆盖索引 (student_no, subject, exam_id)（v1.13.2 性能优化）、`exam_no`（`idx_scores_exam_no`）；`exam_bands` 唯一约束 (exam_id, direction, subject, seq)。

## 4. 核心流程与页面

### 4.1 考试与成绩
1. 创建考试（年级 + 日期 + 类型；同名阻断）→ 2. 下载导入模板（模板 A 全科含总分列 / 模板 B 分科；填表说明）→ 3. 上传解析（**预检不落库**，返回 import_token + 差异预览：新增 X 人/更新 Y 条/缺考删除 K 条/未出现保留 P 人/错误 E 行，可下载错误明细）→ 4. 确认导入（事务写入 + 整场重算排名与进退步）→ 5. 单条修正（改分自动重算该生总分；状态置 dirty）→ 6. 重新计算排名（dirty → imported）

**导入状态机（防误覆盖/并发）：**
```
draft(新建) ──上传+确认──> imported ──单条修正/再次上传──> dirty ──重算/确认──> imported
      └──────────────────< 删除考试（级联）
```
- 模式 A 增量覆盖（日常）：影响范围 = 文件出现的 (学生 × 科目列)；单元格空 = 该科本次缺考（删旧行）；**文件未出现的科目列保留不动**（支持分批补导）；未出现学生默认保留（可勾"一并移除"纠错）
- 模式 B 整场重置（纠错）：清空全场按本次文件重导（输入考试名强确认）
- 上传 16MB 上限，仅内存解析（BytesIO），不落盘；token + 整场事务双重防串批；每次导入写 import_info + OperationLog

**导入解析校验**：表头识别失败/缺学号列 → 整批报错引导模板；年级列不一致 → 行错误（防跨年级混入）；分数越界（非数值/负分/超满分+0.5）→ 行错误；学号未匹配 → 行错误；非应考科目 → 忽略；全行无分 → 提示未参加；**错误行不阻断整批**；借读等学籍状态不剔除仅标注。

### 4.2 划线分层
模板选择（比例制：按参考人数换算分数线；分数制：直接指定，层名可改）→ 应用至考试（按方向/科目独立，考试与模板绑定）→ 分层结果进入各分析与汇报口径。层判定/比例换算/三线口径见[算法手册第 4 章](成绩分析算法手册.md)。

### 4.3 分析（5 个 tab + 方向筛选）
**分析视图全清单（A1~A5，验收依据）：**

| 模块 | 表格 | 图表 |
|---|---|---|
| A1 年级分析 | T1 各班汇总（分层计数动态列）、T2 科目总表、T3 分数段分布、T4 名次段分布、T5 历次考试总览 | G1 班均分对比柱（含年级均值线）、G2 分数段堆叠、G3 班级箱线、G4 历次多折线 |
| A2 班级分析 | T1 班级概况（含年级差）、T2 班-年级科目对标、T3 学生历次明细（含进退步）、T4 分层统计（各层科目均分） | G5 本班 vs 年级柱、G6 总分直方、G7 历次走势（含年级参照线）、G8 各科得分率雷达 |
| A3 学科分析 | T1 学科各班对比、T2 历次统计、T3 总分分层内该科得分 | G9 班级×科目热力、G10 同科各班对比、G11 历次均分/及格率双轴 |
| A4 任课教师 | T1 教师教学数据（班均分/年级差/及格率/优秀率）、T2 历次跟踪 | G12 同科教师对比、G13 本人走势 |
| A5 班级对比（总览） | 班级 × 学科宽表：每科「去差均分 + 各分数线」（上线人数/率竖排），班主任并入「总分」格下方 | 各班去差均分对比柱 |

- **A5 班级对比/全局对比**（`/grades/global-compare`）：班级多选横向对比；分数线可勾选，
  **默认勾选 211线/特控线/本科线**（`DEFAULT_LINE_NAMES`），其余层（清北/985…）勾选才显示；
  列宽尽量压缩（小字号/窄内边距/表头换行），宽表在容器内横向滚动，页面不横向溢出；
  权限与汇报区同档（`_guard_report`）；Excel 导出与页面同口径。
- 导出：各 tab 一键导出 Excel（多 sheet，首 sheet 含口径说明；权限随 grades.view，
  判定复用 `analysis._guard_tab`，保证「能看就能导」）
- 打印：浏览器打印仅当前激活 tab（A4 横向、表格分页表头重复、图表固定打印宽）；
  全局打印基线在 `base.html`（导航/侧栏/按钮一律不打印），各页面只需给业务控件加 `.no-print`
- 图表主题：蓝 #3b82f6 系，物理蓝/历史紫分色；所有均值/率保留 1 位小数，排名整数；空值"—"，变动列仅颜色不评价
- **分批导入提示**（2026-10-12 新增）：模式 A 分批补导中途，成绩单页顶部显示
  「本场科目尚未导齐：还有 X 未导入…当前总分＝已导入科目合计，与导完后的总分不可比」。
  后端数据来自 `stats_service.ExamData.partial_import()`（早前已下发到 4 个分析接口的
  `meta.partial`，页面一直未消费）。

### 4.4 自由表（pivot）
行维度（班级/科目/层）× 列维度 × 指标（人数/均分/去差均分/上线/双上线/层内占比…）任意组合

### 4.5 汇报区（v1.13.x）
- 板块一 各科层上线（含对比考试与去差均分）｜板块二 班级概况｜板块三 单班各科｜板块四 单科各班｜板块五 压线提醒（临界生名单，含班主任/方向排名）
- 列级排名勾选、任课教师名次标注；交付物导出：独立 HTML / PPTX（python-pptx 服务端生成）
- 权限：仅管理员 / 校级 / 年级长（或用户级范围配置者）；缓存 15 分钟，改分/划线后统一失效
- **临界生对比**（`/grades/exams/<id>/near-line`）：与板块五同源计算
  （`report_warning_service.near_line_report()`）。参数 `direction` / `layer` /
  `above`（线上 N 分，默认 10）/ `below`（线下 M 分，默认 20），上限 `NEAR_LINE_MAX=100`。
  展示：概览卡 → 班级对比矩阵（线下/线上/合计 + 占比条）→ 临界生明细
  （含各科、距线、方向排名）。未划线考试显示提示而非报错。

### 4.6 考务管理（v1.12.1+，v1.19.43.2 扩为 7 环节）
考务向导页 `/grades/affairs/<aid>`，7 个页签 `#t1`~`#t7`；左侧悬浮栏同步渲染
**7 个环节圆点**（只亮当前所处环节，已完成但非当前的用浅绿勾），当前环节由 URL hash 决定
（点页签用 `history.replaceState` 写 hash，不触发屏幕滚动）。

| 环节 | 页签 | 做什么 |
|---|---|---|
| ① | `#t1` 学生名单 | 模板预填/导入；字段：学号、姓名、班级、选科组合、是否参与考试、固定考场、固定座号、自定义考号。同步口径：只收「本年级 + 数字教学班 + 未毕业」 |
| ② | `#t2` 考场设置 | 编号/位置/适用选科/容量/前缀；"默认/通用/空"科目对所有选科开放。改考场/科目/容量后「编排容量 + 选科明细」**实时重算**（`GET /affairs/<aid>/stats`），明细默认展开 |
| ③ | `#t3` 编排与考号生成 | **模式 0** 前缀+考场号+座号；**模式 1** 考号=学号；**模式 2** 自定义。规则：先安置固定考场/座号学生，其余按选科分组、**同班邻座 ≤1**；支持「按成绩分层编排」（用上一场同阶段方向排名做容量累积分段）；容量不足日志提示 |
| ④ | `#t4` 核对任课教师 | 首次进入自动带入当前任课映射；可逐格改派（应对临时换老师 1-2 月）。**仅涉及本次考试**，不回写全局 `TeacherSubjectLink`；结果落 `affair_teachers` |
| ⑤ | `#t5` 考试时间表 | 时间段 → 考试科目（`affair_schedules`）。**这是环节⑥「同科回避」的依据**；科目须落在科目字典内 |
| ⑥ | `#t6` 编排监考表 | 教师池 = 环节④ 任课教师（去重）+ 其他监考员（`affair_invigilators`，可为**无账号的校外老师**，仅本场使用）。每考场监考人数 1/2/3（默认 1，`invig_slots`）；**监考表一人一格**；回避规则：某场次科目=化学 → 任教化学的老师不排该场次；同一场次一人只监一个考场；按负载最轻者贪心轮转。编排前做**容量预检**：总格数 vs 单场可排教师数，不足时明确报「缺 N 格」而非静默留空 |
| ⑦ | `#t7` 导出 | 按班级/按考场名单、竖版桌签（格式与 Excel 宏一致）+ **监考表 Excel / PDF**。成绩关联：绑定同年级考试后按考场查看总分/排名/进退步，缺成绩标"缺" |

**考号唯一性**（2026-10-12 新增）：自定义考号导入时校验文件内重复 + 与名单已占用冲突，
冲突即拒绝该行并回报，不再静默入库（同考号会污染按考号回溯的成绩关联）。

### 4.7 个人成绩查询与成绩证明（v1.10 / v1.12.2）
按学生查询历次成绩与趋势 → 生成证明（快照固化 + HMAC 防伪码 SL+日期+随机码+签名段）→ 打印页/公开核验页 `/grades/cert/<code>`（按 IP 限流、脱敏展示：隐藏学籍号、身份证仅显示前3后4）→ 证明台账（作废管理）。快照 `content_json` 落库前 AES 加密（`enc::` 前缀，签名绑定明文，旧码兼容）

- **打印权限**（2026-10-12 审计 H-4 修正）：`/student-query/cert-print/<code>` 原只校验
  `grades.student_query`，任意持该权限者可打印他人完整证明（含完整身份证号）。
  现与作废接口对齐：**仅生成人或管理员**可打印。
- **审计留痕**：证明生成/作废均写 `log_operation`（含学生、范围摘要、防伪码）——
  这是对外法律效力文书，必须能回答"谁给谁开了证明"。

### 4.8 AI 智能导入（v1.19.x）
成绩导入页 / 侧栏「AI 智能导入」→ 拖入任意格式表（可多选，最多 8 个）→ 服务端 probe
（表头按"文本单元格最多且最早出现"的行识别 + 3 行样本）→ AI 只做「列映射 + 分数类型判断 +
待确认问题」→ 页面展示 AI 结论，用户确认/微调（每个工作表可改"这份是：赋分/原始/两者"）→
确定性引擎解析全量 → 预览 → 写入。

- **双文件双轨合并**：赋分表进主分、原始表进 `raw_score`；只有原始分的学生主分顶上
- **无 AI Key 时**：跳过 AI，遍历所有列提供"对应字段"下拉，手工指定后同样能导入
- **三类表都能导**：成绩表 / 分数线表（→ 本场分层划线）/ 考务表（考生名单·编排结果·考场设置
  → 本场考务批次，没有则自动创建）
- **图片 / 监考表识别 → 划分场次**（v1.19.47.4）：除成绩表外，还支持两种「场次」来源 ——
  ① **考试时间表图片**（截图/照片 → 交视觉模型 `chat_with_image` 识图，只输出场次）；
  ② **监考表 Excel**（多级表头：日期行 / 时间行 / 科目行 + 数据行含考场与监考老师）。
  两者都解析出「日期 + 开始/结束时间 + 科目」写入本场考务的**环节⑤ 考试时间表**
  （`affair_schedules`，即"划分场次"）；监考表若带监考老师，顺带写环节⑥。
  仍遵循同一原则：**AI 只做识图/判表，结构化落库由确定性代码负责**
  （`looks_like_schedule_sheet` / `parse_schedule_sheet` / `parse_schedule_json`）。
- **防误覆盖**（2026-10-12 新增）：本场已有成绩且选「整场覆盖（模式 B）」时，
  必须输入当前账号密码二次确认，避免一次误点清空整场成绩
- **体积上限**：单文件 5MB、全部文件合计 40MB、草稿落库前 8MB（超限要求分批）；
  解析行数上限 `MAX_SCAN_ROWS=4000`
- 接口：`POST /grades/exams/<id>/ai-import/analyze`（multipart，`ai` 字段带本机配置）、
  `POST /grades/exams/<id>/ai-import/apply`（`dry_run` 预览 / 正式写入）

### 4.9 AI 分析（BYOK，v1.9.0 已实现）
- **Key 管理（双轨）**：
  - **主路径（推荐）**：Key 只存**本机浏览器**（`static/js/ai_local.js` + localStorage），
    服务器只用不存、不写日志；服务端 `_client_ai_cfg` 直接透传请求体里的 Key。
  - **兼容保留**：服务端 `ai_keys`（个人）/ `ai_global_keys`（管理员全局兜底），
    AES 随机 IV 加密存储，接口回显掩码（后 4 位）。
  - 服务商默认 DeepSeek，支持自定义 OpenAI 兼容地址（出站地址须过 `url_guard` 白名单）。
- **高级参数**：`max_tokens`（输出上限）/ `max_input`（输入上限）/ `reasoning_effort`（思考强度）。
- **发送数据（权限收敛）**：只发**本次 + 上一次同年级考试**的原始成绩；管理员/年级长=全年级、班主任=所辖班、任课教师=本人任课（科目列只含任教科目）；发送前预览确认（考试/范围/人数/Key 来源），数据出内网前弹窗明示
- **报告**：落库 `ai_reports`（受限 Markdown 渲染防 XSS）；标注"AI 生成，仅供参考"；历史入口可按考试筛选/删除
- **转发**：标准库 urllib 直连（零新增依赖），180s 超时，支持 SSE 流式输出与视觉调用（`chat_with_image`）；错误码中文化；Prompt 强约束"仅依据提供数据，禁止编造"
- **概览口径**：报告概览的「及格率」读**本场考试自己的总分行及格线**（与成绩分析/汇报区同口径），
  未划线则显示「-」，不再用"六成最高分"拍一个数（2026-10-12 修正）。

### 4.10 任课教师映射
- 网页矩阵：选年级 → 科目行 × 班级列 → 单元格下拉选教师（仅启用账号）→ 整行设为/整列填充 → 保存全部（预览绑定/变更/停用）
- 批量导入（同构《教师安排表》横表）：多年级区段解析（英语→外语别名；忽略非高考科目/正副班/教室等列）→ 逐 (年级,班,科) 按**姓名**核对账号：命中启用 → 绑定；停用/重名 → 错误行；无账号 → **自动开户**（real_name 固定、账号=拼音可改、随机初始密码、强制改密）→ 预览开户清单（密码一次性可见，可下载《账号开通清单》）→ 确认生效

### 4.11 选科维护与考场维护（基础配置）
- **选科维护**（`/grades/subjects`，权限 `grades.subject_mgmt`）：按班级列出学生，批量修改选科组合。
  保存时逐条校验学号归属本次提交的 (年级, 班级)，并先过 `assert_grade_visible`。
  **注意**：只写主库 `Student.subject_selection`，**不联动任何历史考试**（历史快照不动），
  但会影响今后导入时的应考科目推断。
- **考场维护**（`/grades/rooms`）：左（全部房间）— 中（箭头）— 右（分组）三栏；
  容量属每场考务（不同考试/年级容量可能不同），房间库按多对多分组跨批次复用，

## 6. 故障隔离自检

| 场景 | 影响面 |
|------|--------|
| `grades.db` 文件损坏/锁定 | 启动时逐库建表容错仅告警；成绩/汇报/考务/证明页面报错；**登录、系统管理、宿舍、教务（除任课映射数展示）不受影响** |

  1. `visible_grades()` 按年份**降序**返回年级 → 分析页默认选「第一个有考试的年级」＝**最新年级**；
  2. 本场 id 不在该年级的考试列表里 → 考试下拉回落「该年级最近一场已导入」，**页面显示的是别的考试成绩**，侧栏标题却是本场；
  3. `syncExamNav()` 随即把侧栏链接也改写成那场考试 → 于是「来回点」每次都被送回最新成绩。
  修复：`fillGrades()` 用页面 `#gInitialExam`（即 `?exam=`）**反查所在年级**再选中；`?exam=` **仅在首次填充生效**
  （用户手动切换年级/考试后不再被拉回本场）；侧栏「成绩分析」文字入口（领导=总览、其余=班级分析）纳入 `syncExamNav()` 同步；
  考试详情页四步卡片与「下一步：成绩分析」按钮补 `exam=<id>`（此前无参数 → 落到全局最新）。
- **本场不可见的兜底（v1.19.47.7）**：`?exam=` 指向已删除 / 超出数据范围 / 已毕业的考试时，四个分析页
  **不再静默回落最近一场**，而是恢复年级/考试下拉并在筛选栏上方显示警示条
  （「本场考试不可见（可能已删除或不在您的数据范围），已改为显示最近一场，请重新选择。」），
  避免用户把最新成绩误当成本场数据。

### B. 考试数据模型扩展（赋分/原始双轨）

| 字段 | 位置 | 含义 |
|---|---|---|
| `exam_kind` | `exams` | 性质：联考 / 本校考 / 小测验 |
| `score_mode` | `exams` | 本场口径：`converted` 赋分 / `raw` 原始分 |
| `raw_score` | `exam_scores` | 原始分（仅展示，不参与划线/排名） |
| `exam_no` | `exam_scores` | 考号（索引 `idx_scores_exam_no`） |

- 主分 `score` = **本场口径分**（划线、排名、上榜用）；`raw_score` 并行保存
- 迁移脚本：`scripts/migrate_exam_four_stage.py`（幂等，`--apply` 落盘）
- 四步进度三处同口径：详情页顶部 `_four_step_status()` / 列表页 `_list_steps_map()`（两条聚合查询，无 N+1）/ 侧栏 `exam_nav()`

### C. 考场分层编排

`app/modules/grades/routes/exam_affairs.py::_arrange(affair, students, rooms, mode, log, layered, rank_map)`：

1. **固定座位优先**（`fixed_room` + `fixed_seat`）占据座位，自动分配跳过
2. 按**选科组合**分组（`selection_mode='selected'`）
3. `layered=True` 时：组内按**上一场同阶段考试**的校内**方向排名**升序 →
   考场按 `room_no` 排序、座位从前往后取**首个空位** → 实现**容量累积分段**
   （前 N 个考场共 M 座 ⇒ 第 1~M 名）
4. 排名来源 `_prev_stage_rank_map(affair)`：同年级 + 同 `exam_type` + 日期更早的最近一场，取总分行的 `rank_dir`；**无数据则退化随机**（不阻断）
5. 入口：考务页「按成绩分层编排」勾选 → `POST /grades/affairs/<aid>/arrange` 带 `layered=1`
6. 验证：`python -m scripts/smoke_affair_arrange`（5 组用例）

### D. AI 智能导入

```
成绩导入页 / 侧栏「AI 智能导入」→ 拖入任意格式表（可多选）
   → 服务端 probe（表头按“文本单元格最多且最早出现”的行识别 + 3 行样本）
   → AI 只做“列映射 + 分数类型判断 + 待确认问题”
   → 页面展示 AI 结论，用户确认/微调（每个工作表可改“这份是：赋分/原始/两者”）
   → 确定性引擎解析全量 → 预览 → 写入
```

- **双文件双轨合并**：赋分表进主分、原始表进 `raw_score`；只有原始分的学生主分顶上
- **无 AI Key 时**：跳过 AI，遍历所有列提供“对应字段”下拉，手工指定后同样能导入
- 接口：`POST /grades/exams/<id>/ai-import/analyze`（multipart，`ai` 字段带本机配置）、
  `POST /grades/exams/<id>/ai-import/apply`（`dry_run` 预览 / 正式写入）

### E. 临界生对比

- 页面：`GET /grades/exams/<id>/near-line`（服务端渲染）
- 参数：`direction` / `layer` / `above`（线上 N 分，默认 10）/ `below`（线下 M 分，默认 20），上限 `NEAR_LINE_MAX`
- 计算：复用 `report_warning_service.near_line_report()`（与汇报区「压线提醒」同源）
- 展示：概览卡 → 班级对比矩阵（线下/线上/合计 + 占比条）→ 临界生明细（含各科、距线、方向排名）
- 未划线考试显示提示而非报错
