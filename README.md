# StuLink - 智联校园学生管理系统

[![License](https://img.shields.io/badge/license-Apache%202.0-blue.svg)](LICENSE)
[![Python](https://img.shields.io/badge/python-3.11+-green.svg)](https://python.org)
[![Flask](https://img.shields.io/badge/flask-3.x-lightgrey.svg)](https://flask.palletsprojects.com/)
[![Version](https://img.shields.io/badge/version-1.19.57.64-orange.svg)](https://gitee.com/zkxxzf/StuLink)

面向中学的综合学生管理平台，采用 **双站点 + 多模块 + 一模块一库** 的故障隔离架构：

- **在校生系统（主应用 :5000）**：系统管理 · 宿舍管理 · 成绩管理 · 德育管理 · 教务管理 · 教师工作台 · 学生画像 · 通知中心
- **往届生查询（独立应用 :5001）**：毕业生数据快照查询 · 学习经历变迁 · 宿舍历史
- **MCP 服务（独立容器 :8765）**：给 AI 客户端（IDE 插件 / 桌面应用 / 豆包）开放成绩分析只读工具，权限与网页端一致

> **状态图例**：✅ 已实现（功能完整、生产中可用）｜🚧 部分实现 / 待完善（主体可用，有明确未完成项）｜📋 规划中（尚未开始）

## 三、宿舍自动分配算法（V20260805 · v8 迭代爬山版）

平滑动态贪心 + 全局压力等级制 + 迭代爬山选优：

- **压力等级 L=6/7/8**：按所选房间总数与总人数自动判定宽松/紧张模式，无需人工调参；宽松优先（L=7，8 人间只住 7 人），房间不足自动升档 L=8 保证分配成功
- **动态前瞻**：分配时检查后续容量，压力均匀分散；班级连续切段（S 型序列，偶数层正向 / 奇数层反向）
- **合班被动触发**：班级收尾剩 1~3 人时与下一班（同性别 + 同年级 + 同班型）合并，两班不分主次；每间合班房 ≤2 班、每班最多发起 1 次
- **合班调整优化**：自动拆分链式合班，减少合班宿舍数量
- **床位填充优先级**：小容量房间优先住满；独享宿舍满后才允许合班；合班按份额分配
- **迭代爬山**：初稿（严格分级贪心）+ 迭代爬山 + 全局评分选优；7 项权重前端可调；连续 20 轮未刷新最优自动收敛；满 8 惩罚消除"8 人满 vs 6 人"并存

详见 [宿舍分配算法手册](docs/设计手册/宿舍分配算法手册.md)。

## 四、项目架构

```
双站点部署：
  :5000 — StuLink   在校生管理系统（读写）
  :5001 — Alumni    往届生查询系统（只读 history.db）
  :8765 — MCP       成绩分析工具服务（给 AI 客户端）

一模块一库（物理隔离，快照字段关联，不建跨库外键）：
  data/system.db       基础库（用户/权限组/字典/学生/班级档案/年级/操作日志）
  data/dormitory.db    宿舍库（房间/床位/住宿信息）
  data/history.db      历史库（毕业生快照 + 学习经历变迁 + 分配流水）
  data/grades.db       成绩库（考试/成绩/分层/任课映射/考务/AI/证明）
  data/points.db       德育库（加减分记录/规则模板）
  data/morality.db     德育奖惩库（奖惩记录/附件）
  data/academic.db     教务基础库（教师名单/学科组长/班主任工作记录/考勤）
  data/timetable.db    课表库（学期课表/节次/调课/版本）
  data/inspection.db   查课库（巡课检查记录）
  data/achievement.db  业绩库（教师业绩 + 附件材料）
  data/forms.db        问卷库（表单模板/轮次/题目/提交/答案）
  data/portrait.db     画像库（画像/评语/事件）
```

- **后端**：Python 3.11+ / Flask 3.x / Flask-Login / Flask-SQLAlchemy 2.x（多库 binds）/ Waitress / openpyxl / reportlab / python-pptx
- **前端**：Bootstrap 5 / jQuery / Jinja2 / ECharts（成绩可视化）/ Chart.js（画像）
- **安全（v1.19.57.64）**：
  - **身份**：管理员首启随机口令 + 强制改密 · 一次性初始口令展示 · 会话口令摘要（改密即踢）· IP + 账号双维限流与锁定（锁键含来源，防账号被恶意锁定）
  - **数据**：AES 身份证与 AI Key 加密 · CSRF 8h 时效 · 二维权限（功能三档 × 数据范围）· 白名单式教师候选过滤
  - **传输**：`url_guard` 出站白名单 + DNS 解析 + 禁 302 跟随 · CSP（Report-Only 起步，可切 enforce）· HTTPS Cookie Secure
  - **输入**：`upload_guard` 4 层（MIME / magic-bytes / 扩展名白名单 / 危险类型）· `text_guard` 考务短标签清洗 · Excel 公式注入防护
  - **运维**：`err_safe` 异常脱敏 · `log_mask` 日志掩码（含异常栈，Formatter 层兜底）· `scan_security_patterns.py` 禁用模式扫描 · `sec_regression.py` 安全回归
- **部署**：Docker Compose（主应用 / 往届查询 / MCP 三容器）/ 阿里云 ECS / 绿联 NAS / Windows 本地；主应用支持**轻量更新**（`docker cp` + `docker restart`，不重建镜像）

### 首次启动与安全基线（必读）

- **默认管理员口令已不再是 `admin/admin123`**：首次启动创建 `admin` 时生成**随机初始口令**，只在控制台打印一次，且强制改密（未改密前无法访问任何功能页）。若输出已滚动过去，请删除 `data/system.db` 中的 admin 记录后重启，或由其他管理员在「用户管理」重置。
- **存量部署**：若 `admin` 仍是历史默认口令，启动时会打印显著告警，请立即修改。
- **密码复杂度**：强制 ≥8 位 + 含字母与数字 + 非弱口令黑名单 + 不等于用户名/姓名/手机号。
- **升级即全站掉登录**（会话口令摘要：旧会话缺 `_pwd_fp` 视为无效）。

**四段式** `主.次.三.四`（自 v1.18.0.0 起；规则 2026-10-12 定稿）：

- **第一段（主）**：重大版本；**第二段（次）**：里程碑版本（每次变动需打 tag 标注）
- **第三段**：主线维护者 `zkxxzf` 的累计改动计数，每次改动 +1
- **第四段**：协助者 `sakay`（飒龘）的累计改动计数，每次改动 +1
- **三、四段永不归零**：主/次版本升级时后两段原样保留（例：`1.19.39.2` → `1.20.39.2`）

统一由 `python -m scripts.bump_version <mode>` 执行（支持 `show | status | check | zk | sakay | minor | milestone | major | set X.Y.Z.W`）。
